# 03. 页面重构规格

## A. 全局工作台外壳

### 宽屏（>= 1280px）

```text
┌────────────── 248 ──────────────┬───────────────────────────────────────────┐
│ 工作区切换器                     │ 页面标题                     [搜索] [用户] │
│ 搜索                             ├───────────────────────────────────────────┤
│                                  │                                           │
│ 收件箱       3                   │              模块内容                     │
│                                  │                                           │
│ 协作                             │  实体页： 336px 列表 | 最小 720px 详情     │
│   消息                            │  工作页：最大宽度 1440px 的单一内容区       │
│   任务          2                │                                           │
│   知识                            │                                           │
│                                  │                                           │
│ 团队 / 运营 / 管理                │                                           │
│                                  │                                           │
│ 账户 / 偏好                       │                                           │
└──────────────────────────────────┴───────────────────────────────────────────┘
```

规范：

- `workspace-layout` 使用 `grid-template-columns: 248px minmax(0, 1fr)`，主区背景为页面底色，不使用渐变。
- 页面 chrome 高度为 64px，底部只有 1px 边线。标题使用 20px/28px、600 字重；不使用展示级字体。
- 内容区填充：宽屏 24px，中屏 20px，小屏 16px。避免当前在外壳、页面面板和卡片上重复叠加内边距。
- 侧栏纵向滚动仅发生于导航区；账户区固定在底部。主内容区独立滚动。

### 中屏（1024--1279px）

- 侧栏收窄为 64px 图标轨道；悬停或点击展开到 248px。
- 实体列表默认 320px；详情区域不可低于 640px。低于此阈值，切换为“列表优先”的单页面模式。

### 小屏（< 1024px）

- 顶栏提供菜单、当前模块、搜索和通知。
- 实体详情通过路由或本地视图进入全屏，并提供明确的返回列表按钮。
- 将筛选、排序和批量操作收进一个底部抽屉或工具栏菜单，不能使列表横向滚动。

## B. 实体页通用模板

```text

辅助说明  4 个已连接 · 1 个需处理
────────────────────────────────────────────────────────────────────────────
筛选 / 搜索 / 排序
┌──────────────────────────┬─────────────────────────────────────────────────┐
│ 引擎列表                  │ 172.30.30.11 / Claude Code      [已连接] [更多] │
│ ● Claude Code             │ 未设置备注 · 负责人：平台运营                    │
│   2 分钟前 · 0 个工作区    ├─────────────────────────────────────────────────┤
│                            │ 概览 | 活动 | 配置                               │
│ ○ Codex                   ├─────────────────────────────────────────────────┤
│   12 分钟前 · 1 个待处理   │ 指标：运行中 0 | 队列 0 | 24h 失败 0 | 版本 2.1 │
│                            │                                                 │

│   认证失效                 │ 09:40  心跳成功                                  │
└──────────────────────────┴─────────────────────────────────────────────────┘
```

### 列表规格

- 容器宽度 `336px`，不可小于 `304px`；在页面有多选、筛选或密集标签时可扩至 `384px`。
- 行高 72px；名称一行，次级信息一行。只允许备注占第三行，且截断。
- 健康状态使用 8px 色点 + 文本标签；不得只使用颜色。
- 行内不提供“删除”图标。`更新 Runtime` 是全局批量操作或详情的主操作；破坏性动作归入 `更多` 菜单并二次确认。
- 活动态只保留浅蓝背景和 3px 左侧边条，避免大面积着色和悬浮阴影。

### 详情规格

- 标题区只出现实体身份、状态、备注和 1 个主要动作；次要操作全部进入带文字说明的“更多”菜单。
- 详情一级标签固定为 `概览 / 活动 / 配置`。标签不使用圆角胶囊，使用底部 2px 指示线。
- 概览的关键指标在一行 3--4 列的无阴影 summary strip 中呈现；数值为空时显示 `--`，不反复显示 `0` 卡片。
- 安装应用采用有语义的 `支持 / 缺失 / 未检测` 表格或紧凑列表，不把技术能力渲染成彩色标签墙。
- 描述语言与 UI 语言一致；原始英文系统描述放入“诊断详情”折叠区，保留复制按钮。

### 首次使用与空状态

- 当工作区尚无执行引擎，内容区显示一个非嵌套的空状态：简短结果说明、一个 `接入执行引擎` 主按钮和一个可展开的“接入前需要准备什么”。
- 当已有引擎时，入口只保留在页面标题的 `接入引擎` 主按钮；不在列表、侧栏、统计卡重复投放同一 CTA。
- 点击接入后进入全屏/大型抽屉式向导。不要在小型 modal 中塞入终端命令、令牌、心跳校验和错误恢复。
- 用户完成一次成功接入后，不再自动弹出引导；帮助内容改为按钮旁的按需入口。

## C. 执行引擎管理页的具体改造

| 当前区域 | 新组件 | 保留的数据 | 调整 |
| --- | --- | --- | --- |
| 左侧三张快捷统计 | `AttentionQueue` | 待审批、打开任务、知识数 | 移至全局收件箱或页面标题，仅在数量非零时出现 |
| 运行时列表 | `EntityList` + `RuntimeListRow` | 名称、Provider、设备、状态、备注 | 设备和完整 Provider 移至次级文本；操作移出行内 |
| 详情顶部 | `EntityDetailHeader` | 名称、备注、连接状态、删除 | 删除进入更多菜单；增加负责人和最近心跳 |
| 5 张指标卡 | `MetricStrip` | 工作区、队列、失败/完成、版本 | 合并为 4 个紧凑指标，增加 24 小时失败数 |
| 已安装应用 | `CapabilityTable` | python、pip、cli-hub、npm、uv | 显示检测状态和版本；空状态说明可操作的下一步 |
| 运行状态说明 | `ActivityTimeline` | 心跳、执行、更新、错误 | 默认显示最近 10 条，支持过滤和跳转诊断 |

## D. 其他模块的页面模板

| 模块 | 首屏重点 | 次级区 |
| --- | --- | --- |
| 收件箱 | 需处理的审批、失败、提及 | 已读通知和历史 |
| 任务看板 | 进行中、阻塞、即将到期 | 已完成和统计 |
| 审批 | 风险等级、对象、请求人、截止时间 | 原始请求、审计记录 |
| 数字员工 | 员工身份、可用性、当前任务、责任人 | 技能、权限、运行时绑定 |
| 知识 | 最近使用、归属频道、权限 | 版本、附件和访问请求 |
| 成本/绩效 | 变化趋势、超预算、归因 | 按 Provider/员工的细节 |

所有模块必须先采用标题、工具栏、内容区、空状态这一共同骨架，再引入其领域特有组件。
