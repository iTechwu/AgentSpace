# 消息与联系人联动

日期：2026-07-25

## 问题结论

旧页面把“数字员工目录”和“数字员工私聊”都渲染成同一个聊天页面，只通过标题和侧栏活动态区分。结果是：

- 从消息页切换“数字联系人”后，侧栏错误高亮“联系人”。
- 从联系人页切换“数字员工”后，仍然出现消息输入框，和消息页没有任务差异。
- 中间栏标题在“会话、私聊、联系人、数字联系人”之间变化，标签和内容语义不一致。
- 同一个数字员工可能被用户理解为两份联系人或两条会话。

底层实体不拆分：数字员工仍由同一个 `contactId` 标识，私聊仍使用同一个直接频道。页面只按用户任务分工。

## 页面职责

| 一级入口 | 二级视图 | 用户任务 | 详情内容 |
| --- | --- | --- | --- |
| 消息 | 会话 | 浏览全部群组和直接会话 | 消息线程、文件、云文档、输入框 |
| 消息 | 数字联系人 | 快速找到数字员工私聊 | 消息线程与输入框 |
| 联系人 | 真人 | 查看工作区成员并发起私聊 | 真人资料与消息线程 |
| 联系人 | 数字员工 | 浏览完整数字员工目录 | 身份、私聊状态、最近消息、管理入口 |

`联系人 -> 数字员工` 不直接承载消息输入框。点击“发消息/继续对话”后进入 `消息 -> 数字联系人`，并用同一个 `focus=contact:<id>` 选中对应会话。

## 路由状态

```text
/im
  消息 -> 会话

/im?view=direct
  消息 -> 数字联系人

/contacts
  联系人 -> 真人

/im?view=direct&context=contacts
  联系人 -> 数字员工
```

`context=contacts` 只表达入口任务，不创建新的业务实体。直接访问旧的 `/contacts?view=digital` 时，服务端统一重定向到带 context 的规范 URL。

## 状态与导航约束

1. `/im?view=direct` 始终高亮侧栏“消息”。
2. 只有带 `context=contacts` 的数字员工目录才高亮侧栏“联系人”。
3. 切换一级侧栏会清除不属于目标模块的 `focus/tab/doc/context`。
4. 从目录进入消息时移除 `context=contacts`，但保留数字员工 `focus`。
5. 两个模块的中间栏共享同一分段选择器、计数和添加按钮布局。
6. “新建数字员工”进入员工管理并直接打开创建面板；“添加真人联系人”进入邀请流程；“创建群组”只属于消息。

## 验收路径

| 路径 | 验收结果 |
| --- | --- |
| 消息 -> 数字联系人 -> 选择 Atlas | 侧栏消息活动；显示 Atlas 消息线程与输入框 |
| 联系人 -> 数字员工 -> 选择 Atlas | 侧栏联系人活动；显示 Atlas 资料；没有输入框 |
| Atlas 资料 -> 发消息 | 进入 `/im?view=direct&focus=contact%3AAtlas` |
| 联系人 -> 真人 | 标题为联系人；真人标签活动；列表/空状态结构与数字员工一致 |
| 数字员工目录 -> 新建 | 进入员工管理并打开新建 Agent 面板 |
