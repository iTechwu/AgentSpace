# DeepSeek Harness Runtime 产品需求与范围

> 实施状态（2026-08-23）：P0 代码路径已接入，真实镜像和 DeepSeek canary 尚未通过，不能视为已发布。P2 持久会话未实施。详细证据见 [05-实施记录与验证证据.md](./05-实施记录与验证证据.md)。

## 1. 背景与问题

AgentSpace 已通过 AgentRouter 将 Claude Code、Codex、Antigravity、OpenCode、OpenClaw 和 Hermes 归一到同一条任务执行路径，但这些 harness 的 provider CLI、session 语义和模型选择方式不同。DeepSeek Harness 是 DeepSeek 官方开源的插件化 agent runtime，当前版本为 developer preview，提供原生 DeepSeek 模型、工具执行、会话持久化、headless runner 和 JSON-RPC/ACP 入口。

接入目标不是再造一个聊天页面，而是让现有员工、workspace、任务队列、runtime binding、技能、文档、审批、runtime-output 和审计能力可以选择 DeepSeek Harness 执行，同时保留 DeepSeek 原生模型名和原生请求语义。

## 2. 产品目标

### P0：可用的单任务 runtime

1. 管理员可以创建或注册 `DeepSeek Harness` runtime，并绑定到员工。
2. 员工任务可以正常进入现有 `agent_task_queue`，由该 runtime claim 和执行。
3. 通过 `deepseek-v4-flash` 提供低延迟、低成本的默认执行档；通过 `deepseek-v4-pro` 提供复杂编码和规划档。
4. 任务状态、最终结果、错误和 runtime-output 继续写入现有 DofeAgent 数据面；headless P0 不承诺实时文本增量、工具事件或 session id，P2 再补齐。
5. 凭据只能通过 runtime 作用域注入，日志、事件、诊断和失败消息必须脱敏。

### P1：可治理、可灰度

1. Runtime 创建页显示 provider、版本、模型、健康状态、能力和最近一次失败原因。
2. 支持按 workspace、employee、model 的灰度绑定和快速回滚。
3. 对模型不可用、凭据缺失、headless profile 缺失、进程超时、非零退出和协议解析失败提供可定位诊断。
4. 支持 runtime 级超时、最大轮次、并发上限和预算统计，不因 provider 特例绕过现有安全门禁。

### P2：持久会话与多轮控制

1. 使用 DeepSeek Harness 的 JSON-RPC/ACP 入口替代“一次任务一个进程”。
2. 支持 session resume、流式事件、取消、审批回调和子 agent 事件。
3. 将 DeepSeek Harness 的 durable session 与 AgentSpace 的 `providerSessionId` 建立显式映射，避免把内部 session 文件当成控制面事实来源。

## 3. 用户体验

### 创建 runtime

- Provider：`DeepSeek Harness`。
- Model：`deepseek-v4-flash`（默认）或 `deepseek-v4-pro`。
- Credential：引用一个 workspace 级 DeepSeek 账户，不在任务 payload 中保存明文 key。
- Execution mode：`headless`（P0）；`jsonrpc`/`acp` 仅在能力检查通过后显示。
- Runtime health：至少包含 CLI/build、credential、model route、workspace tool capability 四类状态。

### 运行任务

用户不需要改变任务入口。员工绑定 DeepSeek Harness 后，消息、工作流、Feishu 触发、CLI task 和定时任务继续进入同一个队列。时间线中 provider 标签显示 `DeepSeek Harness`，模型显示实际的 `deepseek-v4-*` ID。

### 失败体验

错误消息分为可行动类别：

| 类别 | 用户动作 |
| --- | --- |
| Runtime binary missing | 在目标节点安装/更新 approved image 或 executable |
| Credential missing/invalid | 重新绑定 DeepSeek 账户 |
| Model unavailable | 切换 `deepseek-v4-flash` / `deepseek-v4-pro` 或更新模型目录 |
| Profile/config invalid | 修复 `DSH_HOME` profile 或 runtime config |
| Timeout/cancelled | 重试或调整 runtime timeout |
| Tool permission denied | 走现有 approval 流程，不自动放宽权限 |

## 4. 模型与能力策略

| 模型 | 产品定位 | 默认 timeout | 建议路由 |
| --- | --- | ---: | --- |
| `deepseek-v4-flash` | 高频、低延迟、轻量编码/问答 | 15 min | 默认员工 runtime |
| `deepseek-v4-pro` | 复杂编码、规划、长上下文任务 | 30 min | 高价值或人工指定 |

模型 ID 必须原样透传给 DeepSeek Harness 的 `agentDefaultModel`/headless config。禁止在 AgentSpace 内把它改写为 `openai_response` 模型名，也禁止用“任意 OpenAI 模型可选”替代官方模型目录。

能力分成三层：

1. **Harness 能力**：headless、JSON-RPC、ACP、session resume、streaming。
2. **Runtime 能力**：bash、filesystem、PTY、MCP gateway、subagent、审批。
3. **模型能力**：text、image、reasoning、context window、tool calling。

只有三层能力交集才能在 runtime picker 中标记为可用。P0 默认关闭未经验证的 MCP/网络外发能力。

当前 P0 overlay 固定 `workspace-write`，关闭 telemetry、Web search、subagent、workflow 和 Ralph；bash/filesystem 仍受 DeepSeek Harness workspace sandbox 约束。AgentSpace approval 与 DeepSeek Harness 原生 approval 尚未建立双向协议，因此不开放需要该协议的能力。

## 5. 非目标与约束

- 不在本期把 DeepSeek Harness Web UI 部署到 AgentSpace；AgentSpace 仍是唯一控制面。
- 不复制一张 DeepSeek 专属任务队列，不绕过 `agent_task_queue` 的 claim、lease、binding generation 和失败收口。
- 不把 DeepSeek Harness 当成 Codex CLI，不复用 Codex 的 Responses 协议假设或审批语义。
- 不把真实 API key 写入 command line、任务 JSON、session prompt、runtime-output 或 Docker image layer。
- 不在本机启动 Jenkins；本期只做本地实现、验证和提交，部署由后续明确的非 Jenkins 流程执行。

## 6. 发布策略

1. 内部 dogfood：单一 workspace、单一 `deepseek-v4-flash` runtime、headless 模式。
2. Canary：5% 员工绑定，限定可重试任务类型，保留原 provider fallback。
3. General availability：health、billing、审计、回滚和至少一轮真实节点 E2E 全部通过后开放 `deepseek-v4-pro`。

创建入口由 `NEXT_PUBLIC_DEEPSEEK_HARNESS_RUNTIME_ENABLED=1` 开启，默认值为 `0`。在验收矩阵的 P0 必须项完成前不得在生产环境开启。
