# DeepSeek Harness Runtime 实施路径与改动清单

## 1. 阶段总览

| 阶段 | 目标 | 产物 | 退出条件 |
| --- | --- | --- | --- |
| W0 | 依赖与镜像 spike | 可运行的 dsh headless image、凭据 bundle | 无 key 时能启动并得到明确 auth 错误 |
| W1 | AgentRouter P0 | `deepseek-harness` adapter、检测、headless 执行、错误归一化 | 本地 task queue 端到端完成 flash 任务 |
| W2 | Runtime provisioning | provider 类型、模板、env、health、模型 allowlist | managed runtime 可创建、注册、健康检查和回收 |
| W3 | 产品与灰度 | UI、模型选择、billing/审计、feature flag | canary workspace 通过验收矩阵 |
| W4 | P2 持久会话 | JSON-RPC/ACP adapter、resume/cancel/approval | 长驻进程重启、恢复和租约 fencing 通过 |

## 2. W0：依赖与镜像 spike

1. 固定 `deepseek-harness` 版本（当前 checkout 为 `0.1.1-rc.2`），记录 Node/pnpm/系统依赖。
2. 构建一个只包含 Node、dsh 构建产物和受控 profile 的 `dofe/agent-runtime-deepseek-harness:<tag>` 镜像；不得在 Docker Compose 中新增 PostgreSQL、Redis 或 RabbitMQ。
3. 验证以下命令和输出边界：

   ```bash
   dsh --version
   dsh --profile headless --help
   dsh --profile headless "reply with OK"
   ```

4. 记录 `DEEPSEEK_BASE_URL` 的直连和 models gateway 两种模式，不把 endpoint 写死在 adapter。
5. 用无密钥 mock/loopback server 验证 stdout、stderr、退出码、超时和 SIGTERM 行为。

## 3. W1：AgentRouter P0 改动

| 文件 | 改动 |
| --- | --- |
| `packages/daemon/src/agent-router/types.ts` | 将 `deepseek-harness` 加入 harness union；必要时新增诊断 code |
| `packages/daemon/src/agent-router/adapters/deepseek-harness.ts` | 实现 detect/buildLaunch/run/normalizeError；复用 `runNativeHarness` |
| `packages/daemon/src/agent-router/adapters/index.ts` | 注册 adapter |
| `packages/daemon/src/agent-router/cli.ts` | 更新 help、`--harness` 校验和 `harnesses/detect` 输出 |
| `packages/daemon/src/provider-runtime/agent-router-task.ts` | provider 分发、model 传递、session fallback 策略 |
| `packages/daemon/src/provider-runtime/catalog.ts` | provider catalog、默认模型、executable/version 探测 |
| `packages/daemon/src/provider-runtime/provider-env.ts` | managed key 清理与 `DEEPSEEK_*` redaction |
| `packages/daemon/src/agent-router/*.test.ts` | adapter unit、stdout/stderr、timeout、signal、auth/model failure |

Adapter 的 `buildLaunch` 应将 task prompt 作为单一 positional argument，禁止 shell 拼接；`DSH_HOME` 使用 runtime metadata 指定的隔离目录。P0 不支持 `sessionId` resume，收到该参数时要么显式忽略并记录 diagnostic，要么直接返回 `harness.session_missing`，不能静默误恢复。

## 4. W2：Runtime provisioning 改动

| 文件/区域 | 改动 |
| --- | --- |
| `packages/domain/src/daemon-provider.ts` | provider id、label、`deepseek_native` capability、默认模型 |
| `packages/services/src/runtime-provisioning/provider-templates.ts` | credential env、executable `dsh`、gateway/base URL 和 image template |
| `packages/services/src/runtime-provisioning/runtime-provisioning-capacity.ts` | `deepseek-v4-flash/pro` 默认与 allowlist 规则 |
| `packages/services/src/runtime-provisioning/runtime-provisioning-models*.ts` | 模型目录与 protocol filtering；禁止错误套用 `openai_response` |
| `packages/daemon/src/provider-runtime/health.ts` | DeepSeek key/model probe 与错误分类 |
| `deploy/daemon/Dockerfile.provider-runtime` | 允许 DeepSeek Harness approved base/image 的安装与校验 |
| `deploy/daemon/runtimes/deepseek-harness.env.example` | 环境模板，不能包含真实 key |
| managed runtime image registry | 发布并锁定 `dofe/agent-runtime-deepseek-harness:<digest>` |

如果当前模型服务只接受 `openai`/`openai_response`，不要为了赶进度把 native route 伪装成其中之一；先增加显式 protocol/capability 或 runtime-local catalog，并将计费路由作为独立工作项。

## 5. W3：产品和灰度改动

1. `apps/web/features/runtimes/*`：provider 下拉、model picker、health badge、能力说明和 feature flag。
2. `apps/web/features/agents/*`：绑定确认页显示 `DeepSeek Harness · model`，并提示 headless 无 resume。
3. billing/usage：将 provider、model、input/output token（若 P0 无可靠 token event，则标记估算/未知）写入统一 usage contract。
4. audit：记录 runtime 创建、credential 绑定、模型切换、health failure 和 rollback。
5. fallback：canary 失败时只切换 employee binding，不删除 runtime 或 session 证据。

## 6. W4：JSON-RPC/ACP

优先实现 JSON-RPC，因为上游已有 `examples/jsonrpc-agent` 和 SDK client；ACP 作为外部 automation surface。适配器需要一个 bounded connection manager，按 runtime 管理 child process，按 task 管理 request/session，并实现：握手、通知解析、approval、cancel、timeout、重连、session resume 和崩溃恢复。

## 7. 测试顺序

1. 无 key unit：adapter launch、argv 注入、redaction、错误分类。
2. mock HTTP/model：模型选择、重试、空响应、stderr 污染、超时。
3. daemon task-runner：queue claim、binding generation、runtime-output、失败收口。
4. managed runtime：provisioning stages、health、credential bundle、cleanup。
5. 真实 DeepSeek canary：flash smoke、pro coding task、tool task、取消、重试和回滚。

遵循仓库测试资源限制：单文件测试优先，Jest 使用 `--maxWorkers=2`；不要执行无约束的全量 `pnpm test`。
