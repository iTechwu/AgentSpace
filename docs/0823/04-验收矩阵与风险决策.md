## 2. 风险清单

### R1：上游 developer preview 兼容性漂移

风险：DeepSeek Harness 明确允许 breaking changes，CLI 参数、headless 输出或 plugin bundle 可能变化。

缓解：锁版本和镜像 digest；adapter 只依赖已文档化的 headless 外部契约；每次升级先跑 W0/W1 contract suite；健康检查记录 dsh 版本。

### R2：把 native 模型误判为 OpenAI 协议

风险：现有 runtime model picker 以 provider protocol 过滤，若把 DeepSeek Harness 填入 `openai`，会掩盖原生路由和错误地开放不兼容模型。

缓解：新增 `deepseek_native` capability 或 runtime-local allowlist；模型 ID 只允许 `deepseek-v4-*` 目录；没有真实模型级证据时拒绝创建 runtime。

### R3：headless 无实时工具事件

风险：P0 只能在进程结束时得到最终文本，时间线无法展示实时 tool call，用户可能误以为任务卡死。

缓解：明确 UI 状态为“DeepSeek Harness 执行中”；发送 `harness_started`/heartbeat；P2 切换 JSON-RPC 后再开放细粒度事件，不伪造 `text_delta`。

### R4：凭据或 profile 串租户

风险：DeepSeek Harness 使用 `$DSH_HOME/.credentials.yaml` 和 settings；复用目录可能跨 workspace 泄露 session 或 key。

缓解：每个 managed runtime 独立 HOME/profile/session root；credential bundle 只读挂载；任务结束清理临时目录；日志按值脱敏。

### R5：工具权限模型不一致

风险：DeepSeek Harness 的 Code Mode、bash、filesystem、subagent 与 AgentSpace approval/MCP policy 不是同一套模型。

缓解：P0 只启用经 capability contract 映射的工具；禁止通过 `DSH_TOOLS_MODE` 或 prompt 临时提升权限；所有外发动作继续走 Dofe approval。

### R6：计费 token 不完整

风险：headless stdout 契约不保证 token usage，直接写入 usage 会造成账单错误。

缓解：P0 将 usage 标记为 unavailable/estimated，或在 models gateway 侧补充可靠 usage；在 billing contract 明确 provider/model/request id 来源。

## 3. ADR-0823-01：独立 Harness，不复用 Codex/OpenAI adapter

**状态：Accepted（2026-08-23）**

**上下文**：DeepSeek Harness 原生使用插件组合、DeepSeek provider route、headless/JSON-RPC session；Codex adapter 假设 OpenAI Responses CLI 和不同的 approval/session 行为。

**决策**：新增 `deepseek-harness` provider/harness，首期实现独立 headless adapter，复用 AgentRouter 和 task queue 外壳。

**替代方案**：

- 伪装为 `codex`：改动少，但会错误套用 Responses 协议、模型过滤、resume 和审批语义，拒绝。
- 伪装为 `opencode`/通用 OpenAI：可快速调用 endpoint，但失去 DeepSeek Harness 的工具与 session 语义，拒绝。
- 直接在 task-runner 中写 DeepSeek 特判：短期快，长期破坏 provider-runtime 边界，拒绝。

**后果**：需要新增一个 provider id、adapter、镜像模板和测试矩阵；换来的好处是协议边界清晰、灰度可回滚、未来 JSON-RPC/ACP 可在同一 provider 下演进。

## 4. ADR-0823-02：P0 headless，P2 JSON-RPC/ACP

**状态：Accepted for P0 / Proposed for P2（2026-08-23）**

**决策**：先用稳定的一次性 headless 外部契约上线最小价值，再以 JSON-RPC 为持久会话主路径，ACP 仅按外部 automation 需要接入。

**原因**：headless 的 stdout/stderr/exit code 易测试、易隔离、易回滚；JSON-RPC/ACP 虽然能力更丰富，但需要长驻进程、请求复用、通知排序、取消和恢复等额外状态机。

**后果**：P0 没有真实实时 tool event 和 resume；产品文案必须明确这一点，不能把 headless 伪装成完整交互 runtime。

## 5. 回滚

回滚只改变 employee/runtime binding 或 feature flag：

1. 停止向 `deepseek-harness` runtime claim 新任务。
2. 等待或取消运行中任务，保留 task messages、diagnostics 和 artifacts。
3. 将员工切回上一 provider/runtime，重新验证 binding generation。
4. 保留 DeepSeek runtime 以便取证；只有确认 credential/profile 污染时才执行 managed cleanup。
