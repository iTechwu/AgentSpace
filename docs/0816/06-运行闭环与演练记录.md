## 隔离库容量压测入口

新增命令 `pnpm --filter @dofe-agent/db run prisma:pool:loadtest`。它用 PrismaPg 建立指定角色的
连接池，并发执行带 `pg_sleep` 的参数化查询。观察连接会在负载尚未完成时通过独立 PostgreSQL connection
查询 `pg_stat_activity`，报告 `observedConnections/activeConnections/waitingConnections`；同时输出
`connectionTimedOut`、`statementTimedOut`、查询 P95、`connectionWaitP95Ms`，并用独立 Prisma probe 在查询
in-flight 时调用 `$disconnect`，记录 `gracefulShutdownMs/gracefulShutdownDuringInflight`。CLI 只接受数据库名
包含 `test`、`loadtest` 或 `ci` 的显式 URL，防止误压普通 dev/生产库。

隔离库实测已于 2026-08-17 完成（连接串不入库）：

| 场景 | Web | worker | daemon |
| --- | ---: | ---: | ---: |
| 配置池上限 | 10 | 5 | 3 |
| 基线并发 / completed / failed | 12 / 12 / 0 | 8 / 8 / 0 | 6 / 6 / 0 |
| 基线 P95 / 连接等待 P95（ms） | 632 / 382 | 575 / 325 | 575 / 325 |
| 负载期间 observed / active | 10 / 10 | 5 / 5 | 3 / 3 |
| in-flight shutdown（ms / fulfilled） | 303 / true | 282 / true | 278 / true |
| 过载并发 / completed / connection timeout | 12 / 10 / 2 | 7 / 5 / 2 | 5 / 3 / 2 |

额外的 daemon 独立探针以 `statementTimeoutMs=100` 执行 500ms 查询，结果
`statementTimedOut=1`、`failed=0`。`waitingConnections` 是 PostgreSQL `wait_event_type` 观测，
`pg_sleep` 本身会计入该值；客户端 pool 排队证据以 `connectionWaitP95Ms` 和过载时的
`connectionTimedOut` 为准。压测查询改为返回 integer 的 CTE，避免 Prisma 对 PostgreSQL
`pg_sleep` void 列产生 P2010 反序列化失败。
同一关键路径已加入 `pool-capacity-loadtest.test.ts` 真库条件测试；测试数据库可用时自动断言
completed/failed、负载期 observed/active、P95 和 in-flight disconnect，手工证据之外已有回归保护。

## Shadow 30 天准入

新增 `prisma-shadow-readiness`，直接读取集中 SLO audit ledger（最多 10,000 条），检查指定域是否连续覆盖
30 天、采集间隙是否不超过阈值，以及 mismatch/fallback/error/rollback 是否为零；deadlock/P2034 可按 legacy
基线显式传入最大率。默认 minimum samples 为 1000、单窗口跨度上限 3600s（`--maximum-window-span-seconds`
可调，上限 1 天），超跨度窗口剔除并记 `window_span_exceeded`——持续采集才可满足样本门禁。门禁失败设置退出码 2，供发布流程 fail-closed。

门禁现在还要求每个窗口 `shadowComparisonRate=1`。read runner 只有真实执行主备对照才记录 1；
workflow dispatcher/materialization 的 Prisma 主路径虽已产生 SLO 样本，但在无副作用 shadow oracle 完成前固定记录 0，
因此会返回 `shadow_comparison_missing`。损坏 JSON、NaN、越界 rate 或非法 rollback reason 返回
`invalid_snapshot`，不会被静默过滤。

2026-08-17 对 `workflow-dispatcher` 执行 30 天、最大间隙 1,800 秒的检查，结果 `ready=false`，原因
`no_snapshots`、`insufficient_samples`。该记录只证明准入命令生效，不构成 30 天 shadow 证据。

## 回滚发布演练

HTTP payload 固定包含 `releaseId`、`currentFlagVersion`、`targetFlagVersion`、`rollbackReasons`、
`burnRate` 和 `idempotency-key`。部署时先设置 `PRISMA_CUTOVER_AUTO_ROLLBACK_ENABLED=0` 做 dry-run，
验证发布系统权限、重复请求返回同一 publicationId、网络失败不重写 legacy 数据；通过后才允许在单一
workspace 开启自动回滚，并保留 last-known-good flag 的审计记录。
