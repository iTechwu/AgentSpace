# 0815 规格实现一致性复审

## 1. 审查范围与结论

审查对象为 `dev` 分支 `8a990c2a` 及其之前的 0815 优化提交，重点复核
`docs/0815/04`、`05`、`06`、`07`、`08` 与当前 Skill rollout、workflow 编排实现。

结论：**代码主链路已明显改善，但 0815 仍不能作为“文档与实现完全一致”的基线**。
当前主要风险已从最初的 placement/审批绕过，转移为规格版本冲突、失败恢复语义、
能力过滤和测试证据不足。

## 2. 发现

### P1：验收结论相互矛盾，无法作为发布依据

`docs/0815/07-验收审查与差距.md:3-4` 仍写“部分完成，不建议完整验收”，
但 `:14`、`:26`、`:68` 又写 P1/P2/S 全部解决；`:95-101` 再次保留旧的
“不满足完整验收”结论。该文件把历史审查记录和最终状态混在同一结论区，
会导致评审、发布和回滚判断不一致。

建议：将 07 重写成“历史发现（只读）+ 当前状态表 + 未闭环风险 + 证据链接”四段，
只保留一个最终结论；每个已解决项必须链接到提交、测试文件和运行命令。

### P1（已完成）：`SkillRolloutPlan` 契约与落地 API 已显式关联

纯 planner 仍返回内容寻址的 `SkillRolloutPlan`，但当前
`packages/services/src/skills/rollout.ts` 新增 `SkillRolloutPersistedPlan`，并由
`packages/services/src/skills/rollout-dispatch.ts:13-26` 在 dispatch result 中返回
`planId + planDigest + plan` 三者绑定的对象；回归测试已验证 id/digest 一致。
这明确了 planner（纯计算）与持久化审批记录（带 id）的边界。

仍需同步 0815 的历史契约文字，建议：

1. planner 保持纯函数，不承诺数据库 id；
2. 持久化 dispatch 使用 `SkillRolloutPersistedPlan` 承载 `planId`。

### P1（已部分完成）：`all-compatible` 已增加版本化能力选择

`packages/services/src/skills/rollout.ts` 现在读取 `metadata.runtimeCapabilities`，按
`schemaVersion/gpu/egress/mcp/cli` 与 manifest 需求过滤；缺少声明或全不匹配时
fail-closed，`rollout.test.ts` 已覆盖兼容、不兼容和全不匹配场景；daemon 注册/心跳路径
现在会拒绝非法快照、规范化合法快照，并绑定当前 daemon 的 `daemon_probe` provenance。
仍需将 provenance 与真实硬件/网络探针证明绑定，并完成真实 GPU/egress/MCP/CLI 环境验收。

建议：把 `daemon_probe` provenance 与硬件/网络探针的可验证证明绑定，把 Skill manifest 的
capability/egress 要求与过滤原因写入 plan risk/diagnostic，并补充真实 Runtime 的“在线但无
GPU”“在线但无出网批准”和“全部不兼容”验收记录。

### P1（基础闭环已完成）：批量派发具备持久化 reconcile 状态机

`packages/services/src/skills/rollout-dispatch.ts` 现已在子安装创建失败或 finalize 返回
false 时抛出 `SkillRolloutDispatchError`，并将每个 `(planId, runtimeId, artifactDigest)`
写入 `skill_rollout_reconcile_item`。状态机持久化 `pending/failed/created`、尝试次数、错误码、
安装 ID 和 revision；失败项可重试，所有项完成后才消费计划，已消费计划和已完成项重复调用
保持幂等。对应回归覆盖中途失败、离线 Runtime 恢复和重复 reconcile：
`packages/db/src/skill-rollout-reconcile.test.ts`、`packages/services/src/skills/rollout-dispatch.test.ts`。

剩余建议：在 CI/测试环境补充真正多进程并发 reconcile、数据库锁竞争、网络抖动下的退避/指标和
长时间重试观察；这些属于运行时可靠性证据，不再是缺失的持久化实现。

### P2：审批幂等决策已同步，仍需补齐回归证据

`docs/0815/04:37` 和 `08:3-5` 已决定“非唯一 + 每次审批新行 + consumedAt 防重放”，
`docs/0815/05:225`、07 和 08 已同步为同一语义；当前 DB 实现
`packages/db/src/skill-rollout-plans.ts:28-30` 允许同 digest 新建记录，并由

### P2（已部分完成）：planDigest 已绑定闭包父节点

当前 `packages/services/src/skills/rollout.ts:425-434` 已将

### P2（已完成）：iteration_group 运行时注释与质量报告绑定契约已同步
