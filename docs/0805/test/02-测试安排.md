## 5. 自动化与人工执行分配

遵守仓库并发限制，优先执行最小相关范围：

```bash
# Web 类型、测试类型和 lint
pnpm --filter @dofe-agent/web run typecheck
pnpm --filter @dofe-agent/web run typecheck:test
pnpm --filter @dofe-agent/web run lint

# Web 单元/组件/API 测试，最多两个 worker
pnpm --filter @dofe-agent/web exec vitest run --maxWorkers=2

# 单个 Web 测试文件
pnpm --filter @dofe-agent/web exec vitest run path/to/file.test.tsx --maxWorkers=2

# 浏览器 E2E（必须使用独立测试数据库）
DOFE_AGENT_TEST_DATABASE_URL='<test-database-url>' pnpm --filter @dofe-agent/web run test:e2e

# Monorepo 全量测试，根脚本已限制 Turbo 并发为 2
pnpm test -- --maxWorkers=2
```

自动化每日执行：现有 Playwright 冒烟、模块导航、消息发送延迟和移动端 smoke；现有 Vitest/Node 覆盖的模块变更测试。人工必须补足真实测试账号登录、跨工作区权限、CLI/MCP/Skill 真实操作、审批、外部集成和恢复演练。

高风险主链路优先补自动化：

1. SSO 登录 -> 工作区/角色同步 -> 深链隔离。
2. 消息 -> 任务 -> AI 员工 -> Runtime -> 产物回写。
3. 审批阻断 -> 通过/拒绝 -> 继续或取消。
4. CLI/MCP/Skill 安装资格 -> 授权 -> 任务调用 -> 审计。
5. 权限撤销后 UI、API、附件和频道访问同时失效。

## 6. 准入、阻塞与恢复

### 6.1 准入

- 候选 commit 固定，可追溯到测试环境。
- 测试账号可登录，角色/工作区已记录。
- 独立测试数据库和 `/api/health` 可用。
- 至少一个在线 Runtime、一个兼容模型和可验证的测试数据可用。
- 纳入飞书/MCP 的专项凭据、测试目标、清理负责人已确认。
- typecheck、lint 和最小自动化冒烟无应用级失败。

### 6.2 阻塞处理

环境不可用、依赖缺失、账号无权限或数据无法安全清理时，记录为“阻塞”，写明责任人、影响范围、下一次检查时间和恢复条件；不得将阻塞改写为通过或不适用。

S0、生产数据疑似接入、重复计费/部署或 Secret 泄露时，暂停相关写操作，保留脱敏证据并升级处理。

### 6.3 恢复

恢复前必须确认根因或隔离措施、依赖健康、测试数据一致性和清理可行性；恢复后重新执行当日冒烟，再执行失败用例、同域 P0 和跨模块主链路。

## 7. 统计口径与准出

状态仅使用：`未执行 / 通过 / 失败 / 阻塞 / 不适用`。不适用必须有环境或权限依据。

每日记录：总用例、已执行、通过、失败、阻塞、不适用、P0/P1 通过率、S0-S3 数量、已回归/重开数量和清理状态。

最终准出要求：

- P0 执行率和通过率均为 100%。
- 适用 P1 100% 有结果；阻塞项逐项获准出评审确认。
- S0/S1 未关闭数量为 0；S2 有修复版本或书面风险接受。
- 桌面 Chrome 与移动 `390 x 844` 的 P0 全通过。
- 无跨工作区泄露、Secret 泄露、错误 Runtime 执行、重复计费、不可恢复数据丢失。
- 测试资源、连接、授权、邀请和临时高权限清理完成。
