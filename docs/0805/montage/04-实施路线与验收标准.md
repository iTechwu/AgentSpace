# 实施路线与验收标准

> 状态：Proposed
>
> 日期：2026-08-05

## 1. 实施原则

- 先定义跨仓库合同，再修改三个实现。
- 每一阶段都必须保持模型金额只有 models 一个权威来源。
- 先跑通单 workspace、单 Runtime、单并发 Job，再扩展并发和恢复。
- 真实视频、模型计费、取消和审批 E2E 未通过前，不把能力标记为生产支持。
- 阶段可视性与视频执行同等重要；不能用 Prompt、AI 主动轮询或普通日志代替持久化 Job 事件和聊天投影。
- 本机不使用 Jenkins。实施、验证和提交在本地完成；部署需另行提供非 Jenkins 工作流。

## 2. Phase 0：合同与威胁模型

### 工作项

- 冻结 Job、Artifact、Usage Link、委托凭证 v1 schema。
- 明确 workspace、employee、runtime、task、conversation、invocation、Job 的 ID 来源。
- 明确委托凭证签发者、存储者、验证者和撤销者。
- 确认 `model.local.dofe.ai` 与 `models.local.dofe.ai` 的唯一规范域名，并由受管配置显式注入 `DOFE_MODEL_BASE_URL`。
- 完成 SSRF、路径穿越、凭据泄漏、跨租户 Artifact、重复结算和超预算威胁模型。
- 定义 models、AgentSpace、OpenMontage 三方兼容和发布顺序。
- 冻结 Job Event、Chat Projection 和 Approval Action v1 schema。

### 验收

- 合同 fixtures 可被三个仓库独立解析。
- 未知字段、非法枚举、超大输入、绝对路径和跨 workspace ID 均被拒绝。
- 明确记录模型费用与视频计算费用的不同权威来源。
- OpenMontage capability/preflight 返回实际配置的 models endpoint 环境标识，且真实连通性检查通过。

## 3. Phase 1：OpenMontage Job Service

### 工作项

- 提取共享 `JobService`，CLI、REST、MCP 都调用它。
- 实现 Job 状态机、幂等提交、持久化、取消和重启恢复。
- 把现有 reference clone 适配到 Job Service。
- 增加 Artifact manifest 和 Usage Link 记录。
- MCP 增加 submit/status/cancel/approve/artifacts 工具。
- REST 增加 `/api/v1/jobs` 契约。
- 构建 digest-pinned 镜像，保留固定 Remotion、HyperFrames、FFmpeg 和浏览器版本。

### 验收

- 同一 `clientRequestId` 重试只产生一个 Job。
- 容器重启后 Job 可恢复为可解释状态，不静默重跑已计费阶段。
- 取消后不再发起新的模型调用，运行中的调用按 provider 能力停止或进入可解释终态。
- FFmpeg、Remotion、HyperFrames 各完成一个真实渲染 smoke。
- MCP 与 REST 对同一 Job 返回相同状态和错误码。
- 每次用户可感知状态迁移均与 outbox 事件原子提交，并能按 Job 序号完整重放。

## 4. Phase 2：models 委托凭证与权威归因

### 工作项

- 增加 Runtime Job delegation 的创建、查询、撤销内部合同。
- delegation 绑定稳定 employee ID、Runtime、会话、Task、OpenMontage Job、能力、模型和预算。
- Gateway 用量记录增加 source service、invocation、external Job 和 stage 维度。
- Billing Report 增加来源服务和 OpenMontage Job breakdown。
- models 数据面只从已验证 delegation 读取归因，不信任调用方自报 headers。
- 委托凭证达到过期、撤销或预算上限后 fail closed。

### 验收

- 两个 AI 员工通过同一个 OpenMontage 实例调用相同模型，账单仍分别归属。
- 员工改名后历史消费仍归于原稳定 employee ID。
- 相同 `gatewayUsageId` 重放不会产生第二笔模型用量或 charge。
- 撤销 delegation 后新请求被拒绝，已结算记录保持不变。
- Billing Report 金额与 models ledger 一致，AgentSpace 不做本地价格重算。

## 5. Phase 3：AgentSpace managed service 与 MCP 接入

### 工作项

- MCP Center 为平台审核模板开放 `managed_service` transport。
- 复用已有 skill-service admission、digest、SBOM、签名、资源和网络策略。
- daemon 部署 workspace + runtime scoped OpenMontage 服务。
- 使用不可伪造的 service connection reference，不把私网 endpoint 暴露给浏览器。
- MCP Gateway 创建 Job 时签发 delegation，并通过服务间安全通道交给 OpenMontage。
- Job 终态、连接撤销或 Runtime credential 轮换时撤销 delegation。
- 补齐工具发现、批准、逐调用 fencing、审计和降级状态。

### 验收

- Runtime 只能调用管理员批准的 OpenMontage 工具。
- 禁用 MCP connection 后，已运行 Task 的下一次工具调用也被拒绝。
- 浏览器、LLM 输出和 daemon 普通日志中均找不到服务 secret 或 delegation secret。
- OpenMontage 无 Docker socket、Provider HOME 和 Runtime credential volume。
- 服务健康异常时连接进入 degraded，而不是继续对 Agent 宣称可用。

## 6. Phase 4：Artifact Bridge

### 工作项

- 定义 task-scoped Artifact input/output grant。
- 实现内容类型、大小、SHA-256、租户和对象级校验。
- OpenMontage 下载输入、上传输出，不挂载完整 Runtime workspace。
- AgentSpace 将最终 Artifact 接入现有 `dofe-agent output attach` 回收流程。
- 增加临时文件和过期 Artifact 清理。

### 验收

- 100MB 以上视频不经过 MCP JSON 或 LLM 上下文。
- 跨 workspace Artifact ID、过期 grant、摘要不匹配和路径穿越全部被拒绝。
- 最终 MP4 可在任务完成后被 AgentSpace 回收并展示。
- 失败、取消和超时 Job 不遗留无期限临时文件。

## 7. Phase 5：AI 员工聊天阶段闭环

### 工作项

- OpenMontage 实现事务 outbox、签名事件推送和 `afterSequence` 补偿接口。
- AgentSpace 增加 Job Event Bridge、Job Link、Event Inbox 和 Chat Projection 持久化模型。
- 聊天页增加跨 Runtime Task 生命周期的视频 Job 卡片和阶段时间线。
- SSE 增加 `openmontage.job.changed` 失效通知，并保留页面加载时的持久化 snapshot 恢复。
- 审批、取消、重试和预算扩额必须从卡片调用 AgentSpace 服务端动作，不把服务凭据或 OpenMontage endpoint 暴露给浏览器。
- `WAITING_APPROVAL`、失败和成功产物产生高关注聊天消息；普通进度只更新同一卡片。
- 最终 Artifact 发布后自动展示可预览、下载的 MP4，并把 Job 卡片置为不可逆终态。
- 实现事件重复、乱序、缺口、断网、容器重启和原 Runtime Task 已结束时的恢复逻辑。

### 验收

- 一个 7 阶段视频 Job 的每个阶段均在聊天卡片中按顺序出现，刷新页面和重新登录后不丢失。
- Runtime Task 在 Job 创建后立即完成，OpenMontage 后续阶段仍能实时显示并最终送达视频。
- 重复事件不会产生重复阶段、重复消息、重复审批或重复 Artifact。
- 缺失一个 sequence 时页面明确显示“同步中”，补偿完成前不把后续阶段误标为已完成。
- `WAITING_APPROVAL` 未获批准前不进入后续付费阶段；无权限用户看不到可用审批按钮。
- 失败卡片显示失败阶段、用户可理解原因和允许的下一步，不暴露密钥、内部路径或 Provider 原始响应。
- 终态事件到达后 5 秒内聊天页可见，p95 阶段更新延迟不超过 5 秒。
- 完成 [AI 员工聊天阶段可视化方案](./05-AI员工聊天阶段可视化方案.md) 中的全部 E2E 场景。
- 5-8 名目标用户完成阶段识别、审批、失败恢复和产物查找测试，达到文档定义的完成率、误操作和 SUS 门槛。

## 8. Phase 6：成本中心与预算体验

### 工作项

- 成本页增加 `runtime_direct/openmontage` 来源维度。
- 增加 OpenMontage Job 和 Pipeline Stage breakdown。
- models 实际金额不可用时明确显示 unavailable，不回退到本地估算金额。
- OpenMontage 估算只用于提交前预览和审批。
- 增加本地视频资源用量面板；未建立资源账本前不显示推测金额。
- 增加 Job 预算、审批、扩额和耗尽状态。

### 验收

- 能从 AI 员工汇总下钻到 Task、OpenMontage Job、Stage 和 models usageId。
- 页面总金额不重复叠加 OpenMontage 估算与 models 实际金额。
- 一个混合任务能分别展示模型费用与本地渲染资源用量。
- 超预算 Job 在新的付费调用前停止，并提供可审批的扩额动作。

## 9. Phase 7：可观测性和生产门禁

### 结构化事件

- `openmontage.job.created`
- `openmontage.stage.started`
- `openmontage.stage.progressed`
- `openmontage.stage.completed`
- `openmontage.model_request.completed`
- `openmontage.job.waiting_approval`
- `openmontage.budget.exhausted`
- `openmontage.job.cancelled`
- `openmontage.job.failed`
- `openmontage.artifact.published`
- `openmontage.chat_projection.updated`
- `openmontage.event_gap.detected`
- `openmontage.event.reconciled`
- `runtime.delegation.created`
- `runtime.delegation.revoked`
- `runtime.delegation.rejected`

### Metrics

- Job create/success/failure/cancel rate
- queue age and queue depth
- stage duration p50/p95/p99
- models dependency error rate and latency
- render duration and resource saturation
- delegation reject/revoke/expire count
- Artifact upload/download error rate
- unattributed and unreconciled usage count

employee ID、Job ID、request ID 和 usage ID 只用于日志/trace，不作为 metrics label。

### 生产门禁

- 一条任务 trace 能跨 Runtime、MCP Gateway、OpenMontage 和 models 连续查询。
- 故意触发错误后，可只凭 telemetry 定位失败阶段、员工、Job 和 models request。
- Codex MCP 的 call、revoke、audit、lifecycle 真实 E2E 通过后，才默认开放 Codex MCP eligibility。
- 真实模型调用后的 Billing Report、AgentSpace 明细和 models ledger 对账一致。
- 任意 Job 可对比 OpenMontage 事件流与聊天投影序号，终态不存在未投影事件。
- 人为断开事件推送、重启 OpenMontage 和关闭原 Runtime Task 后，聊天阶段仍能通过补偿恢复完整。

## 10. 跨仓库实施位置

### `../OpenMontage`

- `openmontage/job_service.py`：异步任务应用服务。
- `openmontage/contracts.py`：v1 schema。
- `openmontage/event_outbox.py`：状态事务事件与重放。
- `openmontage/mcp_server.py`：MCP adapter。
- `openmontage/cli.py` 或独立 client package：CLI adapter。
- `tools/dofe/client.py`：delegation credential 和 usage correlation。
- Dockerfile/healthcheck：生产镜像和依赖 smoke。

### `../models.dofe.ai`

- internal contract：Runtime credential delegation。
- runtime credential domain：delegation aggregate 和生命周期。
- proxy/generation attribution：解析并固化 delegation attribution。
- usage log/ledger：source service、Job、stage 维度。
- Billing Report：OpenMontage breakdown。

### `agentspace.dofe.ai`

- MCP Center catalog/connections：`managed_service` connection reference。
- skill-services/daemon worker：OpenMontage 服务部署与健康。
- MCP Gateway：可信调用上下文、delegation 签发与撤销。
- OpenMontage event ingress/projector：有序事件消费、补偿和聊天读模型。
- channels/chat：视频 Job 卡片、阶段时间线、审批动作和 Artifact 预览。
- task output/artifacts：Artifact Bridge。
- token usage/costs：usage link 对账和成本下钻。
- Market UI：安装、连接、工具审批、状态和卸载。

## 11. 发布与回滚

推荐发布顺序：

1. models additive schema 和 delegation API，默认无调用方。
2. OpenMontage Job API、事件 outbox 和 delegation client，保留现有 CLI/MCP 兼容入口。
3. AgentSpace managed service、Job Event Bridge、聊天投影和 Artifact Bridge，功能开关默认关闭。
4. 聊天卡片具备事件补偿、审批和终态 Artifact 闭环后，指定 workspace + Runtime 灰度。
5. 完成真实视频、计费、撤销、阶段可视性和恢复 E2E 后逐步开放。

回滚要求：

- 禁用 AgentSpace OpenMontage catalog release 即停止新 Job。
- 撤销所有 active delegation，阻止继续消费。
- 保留 Job、Artifact、usage link 和 models ledger 审计记录。
- 旧 OpenMontage 兼容入口不自动切回共享模型 Key。
- schema 只做 additive 发布，回滚应用版本不删除历史归因字段。

## 12. 完成定义

只有同时满足以下条件，才能宣称“AgentSpace Runtime 已具备完整 OpenMontage 视频处理能力”：

- Docker 服务可重复部署、升级、回滚和健康检查。
- MCP 工具能提交、查询、审批、取消并回收视频产物。
- Artifact 不通过 LLM/MCP JSON 传大文件。
- 每笔 models 消费归属于稳定 AI 员工和 OpenMontage Job。
- models 权威金额与 AgentSpace 成本中心一致且不重复计费。
- 本地渲染资源与模型费用分项展示。
- 凭证、网络、文件和租户边界通过安全测试。
- FFmpeg、Remotion、HyperFrames 与至少一种付费模型完成真实 E2E。
- 每个用户可感知阶段均由持久化事件驱动并在 AI 员工聊天页有序可见，不依赖 AI 主动轮询。
- 原 Runtime Task 结束、页面刷新、网络抖动和服务重启后，阶段时间线、审批状态和最终视频均可恢复。
