# 统一归因与计费设计

> 状态：Proposed
>
> 日期：2026-08-05

## 1. 目标

一次视频任务的完整调用链为：

```text
AI 员工 -> AgentSpace Runtime -> MCP Gateway -> OpenMontage Job
        -> models.dofe.ai 图片/视频/TTS/音乐/理解调用
```

需要回答：

1. 哪个 workspace 和 AI 员工发起了调用？
2. 来自哪个 Runtime、AgentSpace Task、会话和 MCP invocation？
3. 属于哪个 OpenMontage Job、Pipeline Stage 和模型操作？
4. models 实际结算了多少金额，状态是什么？
5. OpenMontage 本地渲染消耗了多少 CPU/GPU/存储？
6. 一次请求是否被重复记录或重复计费？

## 2. 权威边界

### 2.1 models 是模型金额唯一权威

`models.dofe.ai` 负责模型价格快照、折扣、计费单位、币种、预留、结算和退款。AgentSpace 与 OpenMontage 可以保存 request correlation 和领域标签，但不得复制价格目录后重新计算实际金额。

OpenMontage 现有 cost tracker 仅用于：

- 任务提交前预算估算。
- Pipeline 审批阈值。
- 选择不同生成方案时的成本比较。

它不能进入实际模型金额汇总。

### 2.2 OpenMontage 负责本地资源用量

FFmpeg、Remotion、HyperFrames 和本地浏览器渲染不产生 models API 账单，但会消耗平台资源。单独记录：

- CPU seconds
- GPU seconds
- render seconds
- peak memory bytes
- temporary storage byte-hours
- artifact storage byte-hours
- network egress bytes

只有平台为这些资源建立明确价格和结算账本后，才展示货币金额。否则只展示用量，不用猜测价格。

## 3. 归因上下文

创建 OpenMontage Job 时，由 MCP Gateway 生成可信上下文。以下字段不允许由 LLM 工具参数自由指定：

```json
{
  "schemaVersion": 1,
  "workspaceId": "workspace-id",
  "employeeId": "stable-employee-id",
  "employeeNameSnapshot": "视频运营 Agent",
  "runtimeId": "runtime-id",
  "runtimeCredentialId": "runtime-credential-id",
  "rootTaskId": "agentspace-task-id",
  "conversationId": "router-session-or-task-id",
  "sourceService": "openmontage",
  "sourceInvocationId": "mcp-tool-invocation-id",
  "externalJobId": "openmontage-job-id"
}
```

`employeeId` 必须使用稳定员工 ID。`employeeNameSnapshot` 只用于展示，员工改名不能改变历史账务归属。当前 daemon task 已有 `employeeId`，新链路不得继续以兼容字段 `agentId` 作为账务主键。

## 4. Job 级委托凭证

### 4.1 为什么不能使用共享 Key

若 OpenMontage 使用全局 `DOFE_MODEL_API_KEY`：

- 所有消费都会归到 OpenMontage 服务账号。
- 无法可靠区分 AI 员工、任务和 Job。
- Key 泄漏后的消费范围过大。
- 任务取消无法单独撤销权限。
- 预算限制只能靠 OpenMontage 自律，不能由 models 强制执行。

也不能把 Runtime 原始 Key 交给 OpenMontage。它是 Runtime 身份与计费边界，长期暴露给下游服务会扩大权限和泄漏半径。

### 4.2 委托接口

建议在 models 内部合同增加：

```text
POST /internal/runtime-credentials/:runtimeCredentialId/delegations
GET  /internal/runtime-credential-delegations/:id
POST /internal/runtime-credential-delegations/:id/revoke
```

创建请求：

```json
{
  "idempotencyKey": "workspace:task:invocation",
  "employeeId": "stable-employee-id",
  "conversationId": "conversation-id",
  "rootTaskId": "agentspace-task-id",
  "sourceService": "openmontage",
  "sourceInvocationId": "mcp-invocation-id",
  "externalJobId": "openmontage-job-id",
  "allowedCapabilities": ["image", "video", "tts", "music", "stt"],
  "allowedModels": [],
  "spendLimit": "20.00",
  "currency": "CNY",
  "expiresAt": "2026-08-06T00:00:00.000Z"
}
```

响应中的 secret 只返回一次，并通过 daemon 到 OpenMontage 的服务间安全通道传递。secret 不进入 MCP tool arguments、LLM 上下文、浏览器、日志或普通 Job JSON。

### 4.3 生命周期

```text
created -> active -> exhausted
                 -> expired
                 -> revoked
```

撤销条件：

- Job 成功、失败或取消。
- 达到预算上限。
- 超过最长有效期。
- MCP connection 被管理员禁用。
- Runtime credential 被轮换、冻结或撤销。
- workspace 或员工权限被撤销。

异步视频 Job 可能长于 AgentSpace Task，因此委托凭证不能依赖内存中的 MCP session。凭证和撤销状态必须持久化，并在每次 models 请求时校验。

## 5. 用量与对账

OpenMontage 每次 models 调用保存：

```json
{
  "openMontageJobId": "job-id",
  "stage": "assets",
  "operation": "image_generation",
  "modelAlias": "model-alias",
  "gatewayRequestId": "request-id",
  "gatewayUsageId": "usage-id",
  "startedAt": "...",
  "endedAt": "..."
}
```

AgentSpace 使用 `gatewayUsageId` 关联 models 权威 usage/charge：

1. models 完成单次调用并生成 usage 和 billing charge。
2. OpenMontage 将 `requestId/usageId` 写入 Job usage link。
3. Job 状态事件把 usage link 发送给 AgentSpace。
4. AgentSpace 将 link 与原 Task、员工和 Job 关联。
5. 成本中心从 models Billing Report 获取实际金额和结算状态。
6. 相同 `workspaceId + gatewayUsageId` 只允许存在一个模型用量记录。

OpenMontage 估算记录和 models 实际记录不能相加。估算只在实际金额尚未产生时作为 `estimated` 信息展示，并在对账后被实际值取代。

## 6. 账单展示

成本中心增加来源和 Job 维度：

```text
AI 员工：视频运营 Agent
├── Runtime 直接模型消费
└── OpenMontage
    └── Job video-456
        ├── assets / image generation
        ├── assets / TTS
        ├── compose / video generation
        └── review / video understanding
```

展示口径：

| 指标 | 权威来源 | 是否进入模型费用合计 |
| --- | --- | --- |
| 模型输入/输出 Token | models usage log | 是 |
| 按秒、按张、按字符等模型用量 | models usage log | 是 |
| 模型实际费用与结算状态 | models billing ledger/report | 是 |
| OpenMontage 任务估算 | OpenMontage cost tracker | 否 |
| CPU/GPU/渲染/存储用量 | OpenMontage service telemetry | 否，除非另有资源账本 |
| 平台视频处理服务费 | 独立 service usage ledger | 是，但必须与模型费用分项 |

## 7. 预算与审批

预算分三层：

1. OpenMontage 根据计划提供非权威估算。
2. AgentSpace 根据员工、workspace 和单任务策略决定是否需要审批。
3. models 通过委托凭证 `spendLimit` 和账务预检强制执行实际上限。

推荐流程：

```text
提交 brief
-> 生成成本估算
-> 超阈值则 WAITING_APPROVAL
-> 批准后签发/扩展委托额度
-> 每次模型调用做 billing preflight
-> 达到上限后停止新调用并进入 WAITING_APPROVAL 或 FAILED_BUDGET
```

## 8. 安全与审计要求

- 委托凭证采用高熵 opaque secret 或可撤销短期 token；不能只依赖可解码 JWT 的过期时间。
- models 从凭证记录读取归因，不信任 OpenMontage 自报的员工 headers。
- 日志只记录 delegation ID、fingerprint、requestId、usageId，不记录 secret。
- 所有创建、扩额、撤销、过期和拒绝事件必须有结构化审计记录。
- metrics 不使用 employeeId、jobId、requestId 作为标签；这些高基数字段只进入日志和 trace。
- 全链路传播 trace/correlation ID：AgentSpace Task -> MCP invocation -> OpenMontage Job -> models request。
