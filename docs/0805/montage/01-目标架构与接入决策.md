# 目标架构与接入决策

> 状态：Proposed
>
> 日期：2026-08-05

## 1. 背景

OpenMontage 已有 Docker 构建，镜像安装 FFmpeg、Python 依赖、Remotion、HyperFrames 和浏览器运行时，并默认启动 streamable HTTP MCP。它适合作为独立视频处理服务，而不是被复制或以 editable package 安装进每个 AgentSpace Runtime。

当前 OpenMontage 对外能力仍偏向“准备参考视频项目”：CLI 提供 `clone`、`status`、`capabilities`、`mcp`；MCP 提供 `prepare_reference_clone`、`openmontage_capabilities`、`reference_clone_status`。完整视频生产仍缺统一的异步 Job 契约、取消、审批、产物传输和服务级计费归因。

OpenMontage 当前代码中的默认网关地址是 `https://model.local.dofe.ai/api`，而目标部署地址表述为 `models.local.dofe.ai`。部署必须通过受管配置明确注入并验证 `DOFE_MODEL_BASE_URL`，不能依赖默认值；Phase 0 需确定唯一规范域名，避免请求进入错误环境或产生无法对账的消费。

AgentSpace 已具备 Runtime App、MCP Catalog、task-scoped MCP Gateway、工具审批和受管服务编排基础，但现有 MCP Center 对工作区私有项只开放 `streamable_http` 与 `managed_stdio`。本地 HTTP MCP 又必须经过公网 HTTPS/443 检查，不能直接连接 localhost 或 Docker 私网地址。

## 2. 决策

最终产品形态采用：

1. **执行面**：OpenMontage digest-pinned Docker `managed_service`。
2. **Agent 接口**：task-scoped MCP Gateway。
3. **业务核心**：OpenMontage 异步 Video Job Service。
4. **运维接口**：复用 Job Service 的 REST API 和薄 CLI 客户端。
5. **数据面**：Artifact Bridge，不经 MCP 传输大型媒体二进制。
6. **模型调用**：Job 级 Runtime 委托凭证，最终由 models 权威结算。

MCP 是 Agent 的控制协议，CLI 是人和自动化的调试协议，Docker 服务才是完整视频能力的执行边界。

## 3. 方案比较

| 方案 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- |
| Runtime 直接安装 OpenMontage CLI | 开发简单、文件操作直观 | Python wheel 无法完整携带 FFmpeg、Node、Chromium、Remotion 资源；本地路径不可审计 | 仅用于开发调试 |
| Runtime 执行 `docker exec` | 看似直接 | 必须暴露 Docker socket/宿主权限，租户隔离不可接受 | 禁止 |
| `managed_stdio` MCP | 原生工具协议、无公网入口 | 受管节点为 `--network none` 且不挂载任务工作目录，无法承担下载和模型调用 | 仅适合轻量无网络工具 |
| 本地 `streamable_http` MCP | OpenMontage 已支持 | 当前安全策略拒绝 localhost、私网地址和非 HTTPS/443 | 不放宽安全策略 |
| 公网 HTTPS MCP | 可复用现有 external connection | 本地服务暴露公网，文件、认证、回调和租户隔离复杂 | 后续外部托管场景 |
| MCP `managed_service` | 服务隔离、工具审批、审计、完整依赖、内部网络 | 需要补齐 MCP Center 与受管服务连接引用 | **推荐最终方案** |

## 4. 组件职责

### 4.1 AgentSpace Runtime

- 代表具体 AI 员工执行任务。
- 只看到批准后的 OpenMontage MCP 工具。
- 不接触 OpenMontage 服务地址、服务密钥或 Runtime 原始模型密钥。
- 通过 Artifact ID 引用输入和输出。

### 4.2 MCP Gateway

- 将 task、workspace、runtime、employee、conversation 解析为可信调用上下文。
- 执行工具批准、逐调用 fencing、撤销和审计。
- 为创建 Job 的调用申请短期模型委托凭证。
- 通过受管服务 connection reference 访问 OpenMontage，而不是接受浏览器提供的私网 URL。

### 4.3 OpenMontage Managed Service

- 运行不可变镜像和固定视频运行时版本。
- 接收结构化 Job 请求并异步执行。
- 管理视频阶段、审批点、重试、取消和产物清单。
- 使用任务级委托凭证访问 models。
- 记录 models `requestId/usageId`，但不自行结算实际模型金额。

### 4.4 Artifact Bridge

- 输入：把 Runtime 附件转换为 OpenMontage 可读取的 Artifact 引用。
- 输出：把 OpenMontage 产物登记为 Runtime 可回收的 Artifact。
- 为每次读写签发短期、单用途凭据。
- 校验媒体类型、大小、SHA-256、路径和租户边界。

### 4.5 models.dofe.ai

- 验证 Runtime 委托凭证。
- 执行路由、预检、预留、调用、用量记录和结算。
- 保存 AI 员工、Runtime、会话、OpenMontage Job 和阶段归因。
- 提供权威 Billing Report。

## 5. 网络和存储边界

受管部署应满足：

- OpenMontage 与 MCP Gateway 位于 workspace + runtime scoped 私有网络。
- OpenMontage 不对公网暴露管理端口。
- OpenMontage 不挂载 Docker socket、Provider HOME、Runtime 凭据目录或完整工作目录。
- 容器只挂载自己的持久状态卷和受控 Artifact 交换目录。
- 根文件系统只读，临时目录和渲染目录使用独立限额卷。
- 模型、素材下载和 Artifact 服务出站域名由 catalog 模板白名单控制。
- 数据库、Redis、RabbitMQ 如需使用，均连接外部集中管理实例。

## 6. 本地开发过渡方案

在 `managed_service` MCP 完成前，可使用以下过渡链路验证 Job API：

```text
Runtime -> openmontage-client -> OpenMontage REST Job API -> Artifact exchange
```

限制如下：

- CLI 必须是薄客户端，不包含视频引擎。
- Endpoint 由 daemon 注入，浏览器不能自由填写。
- 仅在本地开发 Runtime 网络内启用。
- 仍使用 Job 级委托凭证，不能退回共享模型 Key。
- 该路径用于验证，不作为最终工具审批和审计边界。
