# OpenMontage delegation 生产门禁修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**目标：** 关闭审计发现的 Runtime/MCP purge、durable model invocation、usage 归因、charge/ledger 完整性、MCP 双删除策略和 exactly-once 故障注入 E2E 门禁。

**架构：** models 继续作为模型消费、价格和账本的唯一权威；OpenMontage 负责 Job 本地 invocation outbox 和 Worker 恢复；AgentSpace 负责 Job/Runtime/MCP 生命周期、pending usage 投影和聊天可见状态。清理采用 `禁止新调用 -> DRAINING -> 终态对账 -> REVOKED -> purge`，任何一端都不能绕过 models 门禁。

**技术栈：** NestJS/Prisma/PostgreSQL（models）、TypeScript/SQLite/PostgreSQL（AgentSpace）、Python/SQLite/requests（OpenMontage）、Jest、Node test、pytest。

## 实施边界

- 不新增或嵌入 PostgreSQL、Redis、RabbitMQ 服务；只连接现有集中式基础设施。
- 不使用 Jenkins，不执行部署；只做代码、迁移、测试和文档提交。
- 每个独立实施单元先加失败测试，再改代码，再运行聚焦测试并提交。
- 保留现有 `.superpowers/` 等无关工作区变更，不纳入提交。
