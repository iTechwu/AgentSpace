## 1. P1-06 readiness：分离 /health/live 与 /health/ready

- 新增 `apps/web/app/api/health/live/route.ts`：liveness（进程存活、事件循环可响应，不做外部依赖检查）。
- 新增 `apps/web/app/api/health/ready/route.ts`：readiness——一次轻量 `SELECT 1` + schema 版本读取（`getDatabase()` + `readMetadataValue`），DB 不可达返回 503；不调用慢外部供应商。
- `apps/web/app/api/health/route.ts` 保留为兼容入口（返回 200 即存活），并指向 live/ready。
- 新增 `deploy/self-hosted/healthcheck.mjs`：非 HTTP 服务（worker/daemon/maintenance）的 readiness 探针（退出码 0/非 0），与 Web 走同一 `getDatabase()` 门面。
- `deploy/self-hosted/docker-compose.yml`：
  - `web` healthcheck 由 `/api/health` 改为 `/api/health/ready`（readiness，`start_period` 20s→30s）。
  - 为 `runtime-maintenance` / `workflow-worker` / `daemon-claude` / `daemon-codex` 补齐 `healthcheck`（`node --experimental-strip-types deploy/self-hosted/healthcheck.mjs`）。
- `deploy/workflow-worker/Dockerfile` 增补 `COPY deploy/self-hosted/healthcheck.mjs`（该镜像只拷入 worker 子集，原不含 deploy/ 目录）。
- `.github/workflows/deploy-production.yml` 的 `HEALTHCHECK_URL` 改为 `/api/health/ready`。

已知限制（记录而非修复）：readiness 走同步 DB 门面（worker thread + Atomics.wait），DB 连接超时会短暂阻塞事件循环，属 P1-02「DB 异步切流」既有限制。

## 2. P1-01：统一 .dockerignore + Web standalone

- 新增根 `.dockerignore`：排除 `.git`/`node_modules`/`.next`/`dist`/`data`/`docs`/`.pnpm-store` 等（此前无 ignore，约 13 GiB 的 `.next`+node_modules 全量进 build context）。
- `apps/web/next.config.mjs` 启用 `output: "standalone"`：实测构建产出 `apps/web/.next/standalone/apps/web/server.js`（standalone 88M vs 完整 workspace 数 GiB）。`next start` 流程不受影响（standalone 是额外产物）。
- 后续（需目标平台 Docker 验证，未在本轮改）：self-hosted Dockerfile 的 web target 只复制 `.next/standalone` + `.next/static` + `public`，Workflow Worker 改为 esbuild/tsc 单文件 bundle。

## 3. CI verify workflow（不部署）

- 新增 `.github/workflows/ci-verify.yml`：push/pull_request 触发，`actions/setup-node` 读 `.node-version`（Node 24），`pnpm install --frozen-lockfile` 后跑 `pnpm run ci:verify`，再跑生产依赖审计（显式 `--registry=https://registry.npmjs.org`）。
