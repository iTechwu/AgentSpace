# 员工 Skill 环境变量：端到端安全证明（§6.2）

> 状态：实现配套的安全分析文档（2026-07-31）
>
> 范围：员工 x Skill 的 `config`/`secret`/敏感 `extraKeys` 值从「输入 → 落库 → 传输 → 子进程 → 输出/审计」全生命周期的控制与证据。对应主规格 §6「运行时与安全契约」第 2、6 条。

## 1. 威胁模型

| 假设 | 说明 |
| --- | --- |
| 对抗者不能读写数据库 | 值在数据库中以密文存储；即使拿到 `encrypted_secrets_json`，无 `DOFE_AGENT_SKILL_CREDENTIAL_ENCRYPTION_KEY` 也无法解密 |
| 对抗者不能冒充已绑定 daemon | input bundle 走已认证的 daemon 控制面（Bearer daemon token，工作区级），受管远程 Runtime 另有部署级 mTLS |
| 对抗者能读取页面数据、任务产物、日志、审计 note | 这些通道在服务端/前端均不携带值（见 §3 各阶段控制） |
| 对抗者能拿到 Provider 子进程的 stdout/stderr 与任务产物 | 执行输出在落库前按「注入 Key 名 + 命名模式」双重脱敏 |
| **信任边界**：已认证、已绑定的 daemon 进程本身是可信执行环境 | 它按授权关系取得明文值并注入子进程；daemon 内存中的明文值不在本证明的物理防读取范围内 |

## 2. 数据生命周期

```
UI 输入 ──▶ 服务端 normalize/validate ──▶ AES-256-GCM 加密落库
                                          │
任务启动 ──▶ 服务端解密 → input bundle ──▶ 已认证 daemon（仅 bundle.files 落盘）
                                          │
                                          └─▶ Provider 子进程临时 env
                                                │
                                              输出 stdout/stderr ──▶ 按 Key 值脱敏 ──▶ 落库/展示
```

值**始终不进入**：`SKILL.md`、`skill.config.json`、任务产物、审计 note、浏览器响应、页面数据。

## 3. 各阶段控制与证据

### 3.1 输入与校验

- `normalizeSkillRequirementConfiguration`（[packages/services/src/skills/requirements.ts](../packages/services/src/skills/requirements.ts)）校验：键名大写、值长度 ≤4096、`DOFE_AGENT_*` 保留前缀拒绝、敏感标记仅限声明或额外键。
- 声明解析时 `SECRET_KEY_PATTERN` 自动把 `config:FOO_TOKEN` 升级为 secret；额外变量同名自动加密。

### 3.2 静态存储（At rest）

- 表 `agent_skill_requirement_config`：`config_json`（普通值）、`encrypted_secrets_json`（AES-256-GCM 密文）。
- `encrypt`/`decrypt`（[agent-skill-requirements.ts](../packages/services/src/skills/agent-skill-requirements.ts)）：版本化格式 `v1:iv:authTag:ciphertext`，AES-256-GCM（AEAD），密钥来自 `DOFE_AGENT_SKILL_CREDENTIAL_ENCRYPTION_KEY`（32 字节 base64）。
- 密钥缺失时服务端**拒绝保存**（`readEncryptionKey` 抛错），绝不降级为明文；前端 action 有定向错误文案。
- 敏感 `config`/`secret`/敏感 `extraKeys` 的值**不写入** `config_json.values`（`plaintextValues` 过滤掉 `sensitiveKeys`）。

### 3.3 传输（In transit）

- 任务 input bundle（`metadata.skillEnv`）携带明文值，路由 `apps/web/app/api/daemon/tasks/[taskId]/input-bundle/route.ts` 经 `requireDaemonAuth`（Bearer daemon token + 工作区校验）才返回；受管远程 Runtime 另有部署级 mTLS。
- bundle 仅经该认证通道传输；daemon 只物化 `bundle.files`，`skillEnv` 仅在内存中使用。

### 3.4 子进程注入

- `readAgentSkillRequirementEnvSync` 只返回该员工、该 Skill 已声明 + `extraKeys` 的键，且解密密钥；`resolveAgentSkillEnvironment` 合并技能变量，`assertNoInstalledSkillEnvironmentConflicts` / input-bundle 409 阻断异值冲突。
- Provider 子进程以临时 env 启动；`buildEnvValueRedactions` 以「该次任务注入的键名」为索引收集其值，供输出脱敏使用。

### 3.5 输出与遥测脱敏

- `buildRedactions`（命名模式：`TOKEN`/`SECRET`/`API_KEY` 等，见 [packages/daemon/src/agent-router/utils.ts](../packages/daemon/src/agent-router/utils.ts)）+ `buildEnvValueRedactions`（**按注入 Key 名逐一脱敏**，覆盖 `MY_SERVICE_CODE` 等非命名模式敏感值）。
- 两者在 `provider-runtime.ts` 与 `agent-router/router.ts` 启动 Provider 前合并为 `redactions`，对 stdout/stderr 全文做 `KEY=value`、JSON 字段、URL query、异常回显的统一文本替换（`redactText`）。

| 输出形态 | 覆盖方式 | 证据 |
| --- | --- | --- |
| `KEY=value` 行 | `redactText` 按值替换 | `buildEnvValueRedactions` 生成 `[redacted:KEY]` |
| JSON 字段值 | 全文文本替换（值字符串） | `redactText` |
| URL query（`?token=…`） | 值字符串替换 | `redactText` |
| 异常回显（含堆栈里的值） | 值字符串替换 | `redactText` |
| 审计 note / data | 只记键名与数量，从不记值 | §3.6 |

### 3.6 审计

- 安装/更新：`workspace.agent_skill_requirements_configured/updated`，data 只含 `configKeys`/`secretKeys`/`sensitiveKeys` 名称与计数。
- 删除：`workspace.agent_skill_requirement_key_deleted`，含键名与敏感标记。
- 轮换：`workspace.agent_skill_secret_rotated`（独立事件），只含键名。
- 转交：`workspace.agent_skill_configuration_requested`，只含键名与数量。
- 所有事件经 `tryRecordWorkspaceAuditEventSync` 写入工作区 ledger，值不进入任何字段。

### 3.7 浏览器 / 页面

- 摘要 `environment` 仅含 `{ key, kind, sensitive, configured }`（无值）；`updatedAt/updatedBy` 是元数据。
- 非管理员经 `redactSkillRequirementsForViewer` 连环境变量明细都不返回（仅状态与计数）。
- 维护弹窗明文仅存在于浏览器内存，保存后只回显「已配置/留空保留」。

## 4. 验证

- 服务测试（`agent-skill-requirements.test.ts` 37 + `requirements.test.ts` 8）：摘要不泄露密钥、密钥加密且非敏感值不落明文、敏感 extra 值不入 `config_json.values`、保留 Key 拒绝。
- daemon 测试（`task-context-skill-env.test.ts` + `agent-router/utils.test.ts` 10）：按注入 Key 值脱敏、运行时合并与兜底冲突。
- web 测试：`agents-page-client.test.tsx`「已安装 Skill 维护入口不泄露密钥」。
- 相关数据库测试须顺序执行（共享测试库）。

## 5. 残余风险与后续

1. **daemon 内存明文**：已认证、已绑定的 daemon 在注入前持有明文值；这是可信执行环境的固有边界，不承诺对 daemon 进程的物理内存防读。
2. **密钥管理**：`DOFE_AGENT_SKILL_CREDENTIAL_ENCRYPTION_KEY` 的保管/轮换属平台运维，不在本链路内。
3. **传输层**：Bearer token + 部署级 mTLS 取决于部署配置；本地模式下不涉及远端明文传输。
4. **加密键名痕迹**：`encrypted_secrets_json` 的**键名**未加密（键名非敏感），值密文安全。

## 6. 结论

§6 第 2、6 条的契约已端到端满足：值在静态加密、传输走已认证通道、进程内临时注入、输出按注入 Key 值与命名模式双重脱敏、审计与页面均不含值。剩余风险均为可信执行环境边界或平台运维范畴。
