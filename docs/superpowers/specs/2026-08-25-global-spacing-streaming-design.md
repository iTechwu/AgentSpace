# 全站间距与稳定流式反馈设计规格

> 已确认的完整产品与技术设计见 [全站间距与稳定流式反馈设计](../../0825/im-uiux/05-全站间距与稳定流式反馈.md)。

## 决策摘要

- 采用 Token 驱动、渐进收敛的实施路线。
- 全站使用 `24 / 16 / 12 / 8px` 平衡密度，表格、日志和执行轨迹允许局部紧凑。
- IM 使用稳定节点、单节点更新和 `requestAnimationFrame` 分帧批处理。
- 用户离开底部后保持阅读位置，通过“有新输出”入口恢复跟随。
- 用户主动展开或收起的执行节点不受后续增量影响。
- Harness 已报告但无法识别的事件降级展示，不静默丢失。
- 使用真实浏览器覆盖桌面、移动、长输出、断线、错误恢复和无障碍回归。

## 交付边界

本轮收敛共享页面骨架、间距 tokens 和高频页面模板，同时优化 IM 流式状态与渲染。不会重做导航信息架构、任务协议、权限模型或整套组件库，也不会为每个 token 创建独立消息节点。

## 验收门槛

1. 主要页面在 320px、390px、768px 和 1440px 下无遮挡、溢出或页面横向滚动。
2. 流式期间每帧最多一次状态提交，兄弟节点不因单节点增量 remount。
3. 展开状态、文本选择、详情滚动和会话阅读位置保持稳定。
4. 可恢复错误后仍显示正确最终回复，未知 Harness 事件有安全降级展示。
5. 使用优惠豚测试账户完成真实浏览器登录、IM 发送、流式、展开收起、控制台和网络回归。
