# 组织架构层级视图设计

## 目标

将当前按成员类型平铺的“组织树”改为真正具有根节点、组织单元和成员节点的层级图，让用户第一眼看清工作区范围、成员构成和上下级层次。

## 数据边界

现有 `OrgChartPageData` 只包含人类成员、AI 员工、角色、在线状态及所属群组，没有部门或直属上级字段。本次不虚构汇报关系，使用可被现有数据准确支持的三层结构：

1. 工作区全体（根节点）
2. 人类团队、AI 员工团队（组织单元）
3. 对应成员（叶子节点）

后续数据模型增加部门或直属上级字段时，可在组织单元和成员之间继续嵌套节点，不需要推翻现有视觉结构。

## 交互与布局

- 顶部保留组织树 / 按群组分段切换，使用 `tablist`、`tab` 和 `tabpanel` 语义。
- 组织树自上而下排列，通过连续的竖线和横向分支线连接父子节点。
- 组织单元显示成员数量；成员节点继续显示头像、角色、状态和最多三个群组。
- 某类成员为空时，仍显示对应组织单元及紧凑空节点，避免层级断裂。
- 宽屏优先完整展示，内容超出时在画布内部横向滚动；窄屏保持树的方向和连接关系。
- 按群组视图保持原有逻辑，仅复用统一成员卡视觉和空状态。

## 视觉原则

- 根节点视觉权重最高，使用深色标题、组织图标和汇总人数。
- 组织单元使用轻量边框与类型标记，连接线使用中性绿色灰，避免与在线状态混淆。
- 成员卡固定宽度，内容截断且不改变节点尺寸，避免动态文本造成布局跳动。
- 卡片圆角不超过 8px，状态保留文字，不能只依赖颜色表达。
- 所有交互按钮保留清晰焦点态，并尊重减少动态效果偏好。

## 验收标准

- 组织树存在一个根节点、两个组织单元及与数据数量一致的成员节点。
- 根节点、组织单元和成员之间存在可见连接线。
- 视图切换有正确的选中语义，按群组视图仍可使用。
- 人类或 AI 员工为空时仍呈现完整组织分支和明确空状态。
- 中文和英文界面均可读，桌面与移动视口无重叠或溢出破坏。
