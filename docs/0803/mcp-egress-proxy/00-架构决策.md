# ADR：在当前 monorepo 内新增 Compose 专用 MCP Egress Proxy

> 状态：已实施（Phase 0/1/2）
>
> 日期：2026-08-03

## Context

AgentSpace 已经具备 daemon 侧 loopback MCP gateway：Provider 只能看到 task-scoped loopback URL，daemon 在内存中持有远程 endpoint 与密钥，并在每次工具调用前复核 connection/tool 授权。

当前缺口在于 Runtime 容器仍需要基础设施级的出口约束。只做 endpoint 校验，不能阻止 Provider 或被攻陷的第三方进程自己访问远程 MCP、公共 proxy 或原始 IP。现有 `managed-node` 有 Docker socket、host network 和 `NET_ADMIN`，它可以执行编排和宿主机防火墙策略；这些高权限不能交给 Runtime 或新 proxy。

实际部署使用 Docker Compose。设计不能依赖 Kubernetes `NetworkPolicy`、sidecar 注入或集群服务网格。

## Decision

在本仓库新增独立 app `apps/mcp-egress-proxy`，并生成独立 `mcp-egress-proxy` 镜像和 Compose service。

- 实现位置：[`apps/mcp-egress-proxy`](../../../apps/mcp-egress-proxy)
- 契约位置：[`packages/domain/src/daemon-api.ts`](../../../packages/domain/src/daemon-api.ts)（MCP egress proxy 段落）
- lease 工具位置：[`packages/services/src/mcp-center/egress.ts`](../../../packages/services/src/mcp-center/egress.ts)
- daemon proxy client 位置：[`packages/daemon/src/mcp/egress-client.ts`](../../../packages/daemon/src/mcp/egress-client.ts)
- 独立 Dockerfile：[`deploy/daemon/Dockerfile.mcp-egress-proxy`](../../../deploy/daemon/Dockerfile.mcp-egress-proxy)

proxy 不是：

- 通用 HTTP/HTTPS/SOCKS proxy；
- 可由 Provider 通过 `HTTP_PROXY` 直接使用的公网出口；
- 控制面数据库客户端；
- 持有 Docker socket、host network、`NET_ADMIN`、Provider 凭据或 Runtime HOME 的服务。

proxy 是：

- 只服务 MCP Streamable HTTP 所需 `GET`、`POST`、`DELETE` 的受控 transport bridge；
  - 实现：[`apps/mcp-egress-proxy/src/server.ts`](../../../apps/mcp-egress-proxy/src/server.ts) 的 `/v1/mcp/sessions` 与 `/healthz` 路由，以及 [`upstream-transport.ts`](../../../apps/mcp-egress-proxy/src/upstream-transport.ts) 的 method/path 限制。
- 只接受 daemon 提供的短期、签名、绑定 connection/task 的 lease；
  - 实现：[`packages/services/src/mcp-center/egress.ts`](../../../packages/services/src/mcp-center/egress.ts) 的 `signMcpEgressLease` / `verifyMcpEgressLease`，以及 [`apps/mcp-egress-proxy/src/lease-verifier.ts`](../../../apps/mcp-egress-proxy/src/lease-verifier.ts)；daemon 侧推送与使用见 [`packages/daemon/src/mcp/egress-client.ts`](../../../packages/daemon/src/mcp/egress-client.ts)。
- 按 immutable release/connection 派生的 policy 选择唯一上游 endpoint；
  - 实现：[`packages/domain/src/daemon-api.ts`](../../../packages/domain/src/daemon-api.ts) 的 `McpEgressPolicyRevision` 与 `McpEgressPolicySnapshot`，以及 [`apps/mcp-egress-proxy/src/policy-cache.ts`](../../../apps/mcp-egress-proxy/src/policy-cache.ts)。
- 独立解析 DNS、校验 TLS 并将连接 pin 到已校验地址；
  - 实现：[`apps/mcp-egress-proxy/src/upstream-transport.ts`](../../../apps/mcp-egress-proxy/src/upstream-transport.ts) 的 `pinnedHttpsRequest`。
- OAuth 模式下向内部 token broker 领取一次性注入材料；
  - 当前：[`apps/mcp-egress-proxy/src/oauth-injector.ts`](../../../apps/mcp-egress-proxy/src/oauth-injector.ts) 为 Phase 3 占位 stub。
- 记录结构化、脱敏的连接审计，不存工具参数、结果、Authorization 或完整 URL query。
  - 实现：[`apps/mcp-egress-proxy/src/audit.ts`](../../../apps/mcp-egress-proxy/src/audit.ts)。

## Deployment Boundary

```text
同一 Git 仓库
  apps/web                 控制面与 API
  packages/domain          lease/policy/release 类型契约
  packages/daemon          proxy client 与 gateway 调用链
  apps/mcp-egress-proxy    独立进程、独立最小化镜像

同一 Compose 主机
  managed-node             唯一允许 Docker socket / host network / NET_ADMIN 的编排器
  runtime-*                不具备上述权限
  mcp-egress-proxy         不具备上述权限，只连接运行时网络与受控出口网络
```

源码同仓库是为了让 `McpEgressLease`、release pin、daemon 调用和安全测试保持原子变更；运行时仍然是独立进程与独立容器。新开仓库不会提升隔离，反而增加跨仓契约和版本漂移风险。

## Alternatives Considered

### 不新增 proxy，只依赖 daemon 校验

拒绝。daemon 校验不能阻止 Runtime 内其他进程绕过 daemon 直接出网。

### 给所有 Runtime 设置 `HTTP_PROXY`

拒绝。Provider 可以看到并滥用该配置；通用 proxy 无法按 task、connection、release 和 tool 细分授权。

### 每个 Runtime 一个 proxy

首期拒绝。会提高镜像、升级、证书、审计和故障治理成本，且不能天然带来更强的 policy 语义。共享 proxy 通过短期 lease 进行租户隔离；压力或隔离要求出现后可按 node/故障域横向部署。

### 现在新建独立仓库

拒绝。MCP release、connection、daemon task claim 仍在本仓库，拆仓会使安全契约发布无法原子化。只有 proxy 成为多个产品共用的平台服务、拥有独立团队或需要独立合规发布时，再评估拆仓。

### Kubernetes NetworkPolicy

不作为方案依赖。Kubernetes 可在未来提供等价实施，但当前唯一目标是 Docker Compose + 宿主机 `DOCKER-USER` 防火墙。

## Consequences

- 新增一个可用性组件。proxy 不可用时 MCP 调用失败，严禁回退直连。
- 增加 daemon 到 proxy 的协议、短期 lease 签发和撤销 feed。
- Compose 必须按本文网络设计部署，不能继续把 Runtime 放在未限制的默认 `bridge` 网络。
- proxy 的安全证明包含容器与宿主机防火墙负向测试，而不仅是代码单元测试。
- 首期不需要新数据库服务；policy/release 数据使用现有控制面数据库，proxy 使用签名 lease 和短时内存缓存。
