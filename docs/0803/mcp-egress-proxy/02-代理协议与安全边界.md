# Proxy 协议、Policy Lease 与安全边界

> 状态：Phase 0/1/2 已实施，OAuth 注入为 Phase 3 占位
>
> 目标：proxy 只能代表指定 daemon 对指定 connection 的指定上游发起有限期 MCP 调用。

## 1. 调用路径

```text
Provider
  -> task-scoped loopback MCP gateway
  -> daemon RuntimeMcpClient
  -> mcp-egress-proxy
  -> remote Streamable HTTP MCP
```

Provider 只拥有 gateway URL 和工具 schema。endpoint、密钥、OAuth material、proxy lease 均只存在于受信 daemon 或 proxy 的短期内存中。

## 2. Policy Revision

控制面在 release/connection 验证成功后生成不可变 policy revision。release 只定义上限，connection 只能收窄。

```ts
interface McpEgressPolicyRevision {
  id: string;
  workspaceId: string;
  connectionId: string;
  releaseId: string;
  releaseManifestDigest: `sha256:${string}`;
  manifestDigest: `sha256:${string}`;
  upstream: {
    origin: string;
    allowedHosts: string[];
    allowedPorts: [443];
    allowedPathPrefix: string;
  };
  transport: "streamable_http";
  redirectPolicy: "deny";
  denyPrivateNetworks: true;
  tlsMode: "verify_system" | "verify_private_ca";
  privateCaDigest?: `sha256:${string}`;
  authMode: "none" | "static_header" | "oauth_proxy";
  maxRequestBytes: number;
  maxResponseBytes: number;
  maxConcurrentStreams: number;
  maxRequestsPerSecond: number;
  createdAt: string;
}
```

**实现位置**：[`packages/domain/src/daemon-api.ts`](../../../packages/domain/src/daemon-api.ts) 的 "MCP egress proxy — lease/policy contract" 段落；稳定 digest 计算见 [`packages/services/src/mcp-center/egress.ts`](../../../packages/services/src/mcp-center/egress.ts) 的 `canonicalizeMcpEgressPolicyRevision` / `digestMcpEgressPolicyRevision`。

`releaseId` 使用不可变 catalog release 记录 ID，`releaseManifestDigest` 对 release 的安全相关字段做确定性摘要；`manifestDigest` 是 policy 自身摘要。lease 同时签名 release/policy 两个 digest，任一不匹配时 proxy 必须拒绝。connection 编辑、release 升级、host/tool/schema/OAuth scope 变化都会产生新 policy revision，并使 connection 重新验证。

## 3. Lease

daemon 通过已认证控制面 API 为 verify、health check 或每一次工具调用领取短期签名 lease。task session claim 不预签可重复使用的 task lease：

当前 lease wire version 为 `deg2`；缺少 release digest/QPS 契约的 `deg1` lease fail-closed，不做静默兼容。

```ts
interface McpEgressLeaseClaims {
  iss: "agentspace-control-plane";
  aud: "mcp-egress-proxy";
  jti: string;
  workspaceId: string;
  runtimeId: string;
  connectionId: string;
  releaseId: string;
  releaseManifestDigest: `sha256:${string}`;
  policyRevisionId: string;
  policyDigest: `sha256:${string}`;
  purpose: "verify" | "health_check" | "task_call";
  taskId?: string;
  operationId?: string;
  toolName?: string;
  exp: number;
}
```

**实现位置**：[`packages/domain/src/daemon-api.ts`](../../../packages/domain/src/daemon-api.ts) 的 `McpEgressLeaseClaims`；签名与验证见 [`packages/services/src/mcp-center/egress.ts`](../../../packages/services/src/mcp-center/egress.ts) 的 `signMcpEgressLease` / `verifyMcpEgressLease`。

约束：

- TTL：verify 最长 120 秒，health check 最长 60 秒，task call 最长 60 秒；
- proxy 验证签名、时钟、audience、连接/release/policy 一致性和当前撤销状态；
- lease 签名内容包含 canonical `policyDigest`，proxy 对 snapshot 重算 digest 后再接受和转发；
- `jti` 首次使用后绑定 proxy session，不能跨 Runtime、connection、task 或 session 重放；`task_call` lease 在绑定 session 内可完成协议握手，但最多消费一个 `tools/call`，消费状态随 JTI 持久化；
- 单副本 JTI/policy 状态使用原子 JSON 文件；policy set/revoke 仅在候选状态写盘成功后提交内存，文件损坏或不可读时 proxy 启动失败，不能静默清空或半提交防重放/deny 状态；
- connection disabled、release yanked、OAuth revoked 会推入 proxy deny cache；撤销 tombstone 单调且支持先于 policy 到达，同一 revision 的后续普通 push 不能解除撤销；policy snapshot 新鲜度窗口为 120 秒（允许 30 秒未来时钟偏差），缓存失败、时间戳无效或过期时拒绝新 lease；
- lease 不出现在 Provider argv、env、文件、日志、task bundle 或 browser response。

## 4. Proxy API

proxy 不暴露通用 CONNECT，也不接受由调用方决定的任意上游 URL。daemon 传入 MCP 协议帧和 lease；上游 origin/path 由 proxy 从已签名 lease 对应 policy 中取得。

```text
POST   /v1/admin/policies          daemon/控制面推送 policy snapshot（需 x-dofe-admin-token）
GET    /metrics                    运行指标（需 x-dofe-admin-token）
POST   /v1/mcp/sessions
POST   /v1/mcp/sessions/:id/messages
GET    /v1/mcp/sessions/:id/events
DELETE /v1/mcp/sessions/:id
GET    /healthz
```

**实现位置**：[`apps/mcp-egress-proxy/src/server.ts`](../../../apps/mcp-egress-proxy/src/server.ts) 的 `McpEgressProxyServer`。当前实现通用请求转发：`/healthz` 无需 lease，`/v1/admin/policies` 需 admin token，其余路径需 `Authorization: DofeEgressLease <signed-lease>`，并按 policy 的 `allowedPathPrefix` 校验 path。daemon 在首次经 proxy 调用前通过 `packages/daemon/src/mcp/egress-client.ts` 推送 policy snapshot。

认证使用 `Authorization: DofeEgressLease <signed-lease>`，daemon 同一 transport 还会携带不可猜测的 `x-dofe-egress-session`。proxy 将 JTI 绑定到该 session，二者都不转发给上游。proxy 只转发 MCP 所需、固定 allow-list 中的协议 header；`task_call` lease 仅允许握手/通知所需的 `initialize`、`notifications/initialized`、`notifications/cancelled`、`ping` 以及绑定工具的 `tools/call`，工具名必须等于 lease 中的 `toolName`；JSON-RPC batch 逐项校验，畸形 JSON fail-closed。

拒绝：任意 `Host` 覆盖、absolute-form URL、redirect、用户自定义 proxy header、WebSocket、SOCKS、HTTP/3、未声明的请求 method/内容类型、超大或无限流响应。

## 5. DNS/TLS 与请求限制

proxy 在每个新上游连接时：

1. 用自己的 resolver 解析 policy host；
2. 任一结果是 loopback、RFC1918、link-local、multicast、documentation、metadata 或未批准 IPv6 地址时整体拒绝；
3. 连接到已校验 IP，同时以原 host 作为 TLS SNI 和证书 hostname；
4. 不跟随 redirect，不因 DNS 失败降级为客户端解析结果；
5. 限制 connect/header/request/idle timeout、总 bytes、并发 stream、每 connection QPS；
6. 清理所有错误中的 URL query、授权 header、secret 和 MCP payload。

**实现位置**：[`apps/mcp-egress-proxy/src/upstream-transport.ts`](../../../apps/mcp-egress-proxy/src/upstream-transport.ts) 的 `forwardToUpstream` 与 `pinnedHttpsRequest`，复用 [`packages/services/src/mcp-center/security.ts`](../../../packages/services/src/mcp-center/security.ts) 的 `validateMcpEndpoint` 与 `validateMcpResolvedAddresses`。

审计只保存 connection/release/policy ID、lease JTI hash、上游 host hash、method、结果码、延迟和尺寸分桶。

## 6. OAuth

OAuth refresh token 保存在控制面 token vault。proxy 用 lease 内的 opaque grant reference 向 token broker 兑换一次性 access-token 注入材料，再向上游添加 Authorization。

**当前状态**：[`apps/mcp-egress-proxy/src/oauth-injector.ts`](../../../apps/mcp-egress-proxy/src/oauth-injector.ts) 为 Phase 3 占位实现；当前支持 `none` 与 `static_header`。static header 通过受认证 policy push 进入 proxy 短期内存，持久 policy/revoke 文件会主动剥离认证材料。私有 CA 使用保留 secret field `tls_ca_pem`（兼容 `ca_pem` / `MCP_TLS_CA_PEM`）进入短期 snapshot，policy 只保存 CA digest，持久状态同样剥离 PEM。

daemon 以及 Provider 均不读取 refresh token。若一期尚未实现 proxy 注入，OAuth MCP 不得 GA；不要将长期 token 临时写入 Runtime 配置或环境变量。

## 7. Daemon/Provider 进程边界

现有 daemon 启动 Provider 的方式意味着二者可能共享容器和 UID。仅靠“不把 lease 放 env”不足以防止恶意 Provider 读取 daemon 内存。

enforce 前必须完成：

- daemon proxy client fd 为 `close-on-exec`，不继承给 Provider；
- daemon 设为 non-dumpable；Provider seccomp 拒绝 `ptrace`、`process_vm_readv`、`process_vm_writev`；
- daemon 与 Provider 使用不同 UID，并限制 Provider 查看 daemon `/proc`；
- Compose 负向测试以真实 Provider UID 验证无法读取 daemon `environ`、`fd`、`mem`；
- 长期目标是将受信 daemon/gateway 与 Provider worker 拆为独立容器或至少独立 PID namespace。

未满足上述条件前，Compose 默认 `MCP_EGRESS_ENFORCE=false`，proxy 只能 observe/canary，不能声明能抵御被攻陷 Provider 主动窃取 lease。Provider 子进程环境会剥离全部 `MCP_EGRESS_*` 变量，但这不替代 UID/PID/`/proc` 隔离。

## 8. Proxy Container 权限

| 项目 | 要求 |
| --- | --- |
| user | 固定非 root UID |
| root filesystem | `read_only: true` |
| temporary files | 受限 `tmpfs` |
| capabilities | `cap_drop: [ALL]` |
| privilege | `no-new-privileges:true` |
| Docker socket | 不挂载 |
| host network | 禁止 |
| ports | 仅 `expose`，不 `ports` 发布 |
| Runtime/Provider volume | 禁止挂载 |
| database credential | 禁止注入 |
| egress credentials | 仅 lease 验签公钥、短期 token-broker capability |

**实现位置**：[`deploy/daemon/Dockerfile.mcp-egress-proxy`](../../../deploy/daemon/Dockerfile.mcp-egress-proxy) 与 [`deploy/daemon/docker-compose.mcp-egress.yml`](../../../deploy/daemon/docker-compose.mcp-egress.yml)。
