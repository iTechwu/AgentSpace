# 实施计划、Compose 验证与发布门禁

> 状态：Proposed
>
> 原则：先完成旁路不可达的可证明网络边界，再把 Runtime MCP 调用声明为可用。

## 1. 代码边界

```text
apps/mcp-egress-proxy/
  src/server.ts                 proxy HTTP server
  src/lease-verifier.ts         签名、JTI、TTL、撤销检查
  src/policy-cache.ts           仅内存 policy snapshot
  src/upstream-transport.ts     DNS/TLS pinning + Streamable HTTP bridge
  src/oauth-injector.ts         后续 OAuth token broker client
  src/audit.ts                  脱敏结构化审计

packages/domain/
  src/daemon-api.ts             McpEgressLease/Policy 契约

packages/daemon/
  src/mcp/egress-client.ts      RuntimeMcpClient 的 proxy transport

packages/services/
  src/mcp-center/egress.ts      policy 编译、lease 签发、撤销

deploy/daemon/
  Dockerfile.mcp-egress-proxy
  docker-compose.mcp-egress.yml
  reconcile-runtime-egress.sh   由 managed node 调用的幂等 DOCKER-USER 规则
```

`apps/mcp-egress-proxy` 只依赖协议类型、签名验证和 HTTP/TLS 库，不能导入 `@dofe-agent/db`、工作区服务层或浏览器代码。它通过签名 lease 和撤销/policy 同步接口工作，不直接连接 PostgreSQL。

## 2. 分期

### Phase 0：契约与测试骨架

1. 在 `packages/domain` 定义 policy revision、lease claims、稳定 error code；
2. 编写 canonical policy 与 lease signature golden tests；
3. 在 Compose 中搭建 fake MCP upstream、fake DNS/redirect/private-IP 目标；
4. 不接生产调用，不修改 Runtime 网络。

### Phase 1：Proxy observe

1. 实现 proxy session transport、DNS/TLS 校验、大小/超时限制；
2. daemon 在影子路径生成 lease/policy，记录“若强制是否允许”；
3. proxy 只承载 canary MCP connection；
4. 建立 request/reject/latency/audit 指标。

### Phase 2：Docker Compose enforce

1. 新增 `mcp-egress-proxy` Compose service 和独立 image；
2. managed node 在启动 Runtime 前 reconcile `DOCKER-USER` 默认拒绝规则；
3. canary Runtime 的 MCP 强制经 proxy，proxy 故障直接拒绝；
4. 通过全部容器、IPv4/IPv6、public proxy、raw IP 负向探针；
5. 按 node 灰度到所有 Runtime。

### Phase 3：OAuth 与 managed stdio 复用

1. OAuth token broker 向 proxy 提供一次性注入材料；
2. `managed_stdio` worker 的对外访问同样使用 proxy lease；
3. 完成 revoke/yank/disable 到 proxy deny cache 的时效验证。

## 3. Compose 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 无 lease 请求 proxy | 401/403，绝不建立外连 |
| 有效 lease 请求已批准 endpoint | 成功，TLS/SNI 正确 |
| 有效 lease 请求其他 connection host | 拒绝 |
| Provider 直连已批准 MCP host | 宿主机防火墙拒绝 |
| Provider 直连 raw IP/IPv6/public proxy | 宿主机防火墙拒绝 |
| DNS 回答含私网/metadata | proxy 拒绝 |
| 上游 redirect 或非 443 端口 | proxy 拒绝 |
| lease 过期/JTI 重放 | proxy 拒绝 |
| connection disable/release yank | 新调用在撤销 SLA 内拒绝 |
| proxy 退出 | MCP 调用失败，不回退直连 |
| Provider 读取 daemon `/proc`/fd/mem | 拒绝，作为 enforce 前置 |
| `docker inspect` proxy | 不含 secret、DB URL、Docker socket、host port |
| 日志扫描 | 无 Authorization、lease 原文、URL query、MCP payload |

当前仓库已有 `verify-managed-runtime-egress` 和受限 egress network 检查。实现时应扩展这些 gate，而不是创建脱离现有 evidence 目录的第二套验证脚本。

## 4. 运行与回滚

| 事件 | 正确处置 |
| --- | --- |
| proxy 健康检查失败 | 将相关 MCP connection 置 degraded，停止新 task lease |
| policy/lease 版本不兼容 | 拒绝调用，先升级 proxy 或控制面，不直连 |
| 防火墙 reconciler 失败 | Runtime 不启动或不标记 MCP eligible |
| proxy 新版本异常 | 将 Runtime MCP 功能关闭/降级，保留网络默认拒绝 |
| 控制面撤销 feed 不可用 | 不签发新 lease，现有 lease 自然到期 |

安全回滚绝不等于恢复直连。代理或策略出问题时，安全的降级是停用 MCP 调用。

## 5. 发布门禁

- [ ] proxy 镜像独立、固定 digest、无 Docker socket/host network/数据库凭据
- [ ] Runtime 网络不是 Docker `bridge`/`default`/`host`，并有 `dofe.managed-egress=restricted` 证明标签
- [ ] `DOCKER-USER` 规则在 Runtime 启动前完成并可幂等恢复
- [ ] 已通过所有 Compose 验收矩阵中的正向与负向探针
- [ ] daemon/Provider 进程 lease 隔离已验证
- [ ] connection disable、release yank、OAuth revoke 可在设定 SLA 内阻断新调用
- [ ] proxy 失败没有直连 fallback
- [ ] 现有 MCP gateway task/session/tool 审计仍完整，新增 proxy 审计不包含 payload
- [ ] Docker Compose 未创建 PostgreSQL、Redis、RabbitMQ 服务、镜像、初始化 job 或 volume

测试执行遵守仓库并发限制：优先运行最小相关测试；API 单文件 Jest 使用 `--runInBand`；全量 pnpm/Turbo/Jest 执行必须限制并发/worker 为 2。
