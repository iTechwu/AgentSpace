## 1. 代码边界

```text
apps/mcp-egress-proxy/
  src/server.ts                 proxy HTTP server
  src/lease-verifier.ts         签名、JTI、TTL、撤销检查
  src/policy-cache.ts           内存 snapshot + 不含认证材料的单副本持久状态
  src/upstream-transport.ts     DNS/TLS pinning + Streamable HTTP bridge
  src/oauth-injector.ts         后续 OAuth token broker client（Phase 3 占位）
  src/audit.ts                  脱敏结构化审计

packages/domain/
  src/daemon-api.ts             McpEgressLease/Policy 契约

packages/daemon/
  src/mcp/egress-client.ts      RuntimeMcpClient 的 proxy transport（policy 推送 + lease 头）
  src/mcp/client.ts             根据 lease/policy 选择直连或 proxy transport
  src/mcp/gateway.ts            将 task session 的 lease/policy 传入 ResolvedMcpConnection
  src/mcp/verify-executor.ts    将 operation claim 的 lease/policy 传入 ResolvedMcpConnection

packages/services/
  src/mcp-center/egress.ts      policy digest、lease 签名/验证、审计哈希

deploy/daemon/
  Dockerfile.mcp-egress-proxy
  docker-compose.mcp-egress.yml
  reconcile-runtime-egress.sh   由 managed node 调用的幂等 DOCKER-USER 规则
```

**已实施文件映射**：

- `apps/mcp-egress-proxy/src/server.ts` → proxy HTTP server（含 `/healthz`、lease 校验、`/v1/admin/policies` policy 推送端点）。
- `apps/mcp-egress-proxy/src/lease-verifier.ts` → 签名、TTL、policy 一致性检查。
- `apps/mcp-egress-proxy/src/policy-cache.ts` → 内存 policy snapshot cache；policy/revoke 状态原子持久化，`staticHeaders` 不落盘。
- `apps/mcp-egress-proxy/src/upstream-transport.ts` → DNS 解析、地址校验、TLS pinning 转发。
- `apps/mcp-egress-proxy/src/audit.ts` → 脱敏审计记录。
- `apps/mcp-egress-proxy/src/oauth-injector.ts` → Phase 3 OAuth 占位。
- `packages/domain/src/daemon-api.ts` → `McpEgressPolicyRevision`、`McpEgressLeaseClaims`、`McpEgressPolicySnapshot`、`McpEgressErrorCode`，以及 `ResolvedMcpConnection` 上的 `egressProxyLease` / `egressProxyPolicySnapshot`。
- `packages/services/src/mcp-center/egress.ts` → lease 签名/验证与 policy digest 工具。
- `packages/services/src/mcp-center/connections.ts` → 为 connection operation 与 task session 生成 lease + policy snapshot。
- `packages/daemon/src/mcp/egress-client.ts` → policy 推送与 lease 头构造。
- `packages/daemon/src/mcp/client.ts` → 根据 lease 选择 proxy URL，无 lease 仍直连，有 lease 时 proxy 故障不回退。
- `packages/daemon/src/mcp/gateway.ts` / `verify-executor.ts` → 将 task/operation 的 lease/policy 注入 `ResolvedMcpConnection`。
- `deploy/daemon/Dockerfile.mcp-egress-proxy` 与 `docker-compose.mcp-egress.yml` → 独立镜像与双网 service。
- `deploy/daemon/reconcile-runtime-egress.sh` → 幂等 `DOCKER-USER` 规则脚本。
- `deploy/daemon/managed-node-entrypoint.sh` → 在启动 Runtime 前调用 `reconcile-runtime-egress.sh`。

`apps/mcp-egress-proxy` 只依赖协议类型、签名验证和 HTTP/TLS 库，不能导入 `@dofe-agent/db`、工作区服务层或浏览器代码。它通过签名 lease 和撤销/policy 同步接口工作，不直接连接 PostgreSQL。

## 3. Compose 验收矩阵

| 场景 | 预期 | 状态 |
| --- | --- | --- |
| 无 lease 请求 proxy | 401/403，绝不建立外连 | ✅ `apps/mcp-egress-proxy/src/server.test.ts` |
| 有效 lease 请求已批准 endpoint | 成功，TLS/SNI 正确 | ⏳ 需 fake upstream / 测试环境 |
| 有效 lease 请求其他 connection host | 拒绝 | ✅ `upstream-transport.ts` 路径前缀校验 |
| Provider 直连已批准 MCP host | 宿主机防火墙拒绝 | ⏳ firewall 契约测试已通过，仍需真实 Provider 容器探针 |
| Provider 直连 raw IP/IPv6/public proxy | 宿主机防火墙拒绝 | ⏳ `enable_ipv6: false` 与规则已配置，仍需 raw IP/IPv6/public proxy 真实探针 |
| DNS 回答含私网/metadata | proxy 拒绝 | ✅ 复用 `validateMcpResolvedAddresses` |
| 上游 redirect 或非 443 端口 | proxy 拒绝 | ✅ `redirect: "error"` 与 policy `allowedPorts: [443]` |
| lease 过期/JTI 重放 | proxy 拒绝 | ✅ JTI 绑定 proxy session，单副本重启状态持久化 |
| release digest / policy digest 不一致 | proxy 拒绝 | ✅ lease 同时绑定不可变 catalog release digest 与 canonical policy digest |
| 超过 connection QPS | 429，绝不建立额外外连 | ✅ proxy 固定窗口按 connection 限流 |
| 私有 CA snapshot 被篡改或持久化 | 拒绝 / 不落盘 | ✅ policy 绑定 CA digest，snapshot PEM 仅在内存中使用 |
| connection disable/release yank | 新调用在撤销 SLA 内拒绝 | ⏳ deny cache 推送待 Phase 2/3 |
| proxy 退出 | MCP 调用失败，不回退直连 | ✅ `packages/daemon/src/mcp/client.ts` 有 lease 时无直连 fallback |
| Provider 读取 daemon `/proc`/fd/mem | 拒绝，作为 enforce 前置 | ⏳ 依赖 Phase 2 进程隔离验证 |
| `docker inspect` proxy | 不含 DB URL、Docker socket、host port；生产验签不持有签名私钥 | ✅ Compose 只挂载 Ed25519 验签公钥；HMAC 仅显式 migration 开关可用 |
| 日志扫描 | 无 Authorization、lease 原文、URL query、MCP payload | ✅ `audit.ts` 仅记录 hash 与元数据 |

当前仓库已有 `verify-managed-runtime-egress` 和受限 egress network 检查。实现时应扩展这些 gate，而不是创建脱离现有 evidence 目录的第二套验证脚本。

## 4. 运行与回滚

| 事件 | 正确处置 |
| --- | --- |
| proxy 健康检查失败 | 将相关 MCP connection 置 degraded，停止新 task lease |
| policy/lease 版本不兼容 | 拒绝调用，先升级 proxy 或控制面，不直连 |
| 防火墙 reconciler 失败 | Runtime 不启动或不标记 MCP eligible |
| proxy 新版本异常 | 将 Runtime MCP 功能关闭/降级，保留网络默认拒绝 |
| 控制面撤销 feed 不可用 | 不签发新 lease，现有 lease 自然到期 |

安全回滚绝不等于恢复直连。代理或策略出问题时，安全的降级是停用 MCP 调用。
