# 03. 测试安排

## 1. 周期与目标

计划周期：`2026-08-03（周一）` 至 `2026-08-07（周五）`。

本轮采用“当天冒烟、分域全量、次日回归、周五准出”的节奏。若首日环境或 SSO 不可用，计划整体顺延，不能通过跳过 P0 来追回进度。

## 4. 人员与职责

最小建议配置为 1 名 QA 主责、1 名前端、1 名后端/服务、1 名环境/集成支持；同一人可兼任，但职责不能缺失。

| 角色 | 主要职责 |
| --- | --- |
| QA 主责 | 维护环境/账号基线，执行用例，保管证据，缺陷分级，主持准出 |
| 前端负责人 | 处理页面、路由、响应式、可访问性和浏览器兼容问题 |
| 后端/服务负责人 | 处理授权、状态机、数据一致性、幂等、审计和恢复问题 |
| 环境/集成负责人 | 保证 SSO、PostgreSQL、模型、Daemon/Runtime、飞书和 MCP 测试依赖可用 |
| 产品/业务验收人 | 确认预期、风险接受和最终准出，不替代技术测试 |

## 5. 自动化与人工分配

| 层级 | 频率 | 范围 |
| --- | --- | --- |
| 静态检查 | 每次候选构建 | typecheck、test typecheck、lint |
| 单元/组件/API | 每日，修复后执行相关文件 | Web Vitest、Node tests，最大并发 2 |
| 浏览器 E2E | 每日冒烟，周五全量 | 现有 Playwright + 本文 P0 旅程 |
| 人工功能 | 本轮至少一次 | 所有 P0/P1 用户行为和真实集成反馈 |
| 兼容/可访问性 | 周五 | 移动端、Edge/Safari、键盘、读屏 |
| 恢复演练 | 发布候选版本 | 数据恢复、Runtime/任务恢复、外部依赖中断 |

现有浏览器自动化主要覆盖路由渲染、消息发送延迟、移动端下钻、模块切换与草稿恢复。以下高风险主链路应优先补为自动化：

1. SSO 登录后的工作区与角色同步。
2. 频道消息 -> 任务 -> Agent -> 产物回写。
3. 审批阻断与批准后继续执行。
4. Skill/MCP 安装配置后在任务中调用。
5. 跨工作区和访客数据隔离。
6. 权限撤销后的 UI/API/附件访问同时失效。

## 6. 准入标准

开始全量测试前必须满足：

- 候选 commit 固定，可追溯，已部署到非生产测试环境。
- SSO、独立测试数据库和 `/api/health` 可用。
- 测试账号可登录，至少一个工作区可访问，真实角色已记录。
- 至少一个在线 Runtime 和一个可用模型；异常状态数据可预置。
- 飞书/MCP 专项若纳入当日范围，其测试凭据和测试目标已准备。
- Web build、typecheck、lint 和非数据库冒烟没有应用级失败。
- 已确认备份或测试数据可清理，不会影响其他测试人员。

任一 P0 依赖缺失时，对应域只能记为“阻塞”，不能出具通过结论。

## 7. 暂停与恢复标准

出现以下情况立即暂停相关写操作：

- 发现 S0：越权、敏感信息泄露、不可逆数据破坏或跨工作区污染。
- 测试数据库疑似指向生产或共享关键数据。
- 同一 P0 操作连续产生重复任务、重复扣费或无法清理的外部资源。
- SSO/Runtime/飞书异常导致结果无法区分产品缺陷与环境缺陷。

恢复条件：根因或隔离措施明确，环境健康检查通过，已确认测试数据一致性，并重新执行当日冒烟。

## 8. 准出标准

全部满足才可建议发布：

- P0 执行率 `100%`，通过率 `100%`。
- 所有适用 P1 用例 `100%` 有结果；无法执行的用例必须记为阻塞并在准出评审中逐项说明。
- S0、S1 未关闭数量为 `0`。
- S2 均有修复版本或经产品、技术负责人书面接受残余风险。
- 修复项完成“原用例 + 同域 P0 + 跨模块主链路”回归。
- Chrome 桌面和 `390 x 844` 移动端 P0 全通过。
- 无越权、跨工作区数据泄露、Secret 泄露、重复扣费或不可恢复的数据丢失。
- 测试数据和外部连接已清理，测试账号未保留临时高权限。
- 最终报告记录环境、commit、执行统计、缺陷、阻塞和残余风险。

## 11. 本工作站限制

本次安排不包含 Jenkins 部署或任务触发。若目标是指定测试环境发布，必须由用户另行提供非 Jenkins 工作流，或在指定 CI/测试环境按其授权流程执行。本地工作以文档、实现、验证和明确要求的提交为止。
