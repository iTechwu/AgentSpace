# AgentSpace MCP 产品优化方案

> 状态：Proposed（2026-08-26）
>
> 设计原则来自 product-designer skill：先用仓库证据定义问题，再补充用户研究；为完整 happy path 和一个错误态设计中保真原型；以任务完成率、耗时、错误率和 SUS 作为发布指标。

## 1. 用户问题与证据

### 1.1 已观察到的三类数据点

1. 任务执行代码只有在 `bundle.metadata.mcpConnections.status === "available"` 时 claim session，并在 claim 为空时直接失败，说明 MCP 是任务级硬依赖，用户需要知道“为什么没有工具”。
2. Claude/Codex 的 MCP 配置由 AgentRouter adapter 注入 loopback gateway，且 Codex 默认关闭实验开关，说明不同 harness 的可用性和行为不一致。
3. MCP 连接状态包含 `pending_configuration、verifying、ready、degraded、failed、disabled`，但用户要在多个运行时/市场页面之间理解这些状态，说明状态模型需要统一呈现和可行动建议。

这些是产品与代码证据，不替代真实访谈。上线前必须用 5-8 名管理员、操作员和高频任务用户验证理解度。

### 1.2 问题陈述

“当用户为员工启用 MCP 时，他无法快速判断连接是否真正可用、任务失败属于权限/网络/工具还是 harness，也无法在不暴露 secret 的前提下完成修复。MCP 独立化后，产品应把复杂网络实现隐藏在清晰的连接状态、能力预览和恢复操作后面。”

## 2. 产品目标与成功指标

| 目标 | 指标 | 目标值 |
| --- | --- | ---: |
| 快速接入首个 MCP | 从市场选择到完成验证的中位时长 | < 5 分钟 |
| 清楚判断可用性 | 首次验证成功率 | ≥ 90% |
| 降低任务失败排查成本 | MCP 相关失败中可行动错误占比 | ≥ 95% |
| 独立网络稳定性 | Connector 调用成功率 | ≥ 99%（排除上游 5xx） |
| 不影响任务执行 | 无 MCP 任务被 Connector 阻塞比例 | 0 |
| 用户可用性 | SUS | ≥ 75；关键任务完成率 ≥ 85% |

## 3. 关键 personas 与用户旅程

| Persona | 目标 | 主要痛点 | 机会 |
| --- | --- | --- | --- |
| Workspace 管理员 | 安装、审批和撤销 MCP | 不知道网络/权限边界 | 连接向导、风险分级、审计 |
| Runtime 操作员 | 保障 Connector 和 runtime 健康 | gateway/harness/MCP 故障混杂 | 独立健康面板、拓扑和 runbook |
| 员工/任务发起人 | 用工具完成任务 | 工具消失或调用超时 | 任务前能力预览、结构化错误和重试 |
| MCP 发布者 | 发布新工具 | 每个 harness 都要适配 | catalog schema、版本和兼容矩阵 |

### 用户旅程地图

| 阶段 | 行为/触点 | 情绪 | 痛点 | 产品机会 |
| --- | --- | --- | --- | --- |
| 发现 | 市场搜索 MCP | 好奇 | 不知道风险与网络要求 | 显示 transport、数据域、所需出口和风险 |
| 配置 | 填 endpoint/参数/secret | 紧张 | secret、域名和路径规则复杂 | 分步表单、字段级校验、secret 永不回显 |
| 验证 | 点击“验证连接” | 期待 | 失败原因技术化 | 展示阶段进度：连接→握手→发现工具→策略 |
| 授权 | 选择工具并绑定 runtime/员工 | 谨慎 | 不清楚谁能调用 | approved tools、风险和影响范围清单 |
| 执行 | 在任务中使用工具 | 专注 | 工具延迟或暂时不可用 | 任务能力徽标、调用时间线、可重试提示 |
| 恢复 | 处理 degraded/failed | 焦虑 | 不知道修 endpoint 还是权限 | “重新验证/轮换 secret/切换 runtime/查看日志”四类动作 |
| 留存 | 查看审计与用量 | 安心 | 难以对账 | 连接级调用量、失败率、最近变更和 owner |

## 4. 信息架构

```text
Workspace
+-- MCP 中心
|   +-- 市场与目录
|   +-- 我的连接
|   |   +-- 连接概览
|   |   +-- 工具与授权
|   |   +-- 网络与策略
|   |   +-- 健康与活动
|   +-- 验证任务
|   +-- 审计与用量
+-- Runtimes
    +-- Runtime 概览
    +-- 工具能力（聚合 Skill / MCP / Browser）
    +-- 失败诊断
```

MCP 页面不出现“gateway”作为用户概念；运维详情可显示 Connector 实例、network policy revision 和 trace id。

## 5. 产品功能规格

### 5.1 市场卡片

- 显示名称、版本、transport、风险等级、数据域、所需 runtime capability、网络模式（直连/受控代理/无网络）。
- 显示“支持的 harness”改为“支持的 ToolSurface contract”；harness 兼容性由 runtime 能力计算，不让用户选择 gateway 开关。
- 版本升级显示变更摘要、工具清单 diff 和重新验证要求。

### 5.2 连接向导

1. 选择目录条目和目标 runtime。
2. 配置非 secret 参数，实时校验 host/path/port 与 catalog schema。
3. 输入 secret；支持粘贴后只显示掩码和字段状态。
4. 选择 approved tools，按风险分组并默认最小权限。
5. 选择网络策略：`approved_hosts_only`（默认）、`egress_proxy_required`、`private_ca`。
6. 验证连接，展示阶段进度和最终工具 fingerprint。
7. 成功后显示“可用于哪些员工/任务”，提供绑定入口。

错误态必须保留用户输入（secret 除外），给出错误码、下一步和 trace id；禁止展示原始 URL、Authorization header 或 provider stderr。

### 5.3 任务体验

- 任务开始前在能力栏显示“3 个 MCP 工具已授权，Connector 在线”。
- 工具调用时间线显示 tool name、状态、耗时、重试次数和安全摘要；不显示原始参数/输出中的 secret。
- `degraded` 时只对依赖该工具的步骤提示“暂时不可用”，不把整个 harness 标记为崩溃。
- 支持“重试本次调用”“重新运行任务”“切换已授权 runtime”三种动作；重试遵循 eventId 幂等。

### 5.4 运维面板

- Connector 实例健康：进程、网络、策略版本、连接池、P50/P95 延迟、错误分布。
- 连接健康：最近验证、连续失败次数、失败阶段、下次检查、最近配置变更。
- 拓扑视图：Control Plane → Runtime → Connector → Egress/目标 host；只展示逻辑节点，不暴露内部 IP/secret。

## 6. 设计与可访问性要求

- 遵循现有 AgentSpace 设计系统；状态使用图标 + 文本 +颜色，不能只靠颜色区分。
- 关键按钮提供图标（验证、重试、轮换、撤销），危险操作要求二次确认和影响范围。
- 所有表单支持键盘导航、可见 focus、`aria-describedby` 错误关联；正文/按钮满足 WCAG AA 4.5:1 对比度。
- 长 endpoint、工具名和错误消息使用换行/折叠，不能溢出容器；secret 输入支持密码管理器粘贴。

## 7. 原型与研究计划

### 原型范围

制作中保真原型，覆盖：市场卡片 → 连接向导 happy path → 验证失败（网络拒绝）→ 工具授权 → 任务调用时间线 → 连接 degraded 恢复。

### 可用性测试（6 人）

| 任务 | 完成目标 | 时间目标 | 观察点 |
| --- | ---: | ---: | --- |
| 安装并验证一个 HTTP MCP | 90% | < 5 min | 是否理解网络策略与验证阶段 |
| 撤销一个高风险工具 | 90% | < 90 s | 是否能找到授权入口和影响范围 |
| 从失败状态恢复 | 80% | < 3 min | 是否选择正确动作而非重建 runtime |
| 在任务中识别 MCP 调用失败 | 85% | < 60 s | 是否能区分工具失败与 harness 失败 |

记录 task completion、time on task、错误次数、误触危险操作和 SUS。严重度 P0/P1 的问题必须在灰度前关闭；P2 问题进入后续迭代。

## 8. 发布与沟通

- 发布说明使用“独立 MCP Connector / 更清晰的连接健康 / 不改变任务入口”三句话，不向用户承诺绕过安全策略。
- 迁移期间在连接详情显示“已迁移到 Connector”标签；legacy gateway 仅出现在运维诊断中。
- 连接升级、policy 变更和 Connector 切换写入审计，并提供 30 天可检索历史。
