# AgentSpace MCP 独立化实施方案

> 状态：Proposed（2026-08-26）
>
> 实施约束：每个阶段都要可回滚；不复制任务队列；不在本机使用 Jenkins；部署变更不得引入 PostgreSQL、Redis 或 RabbitMQ 服务。

## 1. 分阶段路线图

| 阶段 | 周期 | 目标 | 退出条件 |
| --- | --- | --- | --- |
| W0 基线 | 1 周 | 固化现状契约、指标和依赖图 | 旧 gateway 行为有 contract tests，指标基线完成 |
| W1 契约 | 1-2 周 | ToolSurface/Connector API v1 | 类型、错误码、认证和幂等契约评审通过 |
| W2 Connector | 2-3 周 | 独立进程、网络和 transport | HTTP/SSE/stdio、health、lease、审计测试通过 |
| W3 Runtime 接线 | 1-2 周 | task-runner 通过 Connector 开会话 | 无 MCP 任务零额外 hop；取消/超时最终收敛 |
| W4 AgentRouter 解耦 | 1-2 周 | 移除 MCP 专属 request/adapters 分支 | AgentRouter 无 MCP import；Claude/Codex 回归通过 |
| W5 产品与灰度 | 2 周 | 市场、向导、健康、任务体验 | 6 人测试达标，5% workspace 灰度稳定 7 天 |
| W6 切换清理 | 1 周 | Connector 默认、gateway 只读回滚 | 两个发布周期无回滚需求，删除 legacy 路径 |

## 2. 代码与配置改动清单

### W1：公共契约

| 区域 | 改动 |
| --- | --- |
| `packages/domain/src` | 新增 `ToolSurfaceProvider`、`ToolDescriptor`、`ToolCallResult`、`ConnectorErrorCode`、contract version |
| `packages/daemon/src` | 新增 `tool-surface/client.ts`、`tool-surface/types.ts`，只暴露通用接口 |
| `packages/services/src/mcp-center` | 将 task grant/lease/policy 输出改为 Connector session input；保留旧 API 兼容映射 |
| `packages/db/src` | 增加 Connector instance、session、health transition 的 schema/读写函数；调用审计复用 eventId 去重 |

### W2：独立 Connector

- 新建 `apps/mcp-connector`（或独立 package + bin），禁止导入 AgentRouter、provider adapter 和 task queue 实现。
- 从 `packages/daemon/src/mcp/client.ts` 提取 MCP SDK transport、endpoint guard、响应限制和错误分类；迁移后 daemon 只保留 client stub。
- 将 `packages/daemon/src/mcp/egress-client.ts` 改为 Connector 内模块；lease 验证公钥只读挂载，admin token 不进入 provider 环境。
- 引入独立 Docker network（例如 `dofe-mcp-egress`）与最小权限容器：read-only rootfs、drop all capabilities、非 root、无 DB 端口。
- health endpoint 和 metrics 只输出计数、延迟、状态码、policy revision hash。

### W3：Runtime 接线

- `packages/daemon/src/remote-daemon/task-execution.ts`：claim 后调用 `connector.openSession`，创建通用 ToolSurface context；任务 finally 中关闭 session。
- `packages/daemon/src/remote-daemon/mcp.ts`：保留 managed stdio launch 装配，改为生成 Connector launch descriptor；移除共享 gateway pool。
- 新增 Connector 不可用、会话过期、policy revoked 的结构化 runtime diagnostic；无 MCP 任务不初始化 Connector client。
- 远程 daemon 配置新增 `MCP_CONNECTOR_URL`/Unix socket、`MCP_CONNECTOR_CA_FILE`、`MCP_CONNECTOR_TIMEOUT_MS`；旧 `MCP_EGRESS_PROXY_*` 只由 Connector 读取。

### W4：AgentRouter 解耦

- `packages/daemon/src/agent-router/types.ts`：删除 `mcpGatewayUrl`、`codexMcpInjectionEnabled`；新增 `toolSurface?: ToolSurfaceLaunchContext`。
- 删除 `packages/daemon/src/agent-router/mcp-gateway.ts` 及 Claude/Codex 的 MCP 专属注入测试；将 provider-native 配置生成移到 ToolSurface adapter。
- `runProviderTask` 只接收通用工具上下文和权限集合；AgentRouter 不知道 connectionId、catalog、lease 或 endpoint。
- 对 OpenCode/OpenClaw/Hermes 等新增 harness，只需声明支持的 ToolSurface contract，不添加 MCP 分支。

### W5：Web 产品

- `apps/web/features/market/*`：市场卡片、连接向导、工具授权、网络策略和验证进度。
- `apps/web/features/runtimes/*`：工具能力聚合、Connector 健康、任务前能力预览。
- `apps/web/app/api/daemon/*`：Connector session/open/call/close、health transition、audit 查询路由。
- 统一错误码映射：`network_denied、dns_failed、tls_failed、auth_failed、tool_not_approved、connector_unavailable、upstream_timeout`。

## 3. 数据迁移

1. 为现有 `RuntimeMcpConnection` 增加 `executionMode`（`legacy_gateway | connector_v1`）和 `connectorInstanceId`，默认 legacy。
2. 将现有 egress policy revision、approved tools、discovery fingerprint 原样迁移；不重新保存 secret 明文。
3. 为每个运行时注册 Connector instance，写入版本、network name、public key fingerprint、能力和最后心跳。
4. 旧 grant 在 TTL 内继续可由 legacy gateway 消费；Connector grant 增加 `contractVersion=1`，两者不可混用。
5. 双写阶段将调用事件同时送入旧审计 outbox 与 Connector ingest，服务端按 eventId 去重；稳定后关闭旧写路径。

## 4. 测试矩阵

| 层级 | 必测内容 | 证据 |
| --- | --- | --- |
| 单元 | endpoint/DNS/TLS guard、lease、policy、schema、redaction、错误映射 | Connector tests |
| 协议 | initialize、listTools、callTool、超时、重试、非法帧、响应上限 | fake MCP server |
| 安全 | secret 不进 provider/env/log；跨 task/runtime session 拒绝；撤销即时生效 | security tests |
| Runtime | open/call/close、取消、超时、daemon 重启、无 MCP 任务路径 | daemon integration |
| AgentRouter | 无 MCP 字段仍能运行所有 harness；ToolSurface opaque config 不泄露 | adapter regression |
| Web | 向导 happy path、网络拒绝、secret rotation、degraded 恢复、键盘可用性 | Vitest + Playwright |
| E2E | 独立 Connector network 到真实测试 MCP，模型任务调用并完成审计 | staging canary |

遵循仓库测试资源限制：单文件 Jest 使用 `--runInBand`，全量测试必须使用 `--maxWorkers=2`；不执行无约束 `pnpm test`。

## 5. 验收矩阵与发布门禁

| 编号 | 验收项 | 必须条件 |
| --- | --- | --- |
| A1 | 独立联网 | Connector 可在独立 network 访问获批 MCP；provider/runtime 无直连外网 |
| A2 | 解耦 | AgentRouter 不导入 MCP 模块，不含 MCP URL/secret/lease 字段 |
| A3 | 授权 | task、runtime、connection、tool、policy、lease 任一不匹配即拒绝 |
| A4 | 生命周期 | open/call/close 在完成、失败、取消、超时、进程退出后最终收敛 |
| A5 | 审计 | 每次调用有唯一 eventId、状态、延迟和安全摘要；重试不重复记账 |
| A6 | 可观测性 | 能区分 Connector、网络、MCP 协议、工具权限和 harness 错误 |
| A7 | 兼容性 | legacy gateway 与 Connector contract tests 结果一致；可按 workspace 回滚 |
| A8 | 产品体验 | 连接验证成功率 ≥90%，关键任务完成率 ≥85%，SUS ≥75 |
| A9 | 性能 | Connector P95 调用额外开销 < 100ms（不含上游耗时），资源上限生效 |
| A10 | 发布安全 | 真实测试 MCP E2E、签名镜像/配置、回滚演练均有证据；未满足则保持灰度 |

## 6. 运行手册与回滚

### 日常运维

- 先看 Connector instance health，再看 connection health，最后看具体 tool call trace；不要先重启 harness。
- 连续失败达到阈值时自动标记 connection `degraded`，暂停新 session，保留现有审计和恢复入口。
- policy/secret/目录版本变更触发重新验证；Connector 只接受新 revision，不修改旧审计。

### 回滚

1. 将 workspace/runtime 的 `executionMode` 切回 `legacy_gateway`，停止新 Connector session。
2. 等待 Connector session 按 TTL 关闭；正在执行的调用按幂等策略完成或失败收口。
3. 保留 Connector 日志摘要、health transition 和审计，不删除连接或 secret envelope。
4. 根因修复后先在单 workspace 重放 contract/E2E，再恢复灰度。

## 7. 风险与决策跟踪

| 风险 | 影响 | 缓解 | 责任 |
| --- | --- | --- | --- |
| Connector 网络策略配置错误 | 大面积 MCP 不可用 | deny-all 默认、配置 lint、canary host | MCP team |
| 跨进程认证失效 | 工具调用被拒或越权 | Unix peer/mTLS、短 TTL、contract tests | Security |
| provider 对 opaque config 支持不一致 | 部分 harness 无工具 | ToolSurface capability matrix、按 harness 灰度 | AgentRouter |
| 双写审计重复 | 账单/审计污染 | eventId 唯一约束、服务端去重 | Services |
| legacy 清理过早 | 回滚困难 | 两个发布周期只读保留、A7 通过后删除 | Release |

## 8. 完成定义（Definition of Done）

- 架构 ADR、API schema、威胁模型和运行手册评审通过。
- Connector 在测试环境以独立网络运行，真实测试 MCP 调用成功并有审计证据。
- AgentRouter/Runtime/MCP 依赖图中不存在反向 import；新增 MCP demo 不改 AgentRouter 文件。
- 产品向导和错误恢复达到指标，迁移/回滚演练完成。
- 所有改动已本地验证并提交；部署仅在用户指定的非 Jenkins 流程下执行。
