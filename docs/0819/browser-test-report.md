## 发现的问题

### BUG-0819-001（高）Runtime 模型目录请求返回 500，界面卡在加载态

- 复现路径：`/runtimes` → “新增执行引擎” → “下一步”。
- 观察结果：浏览器网络收到两次 `POST /w/{workspace}/runtimes` 500；服务端错误为 `managed_runtime.sso_binding_required`。
- 用户影响：模型选择器一直显示“正在加载模型…”，没有说明工作区缺少 SSO Runtime 绑定，也没有可执行的恢复提示；控制台出现错误。
- 预期：将“未配置/不可用”作为可预期状态返回，页面停止加载并显示明确提示，不产生未处理的 500。
- 修复：`listProtocolFilteredRuntimeModelsAction` 将 SSO 绑定缺失和模型服务不可用转换为结构化不可用结果；`RuntimeModelPicker` 结束加载并显示可操作提示，未知请求异常显示可恢复告警。
- 状态：已修复并回归通过。

### BUG-0819-002（中）执行时间线默认状态文案被错误结算

- 复现路径：会话页加载包含 Runtime 执行轨迹的消息；调用 `buildExecutionTimeline` 时未传入任务运行状态。
- 观察结果：未传入 `taskRunning` 时，状态“正在准备执行环境”被改写为“执行环境已准备”，与实时轨迹语义和默认函数契约不一致；时间线单测有 2 项失败。
- 用户影响：部分未附带任务状态的审计/消息数据会提前显示为已完成，造成执行进度误导。
- 修复：仅在显式传入 `taskRunning: false` 时结算遗留状态；未传入或传入 `true` 时保留原始状态文案。生产调用点均显式传递任务运行状态。
- 状态：已修复并回归通过。

### BUG-0819-003（低）附件发送测试 mock 参数类型缺失

- 复现路径：运行 `tsconfig.test.json` 类型检查。
- 观察结果：附件发送测试中的 `vi.fn(async () => {})` 被推断为无参数 tuple，访问首个调用参数触发 `TS2532/TS2493`；运行时行为本身正常。
- 用户影响：测试类型检查无法通过，降低回归检查可信度。
- 修复：为测试 mock 补充与 `ConversationShell.onSubmit` 一致的输入类型。
- 状态：已修复并回归通过。

### BUG-0819-004（低）消息气泡重构后测试选择器失效

- 复现路径：运行会话消息气泡组件测试。
- 观察结果：消息元信息和操作栏已经迁移到 `.inbox-message-*` 结构，但 3 个断言仍查询旧类名，导致回归测试失败。
- 修复：按当前 DOM 契约更新元信息、执行回复时间和消息操作栏断言；同时确认新结构对应样式存在，功能按钮和可访问名称保持完整。
- 状态：已修复并回归通过。

### BUG-0819-005（低）引导关闭与悬浮提示回归存在竞态和歧义

- 复现路径：新建 E2E 工作区后立即关闭新手引导，或运行频道页“添加群成员”悬浮提示测试。
- 观察结果：引导可能在 helper 检查后才完成客户端挂载，导致后续操作受遮罩影响；频道头像和“添加群成员”可同时产生 `tooltip`，旧断言只按角色查找会命中多个元素。
- 用户影响：产品浏览器行为正确，但自动化回归会间歇失败，降低问题定位可信度。
- 修复：引导 helper 等待按钮短暂挂载后点击并确认隐藏；悬浮提示按可访问名称精确定位。
- 状态：已修复并回归通过。

### BUG-0819-006（中）E2E 场景滞后于保留模块和工作流状态契约

- 复现路径：执行工作流迁移及工作区导航 E2E。
- 观察结果：首次全量执行有 7 项失败，包括隐藏保留模块造成严格定位器重复、工作流状态组件 DOM 迁移、重试场景未进入终态、使用非规范错误码、无 SSO Runtime 绑定时仍期待模型菜单可用，以及向导/设置定位器未限定可见区域。
- 用户影响：回归套件无法准确区分业务失败与旧测试契约，可能掩盖真实回归。
- 修复：定位器限定可见元素或语义区域；工作流重试使用 `partially_succeeded`，不确定外部副作用使用规范错误码 `workflow_completion_effect_uncertain`；Runtime 场景验证无绑定时的明确不可用提示；模型菜单 Portal 行为保留在组件测试中；移动端导航在客户端水合窗口内幂等重试。
- 状态：已修复并回归通过。

### BUG-0819-007（中）首次访问新手引导缺少模态语义并允许键盘焦点逸出

- 复现路径：新建 E2E 工作区首次进入 `/im`，不使用自动关闭 helper，直接使用键盘操作引导层。
- 观察结果：修复前真实 Chrome 断言发现引导虽然具有 `role="dialog"`，但缺少 `aria-modal="true"`；Tab 可以离开引导层，关闭后焦点也不会稳定返回工作区。
- 用户影响：键盘用户可能误操作被遮罩的工作区控件，屏幕阅读器无法得知当前处于模态引导；关闭引导后继续操作的焦点上下文不明确。
- 修复：为引导层补充 `aria-modal` 和面板引用；实现 Tab/Shift+Tab 首尾循环、焦点意外落到面板外时拉回、Escape 关闭，并在关闭后恢复打开前的元素焦点；新增组件和真实浏览器回归断言。
- 状态：已修复并回归通过。

### BUG-0819-008（中）多个模态窗口的语义和焦点生命周期不完整

- 复现路径：从市场打开“添加 CLI”、从联系人页打开“添加真人联系人”，或从工作区按钮打开全局搜索后按 Escape。
- 观察结果：CLI 表单设置了 `aria-modal`，但缺少 `role="dialog"`；联系人窗口关闭按钮的可访问名称仅为“×”，且没有统一的 Tab/Escape/焦点恢复行为；全局搜索在关闭状态常驻挂载，导致 dialog hook 过早记录页面初始焦点，关闭后焦点落到 `body`。
- 用户影响：屏幕阅读器不能正确识别 CLI 模态窗口；键盘用户难以理解联系人关闭操作，并在关闭联系人或搜索窗口后失去操作上下文。
- 修复：CLI 和联系人窗口接入 `useDialogSurface`，补齐 dialog 语义、命名关闭按钮、初始焦点、Tab 循环、Escape 和焦点恢复；统一 hook 在首次 render 捕获原焦点，避免 `autoFocus` 抢占后记录错误元素；全局搜索的 surface 改为仅在打开时挂载。
- 状态：已修复并回归通过。
