# AI 员工团队编排：前端设计文档

## 1. 模块结构

```text
apps/web/
+-- app/w/[workspaceSlug]/automations/page.tsx       # 编排中心入口，保留兼容路由
+-- app/w/[workspaceSlug]/automations/new/page.tsx   # 创建向导
+-- app/w/[workspaceSlug]/automations/[workflowId]/page.tsx
+-- app/w/[workspaceSlug]/automations/runs/[runId]/page.tsx
+-- app/w/[workspaceSlug]/calendar/page.tsx          # 日历投影 + 深链入口
+-- app/w/[workspaceSlug]/task-board/page.tsx         # 根任务投影 + 深链入口
+-- features/workflows/
    +-- workflow-list-client.tsx
    +-- workflow-builder-client.tsx
    +-- workflow-canvas.tsx
    +-- workflow-node-palette.tsx
    +-- workflow-node-config-panel.tsx
    +-- workflow-preflight-panel.tsx
    +-- workflow-run-client.tsx
    +-- workflow-run-timeline.tsx
    +-- workflow-actions.ts
    +-- workflow-data.ts
    +-- workflow-types.ts
    +-- workflow-validation.ts
    +-- workflow-test-fixtures.ts
```

实现时优先沿用现有 `WorkspaceInitialModuleData`、`loadWorkspaceModuleDataWithMeta`、`refreshWorkspaceModule`、`runToastAction`、`useLanguage` 和 `WorkbenchPageHeader`，避免新增平行的数据加载和反馈范式。

## 2. 路由与数据加载

| 路由 | 加载数据 | 主要动作 |
| --- | --- | --- |
| `/automations` | Workflow 摘要、过滤项、统计 | 新建、启停、归档、复制 |
| `/automations/new` | 员工、频道、Runtime readiness、模板 | 保存草稿、预检、发布 |
| `/automations/:id` | 草稿/已发布版本、节点、Trigger、权限 | 编辑草稿、发布新版本、手动运行 |
| `/automations/runs/:runId` | Run 摘要、节点 projection、事件分页 | 暂停、取消、重试、接管 |
| `/calendar` | Trigger projection | 新建并跳到向导第 2 步 |
| `/task-board` | Root Task projection | 新建并跳到向导第 1 步、查看 Run |

首屏数据由 Server Component 提供；客户端只管理画布草稿、筛选、展开状态和乐观反馈。运行时间线通过现有事件/失效通知模式定时补偿或 SSE；断线时显示 `reconnecting`，不在本地猜测状态。

## 3. 前端类型与状态

核心客户端类型：

```ts
type WorkflowNodeDraft = {
  id: string;
  type: "employee_task" | "parallel_group" | "join" | "approval";
  position: { x: number; y: number };
  config: Record<string, unknown>;
};

type WorkflowDraftState = {
  workflowId?: string;
  versionId?: string;
  name: string;
  goal: string;
  trigger: TriggerDraft;
  nodes: WorkflowNodeDraft[];
  edges: Array<{ id: string; source: string; target: string }>;
  governance: GovernanceDraft;
  dirty: boolean;
  preflight?: PreflightResult;
};
```

使用 `useReducer` 管理草稿，所有 reducer 事件必须纯函数：`addNode`、`removeNode`、`connectNodes`、`updateNodeConfig`、`setTrigger`、`applyTemplate`、`markPreflight`。服务端返回的 canonical graph 作为唯一保存结果；客户端不负责生成版本号或运行状态。

## 4. Server Actions 与查询契约

沿用仓库已有 Server Action 认证方式，动作建议为：

- `createWorkflowDraftAction`
- `updateWorkflowDraftAction`
- `validateWorkflowAction`
- `publishWorkflowAction`
- `runWorkflowAction`
- `pauseWorkflowAction` / `cancelWorkflowAction`
- `retryWorkflowNodeAction`
- `resumeWorkflowFromNodeAction`
- `archiveWorkflowAction`

每个 Action 返回 `{ ok, data?, error?, invalidation? }`；错误带稳定 `code` 和可定位字段，客户端通过 `runToastAction` 显示摘要并在表单/节点旁显示细节。所有 Action 都重新读取 workspace context 和权限，不接受客户端的 owner 或员工授权作为可信结论。

## 5. 画布实现约束

推荐使用成熟 React 节点编辑器实现缩放、拖拽、连接和键盘导航；业务节点、边和布局数据映射到自己的 `WorkflowNodeDraft`，不直接把第三方库对象落库。自动布局只在用户点击“整理布局”时运行，不能在每次输入时改变用户位置。

画布必须提供：

- 列表视图替代方案；
- 节点搜索和员工 readiness 过滤；
- 连接线方向、错误边高亮和孤立节点提示；
- undo/redo、复制节点、删除确认；
- 保存草稿的离线防抖提示，但发布前必须在线预检。

## 6. 前端校验与错误映射

客户端做即时结构校验：名称、至少一个 AI Task Node、无环、无孤立节点、节点字段完整、并行组有 Join。服务端做最终校验：稳定员工 ID、访问权限、Runtime/Skill、频道、预算、版本冲突和策略。两者错误码统一，避免“前端可发布、后端才报未知错误”。

错误展示策略：

| 错误 | 展示位置 | 恢复动作 |
| --- | --- | --- |
| 图不完整 | 画布顶部 + 节点/边 | 定位第一个问题 |
| 员工未就绪 | 节点配置面板 | 打开员工详情或替换为已授权员工 |
| 版本过期 | 发布栏 | 载入最新草稿并显示差异 |
| 预算超限 | 治理步骤 | 降低并发/重试或申请额度 |
| 运行失败 | Run 节点卡片 | 重试节点/从此处继续/接管 |
| 事件断线 | 时间线顶部 | 重连并从 sequence 补偿 |

## 7. 测试策略

- `workflow-validation.test.ts`：DAG、Join、孤立节点、重复连接和字段校验。
- `workflow-builder-client.test.tsx`：创建、并行组、删除、预检阻塞、键盘操作。
- `workflow-run-client.test.tsx`：状态投影、断线、重试、取消和部分成功。
- Server Action 测试：权限隔离、版本冲突、错误码和失效事件。
- Playwright：完整创建流程、从日历进入、从看板进入、移动端窄屏和审批恢复。

测试遵守仓库资源限制：单文件 Jest/Vitest 使用受限 worker；不得运行无约束的根测试。
