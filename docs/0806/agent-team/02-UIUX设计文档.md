# AI 员工团队编排：UI/UX 设计文档

> 实施边界（2026-08-06）：五步向导、画布/列表、计划/运行中心、预检和运行控制已实现。模板 tab 当前为空状态；owner 筛选、节点超时、“从此处继续”和“转人工”属于二期。可用性研究和数据库驱动 E2E 尚未完成。

## 1. 信息架构

保留现有导航入口，调整语义而不强制用户学习新 URL：

```text
Workspace
+-- 协作
|   +-- 消息
|   +-- 任务看板
|   +-- 编排中心（原 Automations）
|   |   +-- 计划
|   |   +-- 运行
|   |   +-- 模板
|   +-- 日历 / 定时（进入同一创建向导）
+-- 资源
|   +-- AI 员工
|   +-- Skills / Knowledge / Tables
+-- 治理
    +-- 审批
    +-- 审计日志
    +-- Runtimes
```

任务看板和日历不复制编排数据：看板卡片显示根任务和下一节点，日历显示 Trigger；点击都打开同一个 Workflow/Run 详情。

## 2. 页面与入口

### 编排中心

顶部使用 `计划 / 运行 / 模板` tabs，提供搜索、状态筛选、下次运行时间和“新建编排”按钮。列表行显示名称、触发方式、拓扑摘要、下次运行、最近结果、owner、启用状态和风险提示；owner 筛选与模板 CRUD 为二期。

### 创建/编辑向导

1. **目标**：名称、业务目标、频道、owner、通知方式。
2. **触发**：手动、一次性/重复定时、受控事件；设置时区、去重和错过策略。
3. **流程**：画布编排员工节点、并行组、Join、审批；右侧编辑节点配置。
4. **治理**：权限预检、Runtime/Skill readiness、Run 并发上限、预计成本预算和重试；分支失败处理在 Join 节点配置。
5. **预览与发布**：显示版本号、影响范围、并发上限、预计成本和阻塞项。

任务看板入口默认跳到第 1 步，日历入口默认跳到第 2 步；两者共享草稿状态。

### 运行详情

左侧是可缩放但不依赖颜色的流程图，右侧是运行摘要和事件时间线。节点卡片显示状态、员工头像/名称、attempt、耗时、已有成本事件、产物数量和审批状态。首期上下文操作为“重试失败节点”“暂停”“恢复”“取消”；“从此处继续”和“转人工”在二期实现。

## 3. 编排器交互规范

```text
+---------------------------------------------------------------+
| 编排任务 · 周报发布       [草稿] [预检] [保存] [发布]          |
+------------------+-----------------------------+--------------+
| 节点库             | 画布                          | 配置面板       |
| AI 员工            | [研究员 A] ──┬── [主编 D]    | 节点名称       |
| 并行组             |              ├── [分析员 B]  | 员工 / 输入     |
| Join 汇聚          |              └── [审计员 C]  | 输出契约       |
| 人工审批           |                             | 预算 / 重试     |
+------------------+-----------------------------+--------------+
```

- 节点库使用图标 + 文字；拖入画布后必须选择员工，不能创建匿名 AI 节点。
- 连线只允许从上游到下游；形成环、孤立节点或多个结束路径时即时提示。
- 并行组通过“添加并行步骤”明确创建；Join 默认自动生成并可设置“全部成功/允许部分成功”。
- 配置面板使用渐进披露：常用字段优先，高级输入映射、Join 汇聚策略和预算折叠；首期不提供无运行时语义的全局失败策略。
- AI 员工节点使用逗号分隔的“输出字段”控件声明结构化字段；输入映射只能引用已声明的上游字段，发布前在对应节点显示错误。
- 画布操作同时提供键盘可达的“添加步骤”“连接到”“移动到并行组”命令，不把拖拽作为唯一方式。

## 4. 状态与反馈

| 状态 | 视觉 | 文案与操作 |
| --- | --- | --- |
| 草稿 | 中性徽标 | 未发布；可编辑 |
| 预检阻塞 | 警告徽标 + 行内错误 | 明确到员工、Runtime、Skill 或权限；不可发布 |
| 排队/运行中 | 进度点 + 时间 | 显示当前节点和最近事件，不显示无意义 token 流 |
| 等待审批 | 强调色徽标 | 显示审批人、风险和来源；可跳转审批中心 |
| 部分成功 | 警告徽标 | 列出成功和失败节点，支持重试失败节点 |
| 失败 | 错误徽标 | 显示稳定错误码、本次 attempt 和恢复操作 |
| 已取消/暂停 | 中性徽标 | 保留最后事实，显示恢复条件 |
| 正在提交 | 进度状态 | 禁止取消，提示结果正在持久化；刷新后从服务端恢复 |
| 副作用不确定 | 高风险错误 | 隐藏自动重试，要求检查外部系统并完成人工补偿 |

计划列表在 Workflow 暂停后仍保留原 Trigger 类型和下一次计划时间，并通过状态徽标表达“已暂停”，不得回退成“手动/按需运行”。错过执行显示稳定的“已跳过 / 已补跑 / 触发配置无效 / 物化失败”结果，不展示底层异常正文。

所有状态同时有文字、图标和 aria-label；颜色仅作辅助。刷新、断线重连和页面重开后从服务端 Run projection 恢复。

同一员工存在多个并行任务时，每个等待气泡和完成/失败消息必须绑定任务实例；失败、停止或迟到回调只能更新自己的气泡。

## 5. 设计系统

沿用 AgentSpace 现有工作台的紧凑、可扫描风格，不新增营销式 Hero 或套卡套卡布局。

```css
:root {
  --orchestration-primary: #2563eb;
  --orchestration-primary-soft: #eff6ff;
  --orchestration-ink: #111827;
  --orchestration-muted: #6b7280;
  --orchestration-border: #d1d5db;
  --orchestration-success: #059669;
  --orchestration-warning: #d97706;
  --orchestration-error: #dc2626;
  --orchestration-space-1: 4px;
  --orchestration-space-2: 8px;
  --orchestration-space-4: 16px;
  --orchestration-space-6: 24px;
  --orchestration-radius-sm: 4px;
  --orchestration-radius-md: 8px;
}
```

按钮采用现有 `knowledge-btn` 语义，危险动作使用图标 + 明确文字和二次确认。节点卡片最大宽度稳定，不能因动态日志或长员工名称改变画布布局。桌面采用三栏，≤860px 时切换为“节点列表 / 画布 / 配置”分步视图，不把画布压缩到不可用。

## 6. 组件规格

| 组件 | 变体 | 必须状态 |
| --- | --- | --- |
| WorkflowList | compact/table/empty | loading、error、empty、filtered |
| WorkflowNode | employee/join/approval/start/end | draft、ready、running、blocked、success、failed |
| RunTimeline | grouped/by-node | reconnecting、gap、redacted |
| PreflightPanel | summary/detail | pass、warning、block |
| RetryDialog | node/run | reason、budget、idempotency |
| ScheduleEditor | once/repeat/event | timezone、DST、invalid cron |
| ApprovalGate | pending/approved/rejected | reviewer、deadline、risk |

## 7. 无障碍与安全 UX

- 遵循 WCAG AA，正文和边框文字对比度至少 4.5:1，焦点环清晰。
- 画布提供结构化列表替代视图；屏幕阅读器可按节点顺序读取依赖和状态。
- 批量操作显示影响节点数；取消、删除、发布和重试均有明确确认。
- 不在浏览器响应中展示 Skill secret、Provider credential、宿主路径、原始命令和未经脱敏的日志。
- 事件时间线显示稳定 label code 的本地化文案，不直接信任外部事件携带的用户文案。

## 8. 可用性测试计划

招募 5-8 名 workspace 管理员/任务负责人，覆盖桌面和窄屏。任务：创建“研究员 A → 分析员 B 与审计员 C 并行 → 主编 D 汇总”的每日 09:00 计划；修复一次预检阻塞；从失败节点重试。

目标：任务完成率 ≥85%、中位创建时间 ≤5 分钟、错误率 ≤1 次/任务、SUS ≥68。严重问题分为 P0（无法发布/误执行）、P1（无法理解依赖/恢复）、P2（效率或文案问题）。
