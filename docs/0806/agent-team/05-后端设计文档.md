# AI 员工团队编排：后端设计文档

## 1. 服务与仓储边界

```text
packages/domain/src/workflows.ts
  WorkflowDefinition / Version / Node / Edge / Trigger / Run / NodeRun / Event

packages/db/src/workflows/
  definitions.ts  versions.ts  triggers.ts  runs.ts  node-runs.ts  events.ts  outbox.ts

packages/services/src/workflows/
  definitions.ts  validation.ts  publishing.ts  scheduler.ts  coordinator.ts
  dispatcher.ts  inputs.ts  joins.ts  retries.ts  projections.ts  migration.ts

apps/workflow-worker/
  tick.ts  outbox-consumer.ts  recovery.ts  health.ts
```

`packages/db` 只实现事务和行映射；`packages/services` 持有状态机、权限、图规则和幂等语义；Worker 只循环调用 service，不重复业务规则。Web 和 daemon 不直接修改 Workflow 表。

## 2. 数据模型

### `workflow_definition`

`id, workspace_id, name, description, owner_user_id, channel_name, status, active_version_id, legacy_source_type, legacy_source_id, created_by, created_at, updated_at, archived_at`

约束：`UNIQUE(workspace_id, id)`；legacy source 在 workspace 内唯一；status 为 `draft|published|paused|archived`。

### `workflow_version`

`id, workspace_id, workflow_id, version_number, schema_version, graph_json, input_schema_json, output_schema_json, governance_json, content_hash, published_by, published_at, created_at`

发布后不可更新。`UNIQUE(workflow_id, version_number)` 和 `UNIQUE(workflow_id, content_hash)` 避免重复版本。

### `workflow_trigger`

`id, workspace_id, workflow_id, type, config_json, timezone, status, next_fire_at, last_fire_at, misfire_policy, dedupe_window_seconds, lease_owner, lease_expires_at, created_at, updated_at`

`type` 首期为 `manual|schedule|event`。Schedule config 保存受控 repeat 或验证后的 cron，不保存本地化日期字符串。

### `workflow_run`

`id, workspace_id, workflow_id, version_id, root_task_id, trigger_id, trigger_type, trigger_key, input_json, status, current_sequence, budget_json, started_at, finished_at, created_by, created_at, updated_at`

`UNIQUE(workspace_id, trigger_key)` 保证同一计划时间/事件只创建一个 Run。

### `workflow_node_run`

`id, workspace_id, run_id, node_id, node_type, employee_id, employee_name_snapshot, status, attempt_count, max_attempts, available_at, task_queue_id, approval_id, input_json, output_json, artifact_manifest_json, error_code, error_message, started_at, finished_at, created_at, updated_at`

`UNIQUE(run_id, node_id)`；活动 attempt 通过独立 `workflow_node_attempt` 或现有 `agent_task_attempt` 关联，不能仅覆盖计数。

### `workflow_run_event` 与 `workflow_outbox`

事件表：`id, workspace_id, run_id, node_run_id, sequence, type, actor_type, actor_id, severity, data_json, created_at`，唯一 `(run_id, sequence)`。

Outbox：`id, workspace_id, aggregate_type, aggregate_id, event_type, payload_json, status, attempts, available_at, locked_at, locked_by, last_error, created_at, published_at`。

索引至少覆盖：到期 Trigger、ready/retry_wait Node Run、运行列表、Run 事件顺序、未发布 outbox 和 task_queue 反查。

## 3. Graph JSON 契约

```json
{
  "nodes": [
    {"id":"research","type":"employee_task","employeeId":"emp_1","config":{"instruction":"...","timeoutSeconds":1800,"retry":{"maxAttempts":2}}},
    {"id":"analysis","type":"employee_task","employeeId":"emp_2","config":{"input":{"report":"${research.output.report}"}}},
    {"id":"audit","type":"employee_task","employeeId":"emp_3","config":{"input":{"report":"${research.output.report}"}}},
    {"id":"join","type":"join","config":{"policy":"all_success"}},
    {"id":"editor","type":"employee_task","employeeId":"emp_4","config":{"input":{"results":"${join.outputs}"}}}
  ],
  "edges": [
    {"source":"research","target":"analysis"},
    {"source":"research","target":"audit"},
    {"source":"analysis","target":"join"},
    {"source":"audit","target":"join"},
    {"source":"join","target":"editor"}
  ]
}
```

表达式首期不是通用脚本，只支持 JSONPath 风格的声明式字段引用和固定系统变量。发布时解析并生成依赖索引；运行时不执行 `eval`、shell 或用户 JavaScript。

## 4. 核心算法

### 发布

1. 规范化节点和边，验证 schema version。
2. 拓扑排序检测环、孤立节点和不可达路径。
3. 校验 Join 的上游、员工稳定 ID、Runtime/Skill readiness、频道和权限。
4. 计算 `content_hash`，在事务中插入不可变 Version 并更新 Definition active version。
5. 写 `workflow.version_published` 审计和 outbox。

### Scheduler Tick

```text
claim where status=active and next_fire_at<=now and lease expired
for each trigger:
  derive triggerKey(workflowId, triggerId, scheduledAt/eventId)
  create workflow_run with ON CONFLICT DO NOTHING
  materialize node runs from immutable version
  advance ready nodes
  compute and persist next_fire_at
  emit run.created and trigger.fired in same transaction
```

### 图推进

收到节点终态事件后锁定 Run，验证事件 task/node 归属与 attempt。对每个下游节点计算：所有 required 前置是否终态、Join policy 是否满足、Run 是否暂停/取消、预算是否可用。满足则条件更新 `pending → ready` 并写 outbox；不满足保持 pending 或标记 skipped/failed。重复事件不得创建第二条队列任务。

### Dispatch

读取 ready outbox，在事务中把 Node Run 改为 queued，并调用 `enqueueNativeTaskSync` 的新 workflow-aware 输入；`metadata` 带稳定的 run/node/attempt ID、输入摘要、Artifact refs 和输出 schema。若队列写入失败，Node Run 回到 ready 或 retry_wait，不把 Workflow 标成成功。

## 5. API 与 Action 契约

推荐外部 HTTP 契约：

| Method | Path | 语义 |
| --- | --- | --- |
| GET/POST | `/api/workspaces/:workspaceId/workflows` | 列表/创建草稿 |
| GET/PATCH | `/api/workspaces/:workspaceId/workflows/:workflowId` | 读取/更新草稿 |
| POST | `.../:workflowId/validate` | 图和依赖预检 |
| POST | `.../:workflowId/publish` | 发布不可变版本 |
| POST | `.../:workflowId/runs` | 手动触发 Run |
| GET | `.../:workflowId/runs` | 运行历史 |
| GET | `/api/workspaces/:workspaceId/workflow-runs/:runId` | 运行 projection |
| GET | `.../:runId/events?after=` | 事件补偿/SSE |
| POST | `.../:runId/pause|resume|cancel` | 运行控制 |
| POST | `.../:runId/nodes/:nodeId/retry` | 节点重试 |

Web 页面可通过 Server Actions 封装这些 service；HTTP route 主要服务实时查询、内部 worker 和未来 CLI。所有 mutation 接受 `idempotencyKey` 和 `expectedVersion`。

## 6. 事件契约

首期稳定事件：

- `workflow.run.created|started|waiting_approval|succeeded|partially_succeeded|failed|paused|cancelled`
- `workflow.node.ready|queued|started|retry_scheduled|waiting_approval|succeeded|failed|skipped|cancelled`
- `workflow.trigger.fired|misfired|deduplicated`
- `workflow.version.published`

Payload 只携带稳定 ID、状态码、时间、计数、Artifact 引用和安全参数；不携带秘密、未经脱敏日志或可被 UI 直接渲染的外部 HTML。

## 7. 错误码

| 错误码 | HTTP/状态 | 处理 |
| --- | --- | --- |
| `workflow_graph_cycle` | 422 | 阻止发布并返回涉及节点 |
| `workflow_node_unreachable` | 422 | 定位孤立节点 |
| `workflow_employee_not_ready` | 409 | 返回员工 readiness blocker |
| `workflow_version_conflict` | 409 | 返回最新版本/更新时间 |
| `workflow_trigger_duplicate` | 200 existing | 返回已有 Run，不重复执行 |
| `workflow_budget_exceeded` | paused | 通知负责人，等待调整/审批 |
| `workflow_node_retry_exhausted` | failed | 进入人工接管 |
| `workflow_event_sequence_gap` | reconciling | 暂停投影并补偿 |
| `workflow_cross_workspace_reference` | 403 | 审计并拒绝 |

## 8. 权限、审计与数据保留

复用 workspace role 与 actor context。Definition/Version/Trigger 的变更审计记录 diff 摘要，不记录 secret；Run/Node/Attempt 的每次控制动作写 actor 和 reason。删除 Workflow 采用归档，不级联删除 Run、Artifact、approval 和 audit。数据清理按现有 workspace purge 和员工数据保留策略扩展，Legal Hold 下禁止清理关联运行证据。

## 9. 兼容与迁移实现

- 为 legacy `ScheduledTask.id` 和 `AutomationRule.id` 建 `legacy_source_id` 唯一映射表或列。
- 迁移脚本支持 `--dry-run`、workspace 范围、统计和幂等重跑；每条失败保留原因。
- 切流按 workspace feature flag：`legacy_only → dual_read → workflow_engine → legacy_archived`。
- 双写期间只有一个调度 owner；旧 ScheduledTask 的 UI 写操作转发到新 service，避免双触发。
- 内置“然后”和“做直到”保持 legacy adapter，直到新 Engine 支持等价运行语义并完成历史兼容测试。
