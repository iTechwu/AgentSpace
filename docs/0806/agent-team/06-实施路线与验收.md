# AI 员工团队编排：实施路线与验收

> 实施状态（2026-08-07，本轮深审起点 `d0e8b5e`）：Phase 0-4 的首期代码和静态契约已落地；本文件保留原交付路线。最终证据以本目录所在提交为准。数据库/E2E/真实容量/可用性/环境签字仍未完成，发布保持 `NO-GO`。逐项完成度见 [07-规格实施覆盖矩阵.md](./07-规格实施覆盖矩阵.md)。

## 1. 分期原则

先建立不可变契约和可靠运行内核，再做画布和入口整合。不能先上线“看起来能编排”的 UI，再用内存状态或 Prompt 补齐调度语义。

## 2. 交付阶段

### Phase 0：契约与验证 Spike

- 固化 Workflow/Version/Run/NodeRun/Trigger/Event 类型和状态机。
- 用数据库原型验证 `SKIP LOCKED`、幂等 Trigger、节点终态竞争和 outbox 恢复。
- 用现有 `enqueueNativeTaskSync` 跑通单节点闭环，确认 task completion 可可靠推进 Run。
- 输出 3 个基准图：串行、并行 Join、审批后汇总。

退出标准：重复触发不会创建重复 Run；重复完成事件不会重复投递下游。

### Phase 1：持久化内核与单节点迁移

- 新增 Workflow 表、仓储、服务、审计和 feature flag。
- 实现草稿、校验、发布、手动运行、一次性/重复定时和单 AI 节点。
- 迁移 `ScheduledTask` 为单节点 Workflow，完成 dry-run 和回滚。
- `/calendar` 读取新 Trigger projection。

退出标准：定时运行 P95 延迟 ≤60 秒；单节点成功/失败/重试全链路可见。

### Phase 2：串行、并行与 Join

- 实现拓扑校验、Node Run 物化、输入映射、并行 dispatch、Join policy 和 Artifact manifest。
- 完成 `A → B`、`A → (B ∥ C) → D` 端到端测试。
- 加入 Run 详情、事件时间线和失败节点重试；“从节点继续”移入二期。

退出标准：并行节点独立执行；Join 不早于策略满足；上游失败不会静默生成完整结果。

### Phase 3：编排中心与双入口

- 把 `/automations` 升级为计划/运行中心，并保留模板空状态作为二期入口。
- 实现统一创建向导、画布/列表双视图、预检面板和移动端分步视图。
- 任务看板和日历接入同一向导与 Run 详情。
- 准备可用性测试脚本；真实 5-8 人验证属于发布前外部门禁。

退出标准（尚未关闭）：5-8 人核心创建任务完成率 ≥85%，SUS ≥68，无关键无障碍阻塞。

### Phase 4：审批、事件 Trigger 与 legacy 收口

- 支持人工审批节点、现有任务/文档/消息事件触发。
- 迁移可静态映射的 AutomationRule；内置 legacy 规则保留适配器。
- 完成预计成本预算预检、权限撤销、Runtime 离线、Skill 过期和事件缺序补偿；实际成本熔断为二期。

退出标准：高影响动作 100% 经过治理路径；旧规则无双触发；迁移可回滚。

## 4. 测试矩阵

| 层级 | 必测内容 |
| --- | --- |
| Domain | DAG、环、孤立节点、Join、状态机、输入映射 |
| DB | 唯一约束、workspace 隔离、lease、并发 claim、outbox、终态保护、commit journal 字段保留与 attempt 计数 |
| Service | 发布预检、Trigger 去重、图推进、重试、取消、预算、审批、跨 workspace 提交对账 |
| Daemon 集成 | Node metadata、暂停后的在途 input bundle、Artifact refs、完成/失败事件、staging 冻结、脱敏 |
| Web | 双入口、画布、表单错误、运行投影、断线补偿、无障碍 |
| E2E | 手动串行、定时并行 Join、审批、失败重试、迁移后运行 |
| 故障演练 | Worker 崩溃、提交后投影前崩溃、重复事件、数据库短暂不可用、Runtime/Daemon 离线、事件缺序 |

测试资源遵守仓库约束：根测试保持 `turbo run test --concurrency=2`；只运行最小相关测试；API/Jest 单文件使用 `--runInBand`，完整运行不得超过 `--maxWorkers=2`。

## 5. 发布门禁

- 数据迁移必须先 dry-run，报告转换、禁用草稿、保留 legacy 和失败数量。
- 安全评审确认 workspace 隔离、secret 不落编排数据、Artifact 归属、审批和日志脱敏。
- 并发测试证明没有重复 Run、重复下游任务或终态回退。
- 运行页面在刷新、断网重连、worker 重启后恢复一致状态。
- 可用性测试完成且所有 P0/P1 问题有结论。
- feature flag 支持按 workspace 回滚到 legacy 只读/执行路径。

## 6. 验收场景

### 场景 A：每日经营简报

每天 09:00 触发；研究员收集数据，分析员和审计员并行处理，主编在 Join 后汇总。验收：只产生一个 Run，并行步骤可同时执行，最终结果包含两个上游的 Artifact 引用。

### 场景 B：审批后发布

内容员工产出草稿，人工审批节点等待；批准后发布员工执行，拒绝则 Run 终止。验收：未批准前无外发动作，审批 actor 和意见进入审计。

### 场景 C：失败恢复

并行组一项执行失败，系统按策略重试一次后仍失败。负责人重试该节点，Join 随后继续。验收：已成功节点不重复执行，attempt 正确累计；节点独立超时与实际成本累计另列二期验收。

### 场景 D：定时错过与去重

Worker 停止 10 分钟后恢复。验收：按 misfire policy 只补跑最近一次或跳过；相同 scheduledAt 不产生两个 Run。

### 场景 E：权限撤销

发布后、运行前撤销某员工的 Runtime grant。验收：预检/dispatch 阻止该节点，显示可修复原因，不泄露凭据或内部路径。

### 场景 F：提交崩溃恢复

分别在副作用检查点后、Workspace 提升后、队列完成后和频道投影后终止进程。验收：检查点前的部分副作用进入人工补偿；检查点后的任务可由 HTTP 重试或全局 reconcile 收敛；不重复产物、消息、AI 输出提及或外发 outbox；revision/artifact 元数据不丢失。

### 场景 G：暂停与并行消息隔离

同一员工并行执行两个节点，在其中一个任务领取后暂停 Run，并让另一个任务失败。验收：已领取任务仍可取输入并完成；未领取任务不 dispatch；失败消息只替换对应 `taskQueueId` 的等待气泡。

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 通用引擎范围膨胀 | 首期节点白名单；脚本、循环和动态拓扑不开放 |
| Worker 与队列双写 | 事务 outbox + 幂等 consumer |
| 多员工上下文无限增长 | 输出 schema + Artifact refs + 摘要上限 |
| 旧定时任务双触发 | 单一调度 owner + legacySourceId 去重 + feature flag |
| 运行中员工配置漂移 | 不可变 Version/governance + 员工展示快照 + dispatch 前 readiness 复核 |
| 画布无障碍不足 | 列表替代视图 + 键盘命令 + WCAG AA 测试 |
