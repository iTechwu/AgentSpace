# IM 实施计划与验收

## 1. 阶段总览

| 阶段 | 目标 | 主要产物 | 退出条件 |
| --- | --- | --- | --- |
| P0 | 事件保真与增量读接口 | task stream adapter、snapshot/afterSeq、未知事件保留 | Harness 七类事件可完整回放，现有 IM 不回归 |
| P1 | 节点化客户端渲染 | `ConversationStreamStore`、单节点渲染、正文/reasoning/tool 分离 | 流式只更新目标行，展开状态和滚动稳定 |
| P2 | disclosure 视觉与长内容 | ReasoningRow、ToolRow、IN/OUT、sweep、a11y | 桌面/移动端长输出可读，减弱动效通过 |
| P3 | 性能、断线和发布门禁 | 帧批处理、重连补偿、指标、灰度开关 | 断网/刷新/多任务并发数据不丢，满足发布阈值 |

## 2. P0：事件保真与增量读模型

### 2.1 改动清单

| 区域 | 改动 |
| --- | --- |
| `packages/db/src/task-messages.ts`、`packages/db/src/types/tasks.ts` | 明确 `seq`、`refId`、event type 开放集合；提供按 task 的 afterSeq 查询 |
| `packages/services/src/messages/messages.ts` | pending text 使用累计值；progress 更新保留 source seq/refId，发布 conversation/task 定位字段 |
| `apps/web/app/api/workspaces/[workspaceId]/conversations/[conversationId]/messages/route.ts` | 支持 snapshot、`afterSeq`、`limit`、`hasMore`，补齐执行节点投影 |
| `apps/web/app/api/workspaces/[workspaceId]/conversations/[conversationId]/execution-content/*` | 超大节点内容按 contentId/cursor 受权分段读取，返回总大小和完整性状态 |
| `apps/web/app/api/workspaces/[workspaceId]/channels/[channelName]/events/route.ts` | SSE `channel.thread.changed` 增加 conversationId/taskId/lastSeq |
| `apps/web/features/chat/task-execution-timeline.ts` | 从“删除/折叠”改为“节点投影”：text、thinking、tool_use/result、status、usage、error、unknown 均有结果 |
| `apps/web/features/channels/data*` | 读取模型不再为单 task 只保留一个 carrier；保留原始 execution stream 和 snapshot version |

### 2.2 P0 验收

- 同一 task 的 `text -> reasoning -> tool_use -> tool_result -> text -> usage -> status` 按 seq 回放后节点数量和顺序可核对。
- `tool_result` 缺失 `tool_use`、未知 type、空 content、迟到结果均可见，不静默丢弃。
- 超大 payload 的 preview 必须标明截断和总大小，并能通过分段读取核对完整内容摘要。
- afterSeq 重复请求不会重复节点；缺口会返回同步状态或可重拉区间。
- 现有 `/new`、历史会话、消息发送、审批和 OpenMontage 卡片不改变行为。

## 3. P1：节点化客户端渲染

### 3.1 改动清单

| 文件/区域 | 改动 |
| --- | --- |
| `apps/web/features/chat/conversation-stream/store.ts` | `byKey`、`order`、`lastSeqByTask`、`expandedKeys`、`followMode`；frame-batched publish |
| `apps/web/features/chat/conversation-stream/project.ts` | 从 API executionNodes/task messages 投影稳定 node；处理 tool refId、终态和 unknown |
| `apps/web/features/chat/conversation-stream/components/*` | `StreamNodeSeat`、`StreamTaskGroup`、`ReasoningRow`、`ToolRow`、`StatusRow`、`UsageRow`、`UnknownRow` |
| `apps/web/features/chat/conversation-shell.tsx` | 保留 composer、scroll、历史入口；消息区域委托 `ConversationStreamView` |
| `apps/web/features/chat/chat-primitives.tsx` | 将现有 `TaskExecutionTimeline` 拆为兼容包装或逐步下线，不再承担数据折叠 |
| `apps/web/features/chat/conversation-scroll-anchors.ts` | 增加 node key 锚点，兼容旧 message id |

### 3.2 P1 验收

- 追加一个 reasoning delta 时，只有该 reasoning row 更新；兄弟 tool/text 行不 remount。
- 用户展开 tool 详情后连续收到 output delta，详情保持展开；用户收起后不自动打开。
- 用户离开底部阅读时，新节点不抢滚动；回到底部按钮能显示和恢复 follow mode。
- 切换 conversation、刷新、SSE 断线重连后，节点顺序、完成状态和展开集合符合预期。

## 4. P2：视觉和无障碍

### 4.1 设计落点

- 在 `apps/web/app/globals.css` 或新的 chat CSS 模块中增加 disclosure row tokens，复用当前 `--text`、`--muted`、`--success`、`--danger`。
- `ReasoningRow`：思考图标、Think/思考过程标题、最新行摘要、整行点击、详情换行、运行 sweep。
- `ToolRow`：工具图标、工具名、摘要、状态点、IN/OUT 详情、内部滚动、复制按钮；不使用嵌套 card。
- `StatusRow`、`UsageRow`、`UnknownRow`：保留同一行节奏，详情使用统一 disclosure。
- `prefers-reduced-motion` 下取消 sweep；`aria-expanded`、`aria-controls`、键盘 Enter/Space、焦点样式齐全。

### 4.2 P2 验收

- 320px、390px、768px、1440px viewport 下无横向滚动、无文本遮挡、按钮文字不溢出。
- 10MB 级别的工具输出不一次进入 DOM；聊天显示带总大小的预览，用户可分段继续加载或受权下载完整输出。
- 屏幕阅读器能区分“正在运行/已完成/错误/已展开”，普通 token 更新不会连续播报。
- 视觉快照覆盖运行中、完成、错误、未知事件、reasoning 展开、tool IN/OUT 展开、窄屏。

## 5. P3：性能、观测与灰度

### 5.1 指标

客户端记录（不含正文 payload）：

- `im_stream_first_visible_ms`：首个可见节点从 SSE/响应到渲染的耗时；
- `im_stream_delta_to_paint_ms`：delta 到对应行绘制的 p50/p95；
- `im_stream_gap_recovery_count`：seq 缺口补偿次数；
- `im_stream_duplicate_drop_count`：幂等去重次数；
- `im_stream_scroll_jump_count`：非用户主动滚动造成的跳动；
- `im_stream_unrendered_event_count`：投影失败或安全过滤的事件数（只记 type/code）。

### 5.2 性能门禁

- 单 task 500 个节点、100 个工具调用、持续 60 秒流式更新时，主线程长任务不超过 50ms p95。
- 50 条/秒 delta 输入经 frame batch 后，React commit 不超过 60 次/秒；后台 tab 不持续执行 rAF。
- 频道有 10 个并行 task 时，只更新对应 conversation/task 的 node，不触发所有频道消息气泡重渲染。

### 5.3 灰度与回滚

- 增加 workspace/employee 级 feature flag：`im_stream_nodes_v1`，默认关闭。
- 保留现有 carrier/timeline 兼容渲染作为回滚路径；两种读取模型可由服务端字段或客户端 flag 选择。
- 出现节点顺序错乱、正文丢失、严重滚动抖动或 payload 泄漏时，关闭 flag 即可回到旧视图，不回滚持久化 task_message。

## 6. 测试矩阵

### 6.1 单元测试

- `project.ts`：稳定 key、seq 排序、重复事件、缺口、unknown、tool refId 配对、迟到终态。
- `PartialAccumulator` 类测试：text/reasoning/tool-call block 累计、空 block、乱序 block index。
- disclosure 状态：首次默认态、用户展开/收起、节点更新不改变状态、卸载后按产品策略恢复。
- scroll：底部跟随、用户上滚、长详情内部滚动、prepend 后 anchor 保持。

### 6.2 API/SSE 测试

- conversation messages 首次 snapshot、afterSeq、limit、hasMore、越权和重复请求。
- channel SSE 发送 conversationId/taskId/lastSeq，频道过滤和权限变化后关闭连接。
- task message route 对 text delta、thinking、tool_use/result、unknown 的投影和事件发布。
- execution content 对游标、单次字节上限、conversation 越权、内容摘要和完整读取进行测试。

### 6.3 E2E/视觉测试

- Harness 典型回放：纯正文、reasoning + 正文、tool 输入/输出、并行 tool、错误、usage、未知事件。
- 运行中断网 3 秒后恢复；最终 snapshot 与连续在线结果一致。
- 切换会话、刷新页面、浏览器前进后退，消息和展开状态符合契约。
- 移动端键盘打开、长文本、窄屏工具详情和 reduce motion。

遵循仓库测试资源限制：单文件 Jest 使用 `--runInBand`；全量测试不得使用无约束 worker，根脚本保持 `turbo run test --concurrency=2`。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 旧 task 没有完整 `task_message` | 历史任务无法还原全部节点 | 兼容现有 WorkspaceMessage，显示“历史流不可用”，不伪造缺失事件 |
| provider 只报告 tool result | 工具输入缺失 | 创建独立 result 节点并显示“调用详情不可用”，保留 output |
| seq 在多 task 间不可比较 | 跨 task 排序错误 | 只在 task 内按 seq，跨 task 使用 message createdAt 和稳定插入序 |
| 高频 delta 触发渲染压力 | 卡顿和滚动抖动 | 累计 partial、单节点 selector、rAF batch、后台降频 |
| 将原始 payload 直接展示 | 凭据/路径/堆栈泄漏 | 服务端安全化 + unknown JSON 只读文本 + 诊断分层 |
| 迁移期间新旧模型并存 | 行重复或丢失 | 以 feature flag 选择单一 renderer；node key 与旧 message id 建映射，禁止双绘制 |

## 8. 开放问题

1. Harness 当前 wire/daemon 是否能为每个 visible block 提供稳定 block id；如果不能，首期使用 `taskId + seq`，后续再升级 block key。
2. 是否需要把跨 task 并行输出显示在同一 execution group，还是按各自 task message 的时间顺序合并。
3. usage 是否已有权威 billing 字段；没有时只展示 token/运行时 usage，不展示金额。
4. 诊断详情是否需要单独的“查看运行诊断”权限入口；IM 默认不显示 provider stderr。
5. 是否允许用户将某类节点（例如 reasoning/tool）设置为 workspace 级默认展开；首期建议只保留产品默认策略，避免状态复杂化。

## 9. 发布检查点

### Checkpoint A：P0 后

- [ ] 七类 Harness 可见事件可从持久化 stream 完整回放。
- [ ] afterSeq、幂等、缺口补偿和 SSE 定位字段测试通过。
- [ ] 旧 IM、历史会话、审批、OpenMontage 卡片回归通过。

### Checkpoint B：P1/P2 后

- [ ] 节点局部更新、展开状态和滚动规则测试通过。
- [ ] 桌面/移动视觉快照无溢出和遮挡。
- [ ] 屏幕阅读器状态、键盘 disclosure、reduce motion 验收通过。

### Checkpoint C：P3 后

- [ ] 性能阈值和断线恢复指标达标。
- [ ] feature flag 可按 workspace/employee 关闭并回滚到旧视图。
- [ ] 安全审查确认普通 IM 不显示凭据、绝对路径、原始 stderr 或未授权 payload。
