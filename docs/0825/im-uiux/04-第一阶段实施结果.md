# IM 流式输出第一阶段实施结果

实施日期：2026-08-25

## 1. 本次落地范围

本次按方案优先完成影响 Harness 输出完整性和阅读体验的主链路：

- 将 task message 按 task 内 `seq` 投影为稳定节点，并累计全部 `text` 正文；
- 连续 reasoning 合并到稳定节点，未知事件、usage、错误和无前置调用的 tool result 不再静默丢失；
- tool use/result 保留独立 IN/OUT 内容，详情默认收起，展开状态不随流式增量重置；
- 长详情每次只挂载 16,000 字符，用户可继续分段展开；
- 运行中 reasoning 显示最新一行摘要和低干扰 sweep，`prefers-reduced-motion` 继续由全局规则关闭动画；
- SSE thread change 增加 `conversationId`、`taskId`、`lastSeq`，客户端优先通过 `afterSeq` 定向补拉并按 seq 去重；
- 定向补拉失败、元数据不完整或发现 seq 缺口时，保留原有频道刷新作为兼容回退；
- 用户离开底部阅读时不抢滚动；有新内容时显示“有新消息”，点击后恢复底部跟随；
- 最终回复优先使用持久化 task stream 重建的完整正文，避免 WorkspaceMessage 摘要滞后导致截断。

## 2. 接口变化

### Conversation messages

`GET /api/workspaces/:workspaceId/conversations/:conversationId/messages`

- 新增可选参数 `taskId`、`afterSeq`；
- `afterSeq` 必须与属于当前 conversation 的 `taskId` 一起使用；
- 响应新增 `taskExecutions`、`lastSeqByTask`、`snapshotVersion`；
- task 越权或非法游标返回 400，不泄漏其他 conversation 的执行内容。

### Channel SSE

`channel.thread.changed` 在原字段之外增加可选：

- `conversationId`
- `taskId`
- `lastSeq`

旧发布方和旧客户端仍可使用不带这些字段的事件，并自动走整频道刷新回退。

## 4. 后续发布门禁

下列项目仍按原方案作为后续规模化发布门禁，不在本次核心体验改造中宣称完成：

- 10MB 级 payload 的服务端 contentId/cursor 分段读取；
- 500 节点、50 delta/秒、10 并行 task 的专项性能压测与指标上报；
- workspace/employee 级 `im_stream_nodes_v1` 灰度开关；
- 覆盖真实 Harness 回放数据的桌面/移动视觉基线与断网 3 秒恢复 E2E。

本次实现保留原有整频道刷新和 WorkspaceMessage 摘要路径作为失败回退，因此上述发布门禁可以在不阻塞当前体验改善的前提下继续补齐。
