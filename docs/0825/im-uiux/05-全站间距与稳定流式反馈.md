# 全站间距与稳定流式反馈设计

> 日期：2026-08-25
>
> 状态：已确认
>
> 决策：采用 Token 驱动、渐进收敛方案；全站使用平衡密度，表格、日志和执行轨迹允许局部紧凑；IM 使用稳定分帧流式反馈。

## 1. 背景与目标

当前 IM 已能展示 Harness 的主要执行过程，但不同页面仍存在外边距、区块间距、工具栏密度和窄屏换行不一致的问题。流式输出在高频更新时还需要进一步降低重排、滚动跳动和视觉噪声。

本轮设计同时解决两个用户体验问题：

1. 建立全站一致、可预测的页面节奏，使列表、详情、设置和 IM 之间切换时不出现明显密度跳变。
2. 保证 Harness 已报告的正文、reasoning、工具、状态、usage、错误和未知事件清晰、完整、流畅地呈现。

本轮不是全量重做设计系统，也不改变导航信息架构、任务协议或权限模型。

## 2. 已确认的设计方向

### 2.1 全站平衡密度

全局采用 `24 / 16 / 12 / 8px` 四级间距节奏：

| 层级 | 基准值 | 主要用途 |
| --- | ---: | --- |
| 页面区块 | 24px | 页面标题与主体、独立内容区之间 |
| 组件组 | 16px | 表单分组、面板内容、列表区块之间 |
| 控件组 | 12px | 标签与输入、工具栏控件、同组字段之间 |
| 行内元素 | 8px | 图标与文字、状态点、紧凑操作之间 |

- 桌面页面外边距以 `24px` 为基准，窄屏收敛为 `16px`。
- 表格、日志、执行轨迹允许使用 `8 / 6px` 的局部紧凑节奏，但交互目标不低于 `40px`。
- 页面区块优先使用留白、标题层级和分隔线组织，不叠加无意义的卡片容器。
- 标题区、工具栏和正文区使用共享页面骨架，不在各页面重复定义近似间距。

### 2.2 稳定分帧流式反馈

- 每个正文、reasoning、工具调用、工具结果、状态、usage、错误和未知事件都有稳定节点标识。
- 高频增量先写入缓冲区，再通过 `requestAnimationFrame` 每帧最多提交一次。
- 增量只更新目标节点，不替换整个任务组或消息列表。
- 当前更新节点使用低干扰状态提示，不使用引发布局变化的加载文案或图标。
- 后台标签页降低刷新频率；页面恢复可见时立即补齐累计状态。

## 3. 页面布局模型

### 3.1 共享页面骨架

列表、详情、设置和 IM 页面统一分为：

```text
Page shell
  Page header
    Title / description
    Primary actions
  Optional toolbar / filters
  Main content
  Optional sticky or fixed action area
```

共享骨架负责外边距、区块间距、响应式换行和最大内容宽度。业务页面只声明结构和必要的密度变体，不直接复制页面级 margin/padding 组合。

### 3.2 页面类型约束

| 页面类型 | 默认密度 | 关键约束 |
| --- | --- | --- |
| 列表 | 平衡 | 标题、筛选、批量操作和表格边界清楚；表格内部可紧凑 |
| 详情 | 平衡 | 摘要与分区之间使用 24px；字段组使用 16px |
| 设置/表单 | 平衡 | 标签、说明和控件使用稳定纵向节奏；错误提示不挤压相邻字段 |
| IM | 平衡 | 正文保持连续阅读面；执行轨迹局部紧凑；输入区不遮挡消息 |
| 日志/诊断 | 紧凑 | 行间距更小，保留搜索、复制、展开和键盘可达性 |

### 3.3 响应式行为

- 窄屏下页面标题与操作区允许换行，主操作保持可见，次要操作进入菜单。
- 工具栏由单行自然转为多行，不压缩输入控件至不可用宽度。
- 长单词、路径、代码和 Harness 输出在内容边界内断行或内部滚动，页面本身不得产生横向滚动。
- 固定输入区、底部操作区和安全区域共同计算内容 padding，不能遮挡最后一条消息。

## 4. IM 流式交互规格

### 4.1 节点更新

沿用既有执行节点模型。投影层将事件归一化为稳定 node key，状态层维护 `byKey + order`，组件通过单节点订阅更新。正文使用累计文本引用，工具结果通过 `refId` 更新对应工具节点；无法匹配时创建独立结果节点。

同一动画帧内的多个 delta 合并后一次发布。调度器只负责提交节奏，不丢弃中间语义；最终累计值必须与服务端快照一致。

### 4.2 展开与收起

- 完成的 reasoning、tool 和 usage 默认显示一行摘要。
- error 默认展开首段安全化信息，详细 payload 仍由用户主动展开。
- 用户主动展开或收起后，后续流式更新不改变该状态。
- 详情区域设置稳定尺寸约束和内部滚动，展开时不触发自动滚动到底部。
- disclosure 支持 `aria-expanded`、`aria-controls`、Enter 和 Space 操作。

### 4.3 滚动策略

- 用户距底部不超过 24px 时进入 follow mode，增量到达后跟随最新内容。
- 用户向上阅读后立即退出 follow mode，保持当前锚点和偏移。
- 非 follow mode 下显示“有新输出”入口；入口不遮挡正文，点击后平滑回到底部并恢复 follow mode。
- 切换会话、刷新和断线重连后，按 conversation 保存并恢复锚点、偏移和 follow mode。

### 4.4 状态与错误

- 开始、审批、错误、取消和完成形成明确状态；正文与过程信息不得混为同一错误区域。
- 可恢复运行时警告折叠显示，任务继续成功时仍需呈现正确最终回复。
- 未识别的 Harness 事件显示为安全化的“运行时事件”，不得静默丢弃。
- `aria-live="polite"` 只播报开始、审批、错误和完成，不播报每个 token 或普通工具增量。

## 5. 动效与性能

- 运行中节点可使用约 2.6 秒的低干扰 sweep 或静态状态点；动画不能改变元素尺寸。
- `prefers-reduced-motion: reduce` 下停用 sweep 和非必要平滑滚动。
- 目标节点更新时，兄弟节点不得 remount，用户选中文本和详情滚动位置应保持稳定。
- 后台标签页不持续运行 rAF；使用低频批量刷新并在可见性恢复后同步。
- 长工具输出先显示带总大小和截断状态的预览，完整内容按权限分段加载，避免一次性进入 DOM。

## 6. 实施路线

采用 Token 驱动、渐进收敛方式：

1. 盘点并规范现有 spacing tokens，建立共享页面 shell、header、toolbar 和 section primitives。
2. 先迁移高频页面模板，再处理页面级例外；不使用全局末尾覆盖层掩盖局部问题。
3. 为表格、日志和执行轨迹提供显式 compact 变体，普通页面保持 balanced。
4. 在 IM 内实现稳定节点订阅、帧批处理、展开状态和滚动 follow mode。
5. 完成真实账户浏览器回归后，再逐步扩大共享组件使用范围。

不采用逐页面散落 CSS 调整，因为其会继续积累密度差异；本轮也不进行全量设计系统重构，以免扩大流式输出优化的风险面。

## 7. 验收标准

### 7.1 页面体验

- 列表、详情、设置和 IM 的页面外边距与主要区块节奏一致。
- 320px、390px、768px 和 1440px 视口无内容遮挡、按钮溢出或页面横向滚动。
- 表格和日志更紧凑，但点击目标、键盘焦点和信息层级仍然清楚。

### 7.2 流式输出

- 短回复、高频长回复、连续工具调用、超长工具输出均能持续显示。
- 每个动画帧最多一次状态提交；流式期间不出现明显整页抖动。
- 展开状态、文本选择、详情内部滚动和会话阅读位置在增量更新时稳定。
- 用户向上阅读时不被拉回底部；“有新输出”入口能正确恢复跟随。
- 错误后继续执行的任务必须显示正确最终回复，可恢复错误不能覆盖成功终态。

### 7.3 浏览器回归

使用本地或测试环境的优惠豚管理员账户验证：

- 登录、进入 IM、发送消息并等待完整流式回复；
- 展开和收起 reasoning、工具输入输出与错误详情；
- 检查桌面与移动视口的间距、滚动、换行和输入区遮挡；
- 检查控制台错误、失败网络请求、SSE/增量恢复和最终回复内容；
- 验证 reduced motion、键盘 disclosure 和关键状态播报。

## 8. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 全站间距调整影响范围过大 | 先改共享 primitives，按页面模板逐步迁移并做视觉回归 |
| 高频增量导致主线程压力 | 累计缓冲、rAF 批处理、单节点订阅、后台降频 |
| 滚动锚点在内容扩展时漂移 | 保存 node key 与 offset，详情内部滚动，非 follow mode 禁止抢滚动 |
| Harness 新事件无法识别 | 保留 unknown 节点和安全化 payload，记录未渲染计数 |
| 原始输出包含敏感内容 | 服务端安全化、权限控制、详情分层，IM 不直接暴露诊断级 stderr |

## 9. 非目标

- 不展示 Harness 未报告的隐藏 chain-of-thought。
- 不为每个 token 创建独立消息或 DOM 节点。
- 不在本轮重做导航、品牌视觉或整个组件库。
- 不在本机启动或触发 Jenkins；本地工作止于实现、验证和提交。
