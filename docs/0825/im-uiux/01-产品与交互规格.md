# IM 产品与交互规格

## 1. 现状判断

当前 IM 入口是 [apps/web/app/w/[workspaceSlug]/im/page.tsx](../../../apps/web/app/w/[workspaceSlug]/im/page.tsx) → `ChannelsPageClient` → `ConversationShell`。读取模型在 [apps/web/features/channels/channels-page-client.tsx](../../../apps/web/features/channels/channels-page-client.tsx) 中将同一 task 的多个 `process` 消息折叠成一个 carrier，再由 [apps/web/features/chat/task-execution-timeline.ts](../../../apps/web/features/chat/task-execution-timeline.ts) 生成时间线。

这个实现已经具备基本能力：

- 频道 SSE 失效通知与定时补偿刷新；
- thinking、tool_use、tool_result、status、usage、error 的基础映射；
- `<details>` 展开/收起；
- task 消息按 `seq` 排序，工具结果可按 `refId` 配对；
- pending 助手回复可以持续追加文本。

主要体验问题不是单纯 CSS 问题：

1. **节点身份不稳定**：多个过程消息被折叠到 carrier，增量更新时 React 只能重算整个任务视觉单元，不能只更新发生变化的行。
2. **正文与过程边界不清**：最终 text 被塞进 `executionReply`，中间 narration 又会被去重，部分 Harness 输出因此无法在 IM 中看到。
3. **reasoning 语义丢失**：`buildExecutionTimeline` 当前以单条 thinking 事件建行，但服务端 `recordAgentChannelProgressSync` 会将 pending thinking 累加到同一条 `WorkspaceMessage`，历史回放与实时态的粒度不一致。
4. **流式刷新过重**：SSE 只触发整段频道刷新，客户端通过 `CHANNEL_REFRESH_POLL_MS` 补偿；在高频 delta 下会重复加载不相关数据并造成滚动抖动。
5. **展开状态不具备明确策略**：当前 timeline 默认展开、只记录用户主动收起的 id；重排或 carrier 替换后，用户的阅读状态可能丢失。
6. **超长输出没有稳定的阅读面**：工具详情使用固定 `max-height`，但没有“当前行正在更新”“输出已截断/可继续读取”“跳到最新”等清晰状态。

## 2. 用户目标

用户在 Harness 任务运行时应能回答：

- 当前是否仍在运行，最近更新的是哪一个节点；
- 助手正文已经输出了什么，是否还会继续追加；
- Harness 报告了哪些 reasoning、工具输入、工具输出、状态、usage 和错误；
- 哪些节点已完成，哪些节点仍在等待结果；
- 我展开一个节点后，后续流式更新不会把它自动收起或滚走；
- 刷新、切换会话、网络重连后，内容顺序、展开状态和阅读位置仍然可恢复。

## 3. 目标信息架构

单个 task 在消息流中是一个稳定的执行组，但组内是有序节点流：

```text
用户消息
助手执行组
  ├─ 状态：已接收任务
  ├─ Think · 正在分析 ……                     [折叠]
  ├─ Tool · search · query=...                 [折叠]
  │    └─ OUT                                    [展开后显示]
  ├─ Think · 正在规划下一步                     [展开]
  ├─ 助手正文（流式累计）
  ├─ Usage · 1,240 input / 320 output tokens   [折叠]
  └─ 状态：已完成
```

### 3.1 节点层级

| 层级 | 默认显示 | 节点类型 | 说明 |
| --- | --- | --- | --- |
| L0 | 始终显示 | user / assistant text | 正常聊天内容，Markdown 渲染 |
| L1 | 始终显示一行 | status / thinking / tool / usage / error | 时间线摘要、状态点、更新中的简短预览 |
| L2 | 用户展开 | reasoning detail / tool input-output / usage payload / unknown payload | 原始安全化文本，内部滚动，不撑爆页面 |
| L3 | 权限控制 | provider diagnostics、trace、原始 stderr | 默认不进入 IM；仅诊断入口可见 |

### 3.2 默认展开策略

- **运行中的最后一个节点**：显示摘要，正文详情默认收起；reasoning 和工具行使用轻量 sweep，不使用持续旋转大图标。
- **已完成 reasoning/tool/usage**：默认收起，保留一行摘要和状态点。
- **error**：默认展开第一段安全化错误，详细 payload 仍需用户点击。
- **用户主动展开**：只对该稳定 node key 生效；后续 delta 更新内容，不改变 open 状态。
- **用户主动收起**：即使该节点仍在流式更新，也不自动重新打开。
- **未知事件**：默认以“运行时事件 · type”显示，详情可展开，不能静默丢弃。

### 3.3 正文与 reasoning

- 助手正文按 block 顺序实时追加；每次增量只替换对应 block 的文本引用。
- reasoning 与正文始终是不同节点，不能把 reasoning 当作正文前缀或从正文中去重。
- reasoning 的摘要使用已完成时第一行、运行中时最后一行；摘要过长横向截断但详情保留完整换行文本。
- 只渲染 Harness 协议已报告的 reasoning；产品文案明确“思考过程”或“运行时推理”，不声称是模型全部内部思维。

### 3.4 工具调用

- `tool_use` 先创建 running 节点；`tool_result` 通过 `refId` 精确更新同一节点。
- 没有匹配的 `tool_use` 时，创建独立 completed result 节点，禁止丢弃输出。
- 输入和输出分为 `IN` / `OUT` 两块，分别限制内部滚动高度；长文本保留复制能力。
- 超大输入/输出先展示安全预览，并明确显示总字节数、是否截断和“继续加载/查看完整输出”；完整内容按游标懒加载或通过受权下载获取，禁止静默截断。
- 工具名称、路径、查询词等摘要字段只做安全截断；完整 JSON 仅在展开详情中显示。
- 未来有 sub-call 时，节点模型保留 `parentRefId`，UI 使用递归缩进；首期没有父子关系时按平面序列显示。

## 4. 实时行为

### 4.1 更新节奏

- 服务端每条持久化 task message 产生一个单调 `seq`。
- 客户端收到失效通知后拉取 `afterSeq` 增量；首次加载使用 snapshot + `lastSeq`。
- React 状态更新按 `requestAnimationFrame` 合并，目标最多每帧一次；后台 tab 降级为定时批量刷新。
- 流式追加时只更新对应 node，不重建整个频道列表。

### 4.2 滚动规则

- 用户距底部小于 24px 时，新的节点和正文增量自动跟随底部。
- 用户向上阅读后，不抢夺滚动位置；显示“有新输出”按钮，点击才回到底部。
- 展开一个长详情不会把用户拉到底部；详情内部滚动。
- 切换 conversation 时保存 `conversationId -> anchorNodeKey + offset + followMode`，与现有 [conversation-scroll-anchors.ts](../../../apps/web/features/chat/conversation-scroll-anchors.ts) 兼容迁移。

### 4.3 状态播报

- `aria-live="polite"` 只播报任务开始、需要审批、错误、完成等高关注状态。
- token/delta、普通工具更新、usage 更新不抢焦点、不播报每次变化。
- 状态不能只靠颜色表达，同时使用图标、文本和状态属性。

## 5. 视觉与动效方向

- 沿用 AgentSpace 当前 tokens、圆角和 AppIcon，避免引入一套独立 DeepSeek 皮肤。
- 参考 Harness 的 quiet disclosure row：单行标题 + 分隔点 + 摘要 + chevron；点击整行展开。
- 运行中行采用 2.6s 左右的低干扰 sweep；支持 `prefers-reduced-motion`，禁用后保留静态状态。
- 详情面板使用浅色代码表面、`IN/OUT` gutter、内部最大高度、分段加载和可复制文本；不使用嵌套卡片。
- 消息列保持当前窄屏约束，所有按钮和摘要允许换行或省略，不产生横向滚动。

## 6. 非目标

- 不展示没有被 Harness/daemon 事件协议报告的隐藏 chain-of-thought。
- 不把每个 delta 变成可持久化聊天消息或通知。
- 不在本轮引入虚拟列表；先以稳定节点、局部订阅和内部滚动控制性能。
- 不重做 IM 左侧员工/历史会话信息架构，不改变 Conversation URL 契约。
