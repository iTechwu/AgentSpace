# MCP 市场分类与筛选模型

> 状态：Proposed
>
> 目标：提供稳定、可运营、可分享的 MCP 发现体验，同时不把分类误用为安全授权。

## 1. 设计结论

市场采用“一个主分类 + 多个辅助分类 + 独立 facet”模型：

- 分类回答“这个 MCP 主要帮助完成什么工作”；
- facet 回答“来源、传输、认证、风险、数据域、兼容性和连接状态是什么”；
- 搜索回答“名称、描述、工具和别名是否匹配”；
- 排序回答“哪个结果更值得先看”。

分类绑定 `package`，不绑定 release。release 改变执行 policy，分类改变发现投影，两者必须解耦。

## 2. 分类法 v1

一级分类保持 8 至 12 个，v1 建议：

| key | 中文 | 英文 | 示例能力 |
| --- | --- | --- | --- |
| `developer_tools` | 开发工具 | Developer tools | 代码、Issue、CI、制品 |
| `data_analytics` | 数据与分析 | Data & analytics | SQL、BI、指标、数据仓库 |
| `productivity` | 效率与协作 | Productivity | 文档、知识库、项目管理 |
| `communication` | 沟通 | Communication | 邮件、消息、会议 |
| `sales_crm` | 销售与客户 | Sales & CRM | CRM、线索、客服 |
| `finance_ops` | 财务与运营 | Finance & operations | 财务、采购、ERP |
| `content_media` | 内容与媒体 | Content & media | CMS、设计、媒体处理 |
| `web_automation` | Web 与自动化 | Web & automation | 浏览器、抓取、工作流 |
| `infrastructure` | 基础设施 | Infrastructure | 云、监控、数据库运维 |
| `ai_model_tools` | AI 与模型工具 | AI & model tools | 模型、向量、评测 |
| `other` | 其他 | Other | 尚未归类 |

二级分类按需启用，最多两层。禁止无限树深度和发布者自造一级 key。

## 3. 数据模型

```sql
CREATE TABLE mcp_market_category (
  id TEXT PRIMARY KEY,
  key TEXT NOT NULL UNIQUE,
  parent_id TEXT REFERENCES mcp_market_category(id),
  label_zh TEXT NOT NULL,
  label_en TEXT NOT NULL,
  description_zh TEXT NOT NULL DEFAULT '',
  description_en TEXT NOT NULL DEFAULT '',
  icon_key TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL,                 -- active | hidden | retired
  taxonomy_version INTEGER NOT NULL,
  created_at TIMESTAMPTZ NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL
);

CREATE TABLE mcp_package_category_assignment (
  package_id TEXT NOT NULL REFERENCES mcp_catalog_package(id),
  category_id TEXT NOT NULL REFERENCES mcp_market_category(id),
  assignment_type TEXT NOT NULL,        -- primary | secondary
  assigned_by TEXT NOT NULL,            -- platform | reviewer | workspace_admin
  confidence NUMERIC(4,3),
  reviewed_by_user_id TEXT,
  reviewed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL,
  PRIMARY KEY(package_id, category_id)
);

CREATE UNIQUE INDEX uq_mcp_package_primary_category
  ON mcp_package_category_assignment(package_id)
  WHERE assignment_type = 'primary';
```

规则：

- 每个可见 package 恰好一个 active primary category；
- secondary category 最多 3 个；
- `official/verified_partner` 由平台 reviewer 决定；
- `workspace_private` 可由 workspace admin 分类，但默认 `other`，并记录 actor；
- 删除分类使用 retired + replacement key，不物理删除历史 assignment。

## 4. Facet 模型

不要把以下维度塞进分类树：

| facet | 值来源 | 是否安全决策 |
| --- | --- | --- |
| `source` | package | 否，展示/筛选 |
| `transport` | selected release | 是，连接资格另行判断 |
| `auth` | selected release | 是，决定配置/OAuth 流程 |
| `risk` | selected release/tool | 是，决定确认和审批 |
| `data_domain` | selected release | 是，告知数据边界 |
| `runtime_compatibility` | release + runtime capabilities | 是，决定是否可连接 |
| `connection_state` | workspace runtime connection | 是，决定操作状态 |
| `health` | connection | 是，决定能否进入任务 |
| `publisher` | package | 否，展示/筛选 |
| `category` | package assignment | 否，只影响发现 |

市场 loader 应返回服务端归一化后的 facet，不让浏览器重新解释 manifest JSON。

## 5. 查询契约

建议 URL：

```text
/market?tab=mcp&q=github&category=developer_tools
  &source=official,verified_partner
  &transport=streamable_http
  &auth=oauth
  &risk=low,medium
  &compatibility=compatible
  &connection=not_connected
  &runtime=<runtimeId>
  &sort=relevance
```

规则：

- 同一 facet 多值为 OR，不同 facet 之间为 AND；
- 未知 key 忽略并返回规范化 URL，不产生 500；
- `q` 最大 100 字符，服务端归一化空白和大小写；
- facet value 数量和总 URL 长度有限制；
- URL 是状态来源，浏览器前进/后退必须复现筛选；
- 结果计数由服务端计算，避免前端拿 1000 条后产生错误计数。

接口：

```http
GET /api/workspaces/:workspaceId/mcp-market
  ?q=&category=&source=&transport=&auth=&risk=
  &compatibility=&connection=&runtimeId=&sort=&cursor=&limit=
```

响应：

```ts
interface McpMarketSearchResponse {
  items: McpMarketPackageSummary[];
  facets: Record<string, Array<{ key: string; label: string; count: number }>>;
  pageInfo: { nextCursor?: string; totalApproximate: number };
  normalizedQuery: Record<string, string[]>;
  taxonomyVersion: number;
  catalogRevision: string;
}
```

## 6. 搜索投影

每个 package 建立非敏感搜索文档：

```ts
interface McpMarketSearchDocument {
  packageId: string;
  displayName: string;
  slug: string;
  summary: string;
  aliases: string[];
  primaryCategory: string;
  secondaryCategories: string[];
  declaredToolNames: string[];
  declaredToolDescriptions: string[];
  dataDomains: string[];
  publisherName?: string;
  selectedReleaseId: string;
  selectedReleaseVersion: string;
}
```

不得索引 endpoint、header 名、secret field 值、workspace 私有配置、OAuth token、工具输入输出。私有 package 的索引必须带 workspace ACL，不能依赖结果返回后再过滤。

首期可使用 PostgreSQL 现有查询能力；规模和相关性指标证明需要后再引入独立搜索服务。不得为了分类筛选预先增加新的 Redis/Elasticsearch 部署依赖。

## 7. “默认 release”选择

市场列表展示 package，但必须明确它将连接到哪个 release：

1. 仅考虑 `published` 且未 yanked 的 release；
2. 按目标 Runtime capabilities 过滤；
3. 无 Runtime 上下文时展示平台 `recommended_release_id`；
4. 有 Runtime 上下文时选择最高的兼容推荐 release；
5. 如果没有兼容 release，仍可展示，但标记“不兼容”，不可点击连接；
6. 已连接 package 默认展示当前 pinned version 与可升级提示，不把推荐版冒充当前版。

## 8. 排序

支持：

- `relevance`：文本相关性为主；
- `recommended`：平台审核推荐与兼容性为主；
- `name`：稳定字典序；
- `recently_published`：release 发布时间；
- `recently_used`：仅工作区内、经最小样本阈值处理的使用信息。

不能使用敏感工具调用内容、个人身份或原始 OAuth scope 做推荐。连接数/使用量不能覆盖 risk、compatibility 和 yanked gate。

## 9. UI 行为

- 桌面：左侧搜索和 facet，右侧 package 列表/详情；移动端 facet 使用 drawer；
- 分类使用单选主入口，其他 facet 使用多选 checkbox；
- 已选筛选显示可移除 chips，并有“清除全部”；
- 每个结果显示主分类、来源、风险、认证类型、兼容性和 pinned/recommended version；
- 0 结果说明是哪些条件共同造成，并允许逐个移除；
- 分类 label 本地化，但 URL/API 永远使用稳定 key；
- retired 分类 URL 跳转 replacement，并保留一次兼容周期。

## 10. 治理与审计

分类变更记录：package、旧分类、新分类、actor、原因、taxonomy version、时间。批量重分类先 dry-run，输出影响数量和抽样，审批后执行。

质量指标：

- `other` 占比；
- 无 primary category 的阻断数量；
- 分类筛选使用率与 0 结果率；
- 搜索后连接转化率；
- 每个分类的误分类反馈；
- taxonomy 变更造成的 URL 兼容问题。

## 11. 验收

- 所有可见 package 恰好一个主分类；
- 分类变更不改变 release digest、connection 状态或 task snapshot；
- 多 facet OR/AND 语义有服务端测试；
- URL 前进/后退、分享和刷新完全复现；
- workspace private 条目不会跨 workspace 计数或泄漏；
- runtime compatibility 与 connection status 由服务端事实计算；
- 大目录使用 cursor 分页，不再依赖前端加载 1000 项过滤；
- 中英文 label 不进入稳定 key，也不导致筛选链接失效。
