# 应用市场：MCP 中心与 CLI 市场 UI/UX 设计方案

## 1. 体验原则

1. **先判断影响，再执行连接。** MCP 的入口先说明数据域、Runtime、工具与风险，不能把“连接”伪装成普通安装。
2. **同一市场内清晰分区。** CLI 市场使用“安装/更新/卸载”；MCP 市场使用“配置/验证/启用/停用/移除”。两个 Tab 不混排资源或操作语义。
3. **状态可解释。** 所有状态同时显示文字、图标和下一步；颜色不是唯一编码。
4. **秘密不可见但可维护。** 显示“已配置、更新时间、更新者”，不显示旧值或可复制密钥。
5. **渐进披露。** 目录页用于比较，详情用于决策，连接向导才显示必需字段和高级网络信息。

## 2. 信息架构与导航

```text
管理
└─ 应用市场
   ├─ Tab：CLI 市场
   │  └─ CLI Hub 目录 / 已安装应用 / 操作记录
   └─ Tab：MCP 市场（MCP 中心）
      ├─ 服务目录
      ├─ 已连接服务
      └─ Runtime 连接详情
         ├─ 概览
         ├─ 工具
         ├─ 配置
         └─ 活动
```

- `/market` 是唯一入口，页面标题为“应用市场”；`?tab=cli` 与 `?tab=mcp` 支持直达、刷新和浏览器返回，默认 `cli`。
- 页面标题下方固定显示 `CLI 市场` / `MCP 市场` Tab；MCP Tab 的页内标题是“MCP 中心”，有异常连接时显示简短的“需要处理 N 项”入口。
- Runtime 详情的扩展区域显示独立分组：`已安装 CLI (n)` 与 `已连接 MCP (n)`，点击 MCP 跳转至对应连接详情。
- 宽屏采用目录列表 `320px` + 详情弹性区；窄屏先列表、选中后全屏详情，向导为全屏单列步骤页。

## 3. 页面规格

### 3.1 应用市场框架与 CLI 市场 Tab

应用市场沿用当前三栏工作台。顶栏的两个 Tab 固定高度、键盘可切换且不随内容滚动；CLI 市场 Tab 继续使用现有操作能力。

| 区域 | 变更 |
| --- | --- |
| 页面标题 | `CLI 市场`；副标题说明“为 Runtime 安装受控命令行应用” |
| 目录来源 | 保留 `CLI-Anything Hub`、public/harness 的来源标识 |
| 主按钮 | `安装`、`更新`、`卸载`、`同步 Skill`，不出现“连接”或 MCP 文案 |
| Runtime 选择 | 仍显示 cli-hub readiness，必要时说明会 bootstrap |
| 空状态 | “尚未安装 CLI 应用”，不使用泛化的“应用”术语 |

### 3.2 MCP 市场 Tab：MCP 中心目录

```text
应用市场 / MCP 市场                            [已连接服务 (3)]
MCP 中心
连接经过审核的 MCP 服务到 Docker Runtime

[ 搜索服务、工具或数据域 __________________ ] [传输 v] [风险 v]

服务目录                         服务详情
GitHub MCP      已连接 2          GitHub MCP     [已审核] [中风险]
Notion MCP      未连接            访问仓库、Issue 与 Pull Request
PostgreSQL MCP  需要处理          
                                  Streamable HTTP   12 个声明工具
                                  数据域 GitHub Organization
                                  网络 github-mcp.example.com:443
                                  [选择 Runtime 并连接]
```

列表行：左侧服务图标/来源标记，主行名称和描述，次行传输与工具数，右侧是与当前工作区相关的连接状态。风险使用文字 chip 并配合说明，不把红黄绿圆点作为唯一信息。

详情首屏固定展示：服务描述、审核来源、传输、数据域、允许网络目标、声明工具数、风险说明、文档链接和主操作。完整 endpoint 模板、schema、技术元数据放在“查看技术详情”折叠区，默认不抢占视觉层级。

### 3.3 连接向导

```text
连接 GitHub MCP
1 选择 Runtime  ---  2 配置  ---  3 工具范围  ---  4 验证并启用

目标 Runtime
  ( ) Runtime A - Codex       在线 · 网络兼容
  ( ) Runtime B - Claude      离线 · 不可选择

                                        [取消] [下一步]
```

| 步骤 | 控件与内容 | 校验和反馈 |
| --- | --- | --- |
| 选择 Runtime | 单选列表，显示 provider、在线状态、网络兼容性、现有连接数 | 离线或策略不兼容项可见但禁用，并显示原因 |
| 配置 | 按 schema 分组的输入；机密使用密码框；固定 endpoint 用只读信息 | 行内验证；密钥提示“保存后不会显示”；无效 host 在提交前阻断 |
| 工具范围 | 分组 checkbox；每项显示名称、描述、风险；提供“仅推荐工具” | 默认最小范围；高风险工具勾选出现原因确认 |
| 验证并启用 | 只读摘要：Runtime、外发 host、配置字段名、工具数、数据域、风险 | 提交后创建异步操作，进入进度屏，不假装同步成功 |

向导应保存非密钥草稿以处理验证失败返回；密钥输入在失败后清空并提示重新输入，不能存入浏览器本地存储。

### 3.4 已连接服务与连接详情

连接详情顶部：名称、目标 Runtime、状态 chip、上次验证、主操作。Tabs 如下：

| Tab | 默认内容 | 主要操作 |
| --- | --- | --- |
| 概览 | 数据域、传输、工具数、健康、最近失败摘要 | 重新验证、停用 |
| 工具 | 发现工具列表，显示“已获准/未获准/不可用” | 修改范围（触发重新验证） |
| 配置 | 脱敏字段状态、endpoint 摘要、最近轮换时间 | 更新非密钥字段、轮换密钥 |
| 活动 | 最近验证和工具调用的时间、结果、时延、脱敏摘要 | 查看完整的脱敏事件详情 |

`disabled` 以中性状态显示“已停用，不会提供给新任务”；`degraded` 和 `failed` 以高优先级警示块显示原因和“重新验证/管理配置”动作；`verifying` 显示固定宽度进度与阶段文本，避免状态跳动。

## 4. 状态、文案与错误恢复

| 状态 | 文案 | 视觉 | 默认操作 |
| --- | --- | --- | --- |
| 未连接 | 尚未连接到 Runtime | 中性 | 选择 Runtime 并连接 |
| 需配置 | 缺少必填配置或密钥 | 警告 | 管理配置 |
| 验证中 | 正在从目标 Runtime 验证连接 | 进行中图标 | 查看进度 |
| 已就绪 | 最近验证成功，可向任务提供 N 个工具 | 成功 | 查看工具、重新验证 |
| 需要处理 | 最近检查或调用失败，当前不提供给新任务 | 危险 | 重新验证、管理配置 |
| 已停用 | 管理员已停止此连接 | 中性 | 启用、移除 |

错误消息使用“发生了什么 + 影响 + 下一步”的结构，例如：

```text
无法验证连接
目标 Runtime 无法连接到允许的服务地址，因此此 MCP 不会提供给新任务。
检查网络策略或服务可用性，然后重新验证。
```

禁止将原始 Authorization、Cookie、完整 URL query、命令行、密钥、MCP payload 或堆栈直接作为可见文案。技术详情仅显示稳定错误码、请求阶段、时间和已脱敏摘要。

## 5. 组件与交互规格

| 组件 | 规格 |
| --- | --- |
| `McpServiceRow` | 整行可点击；固定两行文本高度；状态 chip 不改变行高；支持键盘 Enter/Space |
| `McpConnectionWizard` | 4 步受控表单；上一步不丢非密钥字段；离开时询问是否放弃草稿 |
| `McpSecretField` | 密码输入，不提供“显示旧值”；保存后显示状态而非内容；支持轮换 |
| `McpToolScopeList` | checkbox + 风险标签；组级全选仅选低/中风险默认项，高风险需逐项确认 |
| `McpHealthStatus` | 图标、文字、时间三要素；使用 aria-live 宣告异步验证结果 |
| `McpActivityList` | 时间、事件、结果、时延、摘要；摘要溢出截断但可展开脱敏文本 |

按钮使用图标加文本表达明确命令；停止/移除使用破坏性样式并在确认对话框中说明“不会删除其他 Runtime 的连接”。卡片仅用于可重复的服务/连接条目，页面主体保持分栏工作台布局。

## 6. 可访问性与响应式

- 所有状态通过文本、图标和至少 AA 对比度表达；不能只依赖颜色。
- 向导使用 `aria-current="step"`，验证错误与异步状态通过 `aria-live="polite"` 反馈。
- 密钥字段的 label 必须明确说明用途和不回显策略；帮助文字与输入以 `aria-describedby` 关联。
- 键盘焦点按“筛选 -> 服务列表 -> 详情 -> 操作”稳定移动；弹窗打开后焦点锁定并可 Escape 关闭。
- `>=1280px` 固定三栏或列表+详情；`768-1279px` 缩为列表 280px + 详情；`<768px` 全屏列表/详情切换，底部固定主操作但不遮挡表单字段。

## 7. 可用性验证

在 MVP 上线前用 5-8 名目标管理员测试以下任务：

| 任务 | 成功标准 |
| --- | --- |
| 找到 GitHub MCP 并识别其访问范围 | 90% 参与者在 60 秒内说出数据域、风险和目标网络 |
| 将服务连接到指定 Runtime | 85% 完成率；不把“验证中”误认为“已可用” |
| 仅允许低风险工具 | 90% 正确保留默认工具且不误选高风险工具 |
| 处理认证失败 | 80% 能从错误页找到“管理配置/重新验证”并理解密钥不会回显 |
| 在应用市场内区分两个 Tab | 90% 能在正确 Tab 找到“安装 CLI”和“连接 MCP” |

记录完成率、耗时、错误数和访谈中的术语误解。若“安装/连接”或“已就绪/验证中”仍被混淆，优先修改导航和状态文案，再扩大目录内容。
