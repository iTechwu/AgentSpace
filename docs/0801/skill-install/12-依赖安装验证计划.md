- **probeMode 语义 + 按 runtime 逐镜像探测（2026-08-13，第二轮复审收口）**：catalog `binaries[]` 增 `probeMode`（`all`/`any`，默认 `all`）。`all` 须全部 binary 在位（ffmpeg/ffprobe、graphviz dot/neato、poppler pdftoppm/pdfinfo 等多工具套件整体校验）；`any` 任一即可（imagemagick convert/magick、chromium/chromium-browser、libreoffice/soffice 等同类异名）；单 binary 默认 `all`（平凡满足）。安装期 `verifySystemDependenciesInRunner` 从 `manifest.entrypoints` 收集 distinct runtime，对每个声明 runtime 镜像都解析+inspect+探测——任一 runtime 镜像缺二进制即 `blocked`，原因指明 `(runtime=<x>, image=<y>)`；无 entrypoints 回退 `["bash"]`。修复了「安装期写死 bash 镜像、执行期按各 runtime 解析」的探测/执行镜像不一致，以及多 binary 用 `some()` 把部分安装当完整的问题。
- **受审批 egress capability（2026-08-13）**：Runner 默认 `--network none`，`system:curl` 仅证明存在不证明联网。需出站的 Skill 在 manifest 声明 `network.egressAllowlist`（主机名白名单），经 `buildSkillInstallRiskItemsSync` 产出 egress 风险项并绑定 first-install 审批（`riskDecisionDigest`）；任务期快照解析用 `releaseLockDigest` + 重导 digest 经 `readSkillInstallApprovalByLockSync` 重验审批，命中即把已批准白名单 stamp 到 `TaskSkillExecutionSnapshotEntry.egressAllowlist` → `DaemonSkillRunnerEntrypoint.egressAllowlist` → `buildSkillRunnerDockerArgs` 的 networkArgs（DNS 投毒 `--dns 192.0.2.1` + `/etc/hosts` `--add-host` 白名单钉，复用 managed-service 纯函数；**不做 iptables L3/L4**，硬编码 IP 可绕过 DNS 为已知限制）。未审批 → egress 组件 `blocked`（`skill_installation.egress_not_approved`），运行期即 `--network none`。

## 背景（为什么做）

`docs/0801/skill-install/07-实施差距审查.md` P0-2 + 用户审查：**npm/Python 依赖未实际安装验证**——skill-install worker 的 `dependency` component 仅凭 manifest 声明 + 非空 version 即返回 ready，从未在 Runtime 隔离环境安装包或验证版本/入口。设计意图（02-架构设计 §4.1）：依赖放入专属 envs 目录（不写 Provider HOME/宿主机/全局 path）；install 命令来自 planner 生成的 argument array + 精确版本 + allow-listed registry；完成后跑独立 verify command 写 component status。

现状（已核实）：
- `@dofe-agent/sandbox` 提供 `exec(ExecCommand)`（timeoutMs/env/cwd/stdio 流，local = 裸 spawn、cube exec 是 stub，TODO 46）。
- 已有 `buildSkillDependencyInstallPlan`（`dependency-install.ts:184-233`）生成命令计划（npm `--global`、pip `--user`、uv tool install）——**违反设计**（写 Provider HOME/全局 path），且经 `runtime-apps.ts:96-130` 裸 spawn 执行（无 sandbox/timeout）。这是另一条路径（GitHub 依赖），与 skill-install worker 无关。**（历史现状：该路径已在依赖安装落地时一并加固为隔离 `deps/npm`/`deps/pip` 目录 + registry 固定 + `execCommand` 超时/env 精简，见上方 ✅ 实现状态。）**
- worker 的 `verifyDependencyComponent`（`component-verifier.ts:97-122`）声明+版本 → ready。

## 目标

1. 在 skill-install worker 的 materialize 与 verify 之间插入**真实依赖安装步骤**：planner 从 manifest 生成命令（npm/pip/uv，精确版本，`--prefix`/`--target` 指向隔离 envs 目录，绝不 `--global`/`--user`），经 sandbox `exec` 执行（timeout、精简 env、脱敏输出）。
2. **registry allow-list**：平台配置（npmjs.org / pypi.org 默认 + env 覆盖），命令强制 `--registry`/`--index-url` 指向白名单，绝不信任 manifest 内嵌 registry。
3. **install 后独立 verify**：`npm ls name@version` / `pip show` + 版本比对 / `uv pip show`；只有 verify 通过 dependency component 才 `ready`，否则 `blocked`/`failed`（带原因）。
4. **envs 目录隔离**：`<stateDir>/<workspace>/remote-workdirs/skill-install-envs/<installationId>`（每次 prepare 清空重建，保证无陈旧版本）；`HOME`/`NPM_CONFIG_CACHE`/`PIP_CACHE_DIR` 指向 envs 目录。

## 关键决策（已定）

- **命令生成（planner）**：
  - npm: `["npm","install","--prefix",envsDir,"--ignore-scripts","--no-audit","--no-fund","--registry",registry,"<name>@<version>"]`
  - pip: `["python","-m","pip","install","--target",envsDir,"--no-deps","--no-input","--disable-pip-version-check","--only-binary",":all:","--index-url",registry,"<name>==<version>"]`
  - uv: `["uv","pip","install","--target",envsDir,"--no-deps","--index-url",registry,"<name>==<version>"]`
  - verify：npm `["npm","ls","--prefix",envsDir,"<name>@<version>"]`；pip/uv `["python","-m","pip","show","<name>"]`/`["uv","pip","show","<name>"]` + 输出版本比对。
- **registry allow-list**：`DEFAULT_NPM_REGISTRY=https://registry.npmjs.org`、`DEFAULT_PYPI_INDEX_URL=https://pypi.org/simple`，env 覆盖 `DOFE_AGENT_NPM_REGISTRY`/`DOFE_AGENT_PYPI_INDEX_URL`。planner 只接受 allow-list registry；无 manifest registry 信任。
- **env 精简**：仅传 `PATH` + `HOME=envsDir` + `NPM_CONFIG_CACHE=envsDir/.npm-cache` + `PIP_CACHE_DIR=envsDir/.pip-cache`；剥离全部密钥（`DOFE_AGENT_*`、credential、provider env）。
- **执行器**：sandbox `exec`（timeoutMs=10min/install、5min/verify），stdout/stderr tail + 脱敏（复用 `SECRET_PATTERNS` 模式），非零退出/超时 → 组件 `failed`。
- **失败语义**：任一依赖安装/verify 失败 → 该 dependency component `failed`（errorCode `skill_installation.dependency_install_failed` + 脱敏原因）；`allReady` 门自然阻止 installation ready。
