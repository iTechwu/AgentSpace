# UI/UX 设计：Skill Library 与安装工作流

## 1. 信息架构

```text
管理
├─ Skills
│  ├─ Skill Library
│  ├─ 已安装到 Runtime
│  ├─ 导入记录
│  └─ Skill 详情
│     ├─ 概览
│     ├─ 文件
│     ├─ 能力与依赖
│     ├─ 支撑服务
│     ├─ Runtime 安装
│     ├─ 员工分配
│     └─ 历史与审计
└─ 应用市场
   ├─ CLI 市场
   └─ MCP 市场
```

Skills 负责包和分配；应用市场保留 CLI/MCP 的运行时资源管理。Skill 页面只能跳转或嵌入“选择现有 Runtime capability”的选择器，不能复制出另一套连接密钥或 CLI 安装界面。

## 2. Skill Library

宽屏采用筛选栏、Skill 列表、详情三栏；移动端在列表与详情之间全屏切换。列表每行固定显示名称、版本/digest 短码、来源、风险、分配数和聚合状态。状态使用图标、文字和时间，颜色不是唯一编码。

筛选项：来源、内容形态（指令/脚本/assets/依赖/CLI/MCP）、信任级别、风险、安装状态、目标 Runtime、员工。搜索同时匹配名称、描述、作者、能力和文件路径，但不索引密钥或文件正文。

主操作是带下载图标的“添加 Skill”；详情中的命令使用图标加文本：检查、安装、激活、重新验证、升级、回滚、移除。删除和停用是破坏性操作，必须说明影响范围。

## 3. 五步安装向导

```text
添加 Skill
1 来源  ->  2 检查  ->  3 Runtime  ->  4 配置与授权  ->  5 安装并激活
```

| 步骤 | 用户输入与界面 | 系统反馈 |
| --- | --- | --- |
| 来源 | 分段选择：链接、上传 ZIP、目录、市场/Runtime 产物；提供 SHA/版本可选输入 | 显示支持格式；链接未锁定时提示将解析为不可变版本 |
| 检查 | 只读文件树、大小、哈希、依赖、脚本、CLI/MCP capability、许可证和风险 | 可展开 warning；不支持或丢失文件直接阻断，不显示“导入成功” |
| Runtime | 单选可见 Runtime，显示 Provider、在线、架构、现有 cache、网络/CLI/MCP/服务兼容性 | 不兼容项禁用并说明原因；无 Runtime 可先仅保存 artifact |
| 配置与授权 | 根据 schema 的表单；密钥使用密码输入；checkbox 逐项授予脚本网络、写入、CLI/MCP 工具 | 显示权限将授予的对象、期限与影响；高风险必须二次确认 |
| 安装并激活 | 汇总 artifact digest、文件数、安装组件、服务 revision、员工和回滚点 | 异步进度：下载、准备依赖、部署/绑定服务、验证能力、激活；失败提供“修复配置/重试” |

向导允许在检查后保存草稿，但不保存密钥到浏览器。离开时提示“保存草稿/放弃”。安装进行中可安全关闭页面；重新进入详情会恢复服务器端 operation 状态。

## 4. 详情页与状态

### 4.1 概览与文件

概览顶部显示 `ready / preparing / blocked / degraded / retired`，副文本回答“此 Skill 是否会进入新任务”。文件页使用可展开树，显示类型、大小、哈希短码和 mode；二进制仅展示元数据或安全预览。脚本行有终端图标和 entrypoint 标签，不能在浏览器直接执行。

### 4.2 能力与依赖

表格将每个 component 拆开显示：包完整性、npm/Python/系统依赖、CLI、脚本 runner、MCP connection。每行包含状态、目标 Runtime、最近验证、影响、下一操作。避免把 `MCP 已配置` 与 `MCP 工具已可用` 混成同一状态。

### 4.3 Runtime 安装与员工分配

Runtime 安装页按 Runtime 展示 digest、准备目录的抽象标识、component 状态、错误码和最近 operation。员工分配页只允许选择该员工绑定 Runtime 上 `ready` 的 installation；若配置变化导致 degraded，分配保持可见但明确标记“不会进入新任务”。

### 4.4 支撑服务与版本历史

支撑服务页显示 service catalog 名称、作用域、当前 image digest、资源 profile、健康、最近变更和依赖该服务的 Skill 数。管理员只能选择“创建受管实例”“绑定已有实例”“重新验证”“升级”“回滚”“停用”；镜像、端口、网络和外部数据依赖在“运维详情”中只读展示。服务升级必须先展示服务版本、配置 schema、数据迁移和回滚能力，再进入 canary 选择。

版本历史以 release revision 为主行，展开后显示 artifact、依赖、服务、MCP tools 和配置 schema 的锁定值。diff 使用“内容、执行、网络与权限、服务、配置”五类分组；任何风险变化置顶并标记“需重新批准”。

## 5. 关键状态文案

| 状态 | 用户可见文案 | 默认操作 |
| --- | --- | --- |
| 检查中 | 正在检查文件、依赖和能力；尚未安装 | 等待或取消 |
| 需批准 | 此 Skill 请求执行脚本或访问外部能力，尚未授予 | 查看影响并批准/拒绝 |
| 准备中 | 正在目标 Runtime 准备环境，暂不会进入任务 | 查看阶段与日志摘要 |
| 需配置 | 缺少配置、密钥、CLI 或 MCP 连接 | 管理配置 |
| 已就绪 | 所有必需组件已验证，可用于新任务 | 激活/查看能力 |
| 已降级 | 依赖、脚本或连接不再满足要求；新任务不会使用它 | 重新验证/回滚 |

错误使用“发生什么、造成什么影响、如何修复”三段式。示例：`Git revision 已不可访问。现有任务仍固定使用已安装 artifact，但不能升级。请选择新的 commit 或回滚到已验证版本。` 不显示 token、完整 Authorization、原始命令或未脱敏第三方响应。

## 6. 组件与可访问性

| 组件 | 规格 |
| --- | --- |
| `SkillSourcePicker` | 图标分段控件；来源切换不清除已输入草稿，改变类型时显式确认 |
| `SkillInspectionPanel` | 稳定高度的摘要行与可展开文件树；warning 可复制安全错误码 |
| `CapabilityGrantList` | checkbox + 风险 + 影响；高风险逐项确认，默认最小范围 |
| `InstallationTimeline` | 固定宽度阶段、时间和结果；`aria-live=polite` 汇报异步变化 |
| `ArtifactDiff` | 文件/权限/依赖/capability 四种 diff 分类；危险变化置顶 |
| `SecretField` | 仅输入和轮换；保存后显示配置状态、时间和更新者，永不回显旧值 |

所有表单 label 与帮助信息通过 `aria-describedby` 关联；向导用 `aria-current=step`；键盘顺序为来源/检查/Runtime/授权/提交；窄屏底部主操作固定但不遮挡错误和输入。文本、状态与图标须满足 WCAG AA，文件树与组件状态不依赖颜色。

## 7. 可用性测试

招募 5-8 名有 Runtime 管理权限的目标用户，至少包含首次使用者和已有 MCP/CLI 使用者。测试任务：导入含 `.mjs` 与二进制模板的 ZIP；将含 Python 依赖的 Skill 安装到 Remote Runtime；绑定需要 GitHub MCP 的 Skill；处理依赖安装失败；比较升级 diff 并回滚。

成功标准：核心任务完成率至少 85%；90% 参与者能区分“已保存包”“准备中”“已就绪”；0 名参与者误以为密钥会嵌入包；高风险能力误授权为 0。记录完成时长、错误次数、术语误解和 SUS，低于 68 分前不扩大来源覆盖面。
