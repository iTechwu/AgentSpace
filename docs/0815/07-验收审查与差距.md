## 三、剩余风险

### P1：`all-compatible` 仍缺真实 Runtime 能力注册与完整验收

`computeSkillRolloutTargetRuntimesSync({ kind: "all-compatible" })` 现在按版本化的
`metadata.runtimeCapabilities`（`schemaVersion/gpu/egress/mcp/cli`）与 Skill manifest 的
`runtimeRequirements`、network、MCP/CLI 声明进行匹配；缺少能力声明或全不匹配时
fail-closed，相关 rollout 测试已覆盖。daemon/runtime 注册端现在会拒绝非法快照并规范化
合法快照；剩余工作是补充能力来源证明，以及真实 Runtime 的 GPU/egress/MCP/CLI 跨环境验收。

### P1：dispatch 失败仍缺持久化 reconcile 状态机

`SkillRolloutDispatchError` 已返回 `planId`、`planDigest` 和已创建安装列表，finalize
失败也会 fail-closed；但中途失败、重复 reconcile、并发 reconcile 尚未持久化为每项
`pending/created/failed` 状态，恢复仍依赖调用方上下文。

### P2：质量报告摘要尚未绑定完整报告和权限

领域 parser 已严格校验 `quality-report.json`；coordinator 现在从完成节点的 artifact
manifest 读取 `quality-report` envelope，校验 digest、Workspace、schema version、subject
和 checks，并要求摘要 blockingCount 与完整报告一致。审批权限审计和报告来源证明仍需补齐。

### P1/P2：Prisma 与 PostgreSQL 仍有 invariant 缺口

contract gate 已覆盖列、主键、unique/index 和 FK/onDelete；check constraint、enum、
partial index、trigger、function、view 仍需独立的 PostgreSQL invariant gate。在线命令
必须在 CI/测试数据库中执行，当前本地未伪造在线结果。
