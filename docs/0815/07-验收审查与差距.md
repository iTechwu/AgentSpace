## 三、剩余风险

### P1：`all-compatible` 仍缺 Runtime 能力过滤

`computeSkillRolloutTargetRuntimesSync({ kind: "all-compatible" })` 当前只能按
`status = 'online'` 选取 Runtime。Runtime metadata 尚未形成 GPU、egress、MCP/CLI 的
稳定能力 schema，因此不能安全地宣称能力过滤已完成。应先定义版本化 capability contract，
再按 Skill manifest 需求 fail-closed 过滤，并覆盖“在线但不匹配”和“全部不匹配”测试。

### P1：dispatch 失败仍缺持久化 reconcile 状态机

`SkillRolloutDispatchError` 已返回 `planId`、`planDigest` 和已创建安装列表，finalize
失败也会 fail-closed；但中途失败、重复 reconcile、并发 reconcile 尚未持久化为每项
`pending/created/failed` 状态，恢复仍依赖调用方上下文。

### P2：质量报告摘要尚未绑定完整报告和权限

领域 parser 已严格校验 `quality-report.json`，coordinator 目前只校验
`qualityReportDigest` 非空，尚未读取 digest 对应的完整报告、校验 schema version、
subject/inputRefs 或 Workspace/审批权限。

### P1/P2：Prisma 与 PostgreSQL 仍有 invariant 缺口

contract gate 已覆盖列、主键、unique/index 和 FK/onDelete；check constraint、enum、
partial index、trigger、function、view 仍需独立的 PostgreSQL invariant gate。在线命令
必须在 CI/测试数据库中执行，当前本地未伪造在线结果。
