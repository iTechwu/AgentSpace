# 08 审批安全边界设计取舍（P1-2 / P1-3）

> 决策对象：07 审查中的 **P1-2（Rollout 审批可被重放，缺 planDigest/consumedAt 校验）** 与 **P1-3（skill_rollout_plan 缺 UNIQUE 唯一约束）**。
> 结论：**采用「非唯一 + 每次审批新建行 + consumedAt/planDigest 重放防护」**，与现有 `skill_install_approval` 的成熟模式对齐；推翻 04/05 文档里的 `UNIQUE(workspace_id, plan_digest)` DDL。

---

## 1. 问题与耦合

- **P1-3**：04/05 文档 DDL 指定 `UNIQUE(workspace_id, plan_digest)`；实现为「非唯一 + 每次审批新建一行」。
- **P1-2**：子安装只校验 plan 存在/批准/scope，不校验 `consumedAt` 与 `planDigest`；`consumeSkillRolloutPlanSync` 是死代码，已消费的批准计划仍可继续派发子安装。

两者耦合在同一个语义问题上：**一个 planDigest（内容哈希）到底对应「一次审批」还是「多次审批」**。

## 2. 核心矛盾（三角张力）

一个 `skill_rollout_plan` 需要同时满足三个诉求：

| 诉求 | 含义 | 倾向 |
| --- | --- | --- |
| 幂等 | 同一闭包 + 同一 Runtime 集合，重复规划应得到同一计划 | UNIQUE |
| 一次性 | 一次审批只授权一次 rollout，派发后不可重放 | consumedAt 门禁 |
| 可重新审批 | 同闭包再次 rollout（重装/重跑）需要一次**新的**审批 | 非唯一 |

UNIQUE 直接给「幂等」却与「可重新审批」冲突：被消费后同一 planDigest 无法再建新行。

## 3. 方案对比

### 方案 A：UNIQUE(workspace_id, plan_digest) —— 一个内容 = 一行

- 幂等：天然（`ON CONFLICT DO NOTHING`）。
- 重新审批：被消费后同 planDigest 无法新建，必须「重置」该行（清 consumed_at + 回退 decision=pending）。
- 缺点：① 重置会**抹掉上一次 rollout 的审计痕迹**；② 「同一内容被 rollout 了 3 次」无法用行表达，需要额外审计表。

### 方案 B：非唯一 + 每次审批新建行（当前实现方向）

- 幂等：由 **planner 层** 无状态实现（按 planDigest 复用「最新未消费」计划，无需 DB 唯一约束）。
- 重新审批：天然（新建一行，同一 planDigest 多行，各带独立 id/decision/consumedAt）。
- 一次性：`consumedAt` 门禁 + planDigest 反篡改。
- 审计：每次 rollout 一行，历史完整。

## 4. 推荐：方案 B

理由：

1. **可重新审批是硬需求**（重装/重跑）；方案 A 的「重置」破坏审计，不可接受。
2. **与 `skill_install_approval` 一致**：它已经是「非唯一 + 每次审批新建行 + consumedAt 重放防护」的成熟模式，镜像它可降低认知成本、复用已验证路径。
3. **幂等可在 planner 层无状态实现**：planDigest 本身就是内容寻址，无需 DB 唯一约束兜底。
4. **审计完整**：每次 rollout 一行，可追溯「同一闭包被批准并派发了多少次」。

## 5. 具体设计

### 5.1 Schema（保持不变）

`skill_rollout_plan` 保持非唯一；已有 `idx_skill_rollout_plan_digest(workspace_id, plan_digest, created_at DESC)` 用于「按内容取最新」。

### 5.2 planner 层幂等（随 G1 编排闭环落地）

`planSkillRollout` 计算 planDigest；新增 `resolveOrCreateSkillRolloutPlanSync`：存在「最新未消费」的同 planDigest 计划则复用，否则新建 pending 行。本任务不强制实现（它属于 G1 编排闭环），但重放防护与反篡改是 G1 的前置。

### 5.3 审批一次性

`decideSkillRolloutPlanSync`：`pending → approved|rejected`，一次性（已实现）。

### 5.4 重放防护（P1-2，本任务落地）

`createSkillInstallationPlanSync({ rolloutPlanId })` 校验**四关**：

1. `decision === "approved"`（已有）。
2. `consumedAt === null`（**新增**，拒绝已消费计划）。
3. **planDigest 反篡改**（**新增**）：从 plan 的 `closureJson/targetRuntimesJson/riskSummaryJson/rootArtifactDigest/policyVersion` 重算 digest，与 `plan.planDigest` 一致，否则拒绝（防止审批后篡改闭包/目标集合）。
4. scope 覆盖：artifact ∈ closure、runtime ∈ targetRuntimes（已有）。

### 5.5 一次性（consume，随 G1 编排闭环调用）

新增 `finalizeSkillRolloutPlanSync(planId)`：rollout 全部子安装派发完成后调用 `consumeSkillRolloutPlanSync` 置 consumedAt。本任务先落地该函数与「已消费拒绝」逻辑，调用点由 G1 接入。
