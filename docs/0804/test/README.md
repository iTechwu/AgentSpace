# K22 Runtime 与 AI 员工全链路测试方案

## 目的

本目录提供一套以测试管理员账号视角，在 **K22 tenant** 内从零新增两类 Runtime、配置能力、创建 AI 员工并完成真实任务的专项测试方案。主链路覆盖：

```text
SSO 登录并确认 K22
  -> 新增 Codex Runtime / Claude Code Runtime
  -> 为两个 Runtime 安装 CLI、连接 MCP
  -> 新增并安装共享 Skill
  -> 新增两名 AI 员工并分别绑定 Runtime + Skill
  -> 用同一任务分别执行
  -> 核对工具调用、产物、审计、成本和数据隔离
  -> 异常回归与清理
```

## 范围说明

本方案验证当前产品真实能力名称：

- Runtime 创建页中的“配置执行能力”，分别选择 `Codex` 与 `Claude Code`。
- Codex 使用 `openai_response` 协议，默认模型基线为 `gpt-5.6-terra`；Claude Code 使用 `anthropic` 协议，模型必须从实际兼容目录选择。
- “CLI 市场”把 Runtime App 安装到指定在线 Runtime。
- “MCP 服务”把目录能力连接到指定 Runtime，并限定批准工具和网络范围。
- Skill 必须安装到目标 Runtime 达到 `ready`，再绑定给 AI 员工；只在工作区技能库中存在不代表可执行。
- 任务由消息中向数字员工分配工作产生，并应在任务看板、执行时间线、审计和产物中形成一致闭环。

不包含生产部署、Jenkins、本地 PostgreSQL/Redis/RabbitMQ 部署或未经授权的外部资源写入。
