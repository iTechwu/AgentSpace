## 1. 结论

本轮已完成 P0、P1 与 P2 首期：CLI 安装资格和来源事实已修复，CLI/MCP 操作阶段可恢复，工作区私有 CLI 采用不可变 release，并可作为 managed stdio MCP 的显式安装依赖。

当前不再存在“由管理员填写未知本地命令”的私有 managed stdio 发布路径。剩余工作集中在 Runtime 下载后的 artifact integrity 二次校验，以及达到运营门槛后再启动的 P3 公共来源治理。

## 3. 规范符合性审查

### P0：必须先修复

| 差距 | 代码证据 | 风险 | 完成标准 |

## 4. 代码质量审查

本节只记录工程质量问题，不与规范缺失混算。

### 必须修复

- 用户可见行为已经增加，但本次实现提交没有同步更新产品文档；本审查文件补齐现状，后续每个阶段继续维护验收状态。
- Runtime 操作记录存在硬编码中文和固定中文日期，英文界面会出现混合语言。

### 建议重构

- `RuntimeCapabilitiesPanel` 同时承担完整市场数据、CLI 生命周期、MCP 配置、轮询、操作记录和渲染，职责过多。拆为 CLI、MCP、OperationHistory 三个能力组件，并只传当前 Runtime 的投影数据。
- active operation 状态在三个界面重复判断。应抽取共享谓词和状态标签，避免同一状态在不同入口产生分叉。
- provider Runtime 镜像为单一条目硬编码 Hacker Feeds，并为所有 provider 安装 Git，扩大镜像和攻击面。若无平台级使用证据，应改为按受管 release 安装或移除该特例。

## 5. 实施顺序

1. **P0-A 来源与健康事实**：修复来源标签、本地化详情、展示目录健康、补 harness raw fallback。
2. **P0-B 安装资格与服务端阻断**：禁止可漂移版本和不安全命令，输出结构化阻断原因，按 Runtime readiness 禁用安装。
3. **P1-A 共享状态与一致性**：统一 active 状态、日期/文案、筛选选择行为和错误恢复。
4. **P1-B MCP 单一主流程**：将 managed stdio 依赖安装与连接串成步骤器。
5. **P2 工作区私有 CLI**：先完成不可变数据模型和服务端校验，再开放管理员入口。
6. **P3 来源治理**：达到安装成功率、安全审查和来源健康可见性门槛后再实施。

## 7. 实施记录

### 2026-08-05：P0-A 来源与目录事实

- 已为 CLI 目录增加产品来源投影，平台固定 MCP Runtime 组件显示为“平台官方”，其他来源显示为“CLI-Anything 工具套件”“社区目录”或“Skill 依赖”；
- 已本地化 CLI 详情事实、风险和筛选标签，并让时间格式跟随当前语言；
- 已展示目录条目数、最后同步时间和陈旧状态；
- 已将原始命令明确标记为“上游安装声明”，说明服务端会生成受控执行计划；
- 已为 harness 目录增加 raw GitHub fallback；
- 待办：当前健康数据仍是聚合视图，分来源错误、最后成功时间和 revision 需要在 P3 数据模型中持久化。

### 2026-08-05：P0-B 安装资格与服务端阻断

- 已增加结构化安装资格：`installable`、`needs_configuration`、`unsupported`，并提供稳定错误码和所需 Runtime 工具链；
- 已在 loader、市场主动作和服务端排队接口复用同一组规则，前端禁用不能替代服务端校验；
- 已阻断 `latest`/范围版本、缺安装声明、缺入口、桌面或交互依赖、任意 shell 控制命令和未固定 artifact；
- CLI-Hub fallback 只接受完整白名单命令以及精确 npm/PyPI 版本或 40 位 Git commit，不再自动安装未固定版本的 `cli-anything-hub`；
- 已按目标 Runtime 的 npm、Python、pip、CLI-Hub readiness 禁用动作并展示修复原因；
- 已修正目录健康聚合，平台官方组件的刷新时间不再掩盖上游目录陈旧；
- 卸载不受新版目录资格影响，已安装的旧条目仍可安全移除。

### 2026-08-05：P1-A 状态与入口一致性

- 已提取共享 active operation 判断和 Runtime 安装资格投影，市场与 Runtime 详情使用相同状态与阻断原因；
- 已让 Runtime 安装记录的空状态、动作、状态和日期跟随当前语言；
- 已修复 MCP 筛选后列表与详情不一致，非编辑状态只展示当前筛选结果中的详情；
- 已由 P1-B/P1-C/P1-D 补齐 managed stdio 步骤器及 CLI/MCP 服务端持久化阶段。

### 2026-08-05：P1-B managed stdio 单一主流程

- 市场页与 Runtime 详情页共用五步连接进度：Runtime、依赖 CLI、配置、工具权限、连接验证；
- managed stdio 只保留一个主动作，依赖未安装时继续安装固定版本 CLI，依赖就绪后继续验证并连接；
- 依赖 CLI 同步复用目录安装资格与 Runtime readiness，不能安装时直接展示稳定阻断原因；
- 已将 MiniMax API Key 与网络授权从 CLI 安装前置条件移回 MCP 连接配置，避免安全预检错误阻断官方组件安装；
- 已由 P1-C/P1-D 补齐 CLI 安装、验证和 MCP 连接、协议协商、工具发现等后端真实阶段；下载百分比仍等待包管理器结构化事件。

### 2026-08-05：P1-C CLI 可恢复执行阶段

- `runtime_app_operation` 已持久化当前阶段、失败阶段与阶段更新时间，刷新后可恢复同一 operation 的进度；
- daemon 在受控计划执行时上报安装、验证和收尾阶段，完成时固化为完成，失败时保留实际失败阶段；
- daemon 阶段 API 复用 operation 的工作区与 Runtime 归属鉴权，只接受白名单阶段；
- CLI 市场与 Runtime 安装记录显示本地化阶段，不再只暴露 `running` 等底层状态；
- 待办：包管理器目前不能可靠拆分下载与安装事件，因此首期不伪造下载百分比；后续接入 npm/pip 结构化事件后再增加下载与完整性校验子阶段。

### 2026-08-05：P1-D MCP 可恢复连接阶段

- `runtime_mcp_operation` 已持久化当前阶段、失败阶段与阶段更新时间，兼容旧记录并在刷新后恢复连接进度；
- daemon 按实际执行路径上报连接、协议协商、工具发现和收尾阶段，移除操作也会进入收尾后再完成；
- 阶段迁移只允许单调前进，完成固化为 `completed`，失败保留实际失败阶段，防止重试或并发回报让界面倒退；
- daemon 阶段 API 复用 operation 的工作区归属鉴权并限制阶段白名单；
- Runtime MCP 操作历史和 MCP 连接详情均显示本地化阶段，已增加执行顺序、API 输入和英文界面回归测试。

### 2026-08-05：P2 工作区私有 CLI 首期发布

- 增加 `runtime_app_package` / `runtime_app_release` 独立数据模型，按工作区隔离，`package + version` 唯一且 release 只插入不覆盖；
- 管理员可在 CLI 市场打开“添加 CLI”，选择 npm 或 PyPI，提交固定版本、入口和产品元数据；浏览器表单没有 shell、registry 凭据或宿主机路径字段；
- 服务端仅访问 `registry.npmjs.org`、`pypi.org` 和 `files.pythonhosted.org`，校验版本、artifact URL、integrity 和 npm 声明的 entrypoint，并记录发布者审计事件；
- 私有 release 投影为 `workspace_private` CLI，安装计划只生成精确 npm/PyPI argv，私有 CLI 固定按高风险要求确认；
- 市场列表按当前 workspace 过滤私有 release，安装/卸载/Runtime 上下文沿用现有 operation 生命周期；
- 待办：安装时仍使用精确包版本，尚未在 Runtime 下载后按已保存 artifact integrity 做二次 hash 重验。

### 2026-08-05：P2 私有 CLI 与 managed stdio MCP 绑定

- `mcp_catalog_item` 持久化 `required_runtime_app_json`，保存工作区私有 CLI release ID、精确版本和来源；旧 catalog 记录保持兼容；
- 私有 managed stdio MCP 发布时必须引用当前工作区未下架的 CLI release，服务端同时校验 release 版本和 `stdio://entrypoint`；
- 发布弹窗不再接受手工入口命令，改为选择当前工作区已发布的 CLI release，并只读展示由 release 推导出的 stdio 入口；
- MCP 连接和单一主流程复用既有 Runtime 安装就绪检查，只有同一 release、同一版本已安装并启用时才允许验证；
- 官方 managed stdio MCP 继续使用平台固定依赖，工作区私有依赖不会被错误标记为平台官方来源。
