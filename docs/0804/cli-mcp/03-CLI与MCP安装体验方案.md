# CLI 与 MCP 安装体验方案

## 1. 设计原则

1. **先回答“能不能用”，再允许“安装/连接”**：兼容性和前置条件必须在主动作前可见。
2. **一个主任务一个主按钮**：CLI 详情主动作是安装；MCP 详情主动作是连接；依赖步骤由步骤器组织。
3. **目录、安装和连接状态分离**：目录可用不代表 Runtime 已安装，已安装不代表 MCP 已连接，已连接不代表任务调用健康。
4. **过程可观察**：所有长操作显示当前阶段、已完成步骤和可恢复失败点。
5. **安全默认值**：固定版本、最小工具权限、最小网络范围、密钥不回显。
6. **渐进披露**：普通用户先看到结论，高级字段和原始证据放入展开区。

## 2. 目标市场结构

```text
应用与服务市场
+-- CLI 应用
|   +-- 搜索
|   +-- Facet：类别 / 来源 / 兼容性 / 安装状态 / 风险
|   +-- 来源健康提示
|   +-- 添加 CLI（管理员）
|   +-- 目录列表
|   +-- CLI 详情与安装步骤
+-- MCP 服务
    +-- 搜索
    +-- Facet：类别 / 来源 / Transport / Runtime / 连接状态 / 风险
    +-- 添加 MCP 服务（管理员）
    +-- 服务列表
    +-- MCP 详情与连接步骤
    +-- 已连接服务
```

CLI 和 MCP 继续使用 Tab，而不是合并成同一个混合列表。用户的搜索心智不同：CLI 关注安装与命令，MCP 关注工具、数据域、认证与连接。

### 来源状态

页头的“来源状态”打开轻量抽屉：

| 来源 | 状态 | 条目 | 最后成功同步 | 动作 |
| --- | --- | ---: | --- | --- |
| 平台官方 | 正常 | 2 | 3 分钟前 | 查看变更 |

普通成员只能查看，管理员可以重试或管理。来源错误不得只出现在刷新 Toast 中。

## 4. CLI 安装步骤

### 4.1 安装前

选择 Runtime 后立即执行只读预检：

- Runtime 在线；
- OS/architecture 兼容；
- Node/Python/系统依赖满足；
- 安装网络和 registry 可用；
- entrypoint 无冲突；
- 已安装版本与目标版本关系；
- 是否需要凭据、账号、桌面应用或常驻本机服务。

预检结果分为：`可安装`、`需配置`、`不兼容`。只有 `可安装` 或管理员完成可修复配置后才启用安装按钮。

### 4.2 安装中

```text
安装 Internal Search CLI 到 Managed Codex

[完成] 1. 锁定 release 1.4.2 与摘要
[完成] 2. 准备 Runtime 私有目录
[进行] 3. 从受信 registry 下载并安装
[等待] 4. 验证 entrypoint
[等待] 5. 写入安装记录

当前步骤已运行 18 秒                         [在后台继续]
```

关闭弹窗不取消操作。市场列表和 Runtime 详情均显示同一个 operation。只有明确的“取消安装”且后端支持安全取消时才提供取消动作。

### 4.3 安装成功

- 主状态：`已安装到 Managed Codex`；
- 次要信息：版本、安装时间、验证时间、entrypoint；
- 后续动作：`同步 Skill`、`用于 MCP 服务`、`在任务中测试`；
- 不应只显示通用 Toast。

### 4.4 安装失败

错误结构统一为：

```text
安装失败：目标 Runtime 缺少 Node.js 20.19+
失败步骤：Runtime 预检
未发生变更：尚未下载或安装文件

[查看修复方法] [更换 Runtime] [修复后重试]
```

错误信息分三层：用户可理解的原因、可执行的恢复动作、管理员可展开的脱敏技术详情。Docker 命令、密钥、堆栈和宿主机路径不进入默认视图。

## 5. MCP 连接步骤

### 5.1 Streamable HTTP

```text
1 选择 Runtime
  -> 2 配置 Endpoint/OAuth/密钥
  -> 3 选择工具权限与确认数据域
  -> 4 验证连接
  -> 5 Ready
```

无需安装 Runtime 组件。页面不得使用“安装 MCP”，主动作始终是“配置并连接”。

### 5.2 Managed stdio

```text
1 选择 Runtime
  -> 2 检查 CLI release
  -> 3 安装/验证 Runtime 组件
  -> 4 配置密钥与工具权限
  -> 5 验证 MCP 握手和工具清单
  -> 6 Ready
```

现有页面中的两个并列主按钮应改成一个步骤器：如果依赖未安装，主按钮显示“继续：安装 Runtime 组件”；依赖安装完成后自动进入配置步骤，而不是让用户猜测下一步。

### 5.3 MCP 详情草图

```text
+-----------------------------------------------------------------------+
| Internal Search MCP                         [工作区私有] [高风险]     |
| 连接内部搜索服务并批准可调用工具                                      |
+-----------------------------------------------------------------------+
| 进度  [1 Runtime ✓]--[2 组件 ✓]--[3 配置]--[4 权限]--[5 验证]        |
|                                                                       |
| 配置凭据                                                              |
| API_BASE_URL [________________________]                               |
| API_KEY      [••••••••••••••••••••••]  保存后不会显示                 |
|                                                                       |
| 数据边界：内部知识库、搜索查询                                        |
|                                                                       |
| [返回]                                      [继续：选择工具权限]       |
+-----------------------------------------------------------------------+
```

工具选择默认只批准目录声明的低风险工具。高风险工具逐项确认，不能用一个笼统的“确认 high-risk”替代工具级解释。

## 6. 列表状态模型

### 6.1 CLI

| 状态 | 列表文案 | 主动作 |
| --- | --- | --- |
| catalog_only | 未安装 | 安装 |
| incompatible | 当前 Runtime 不兼容 | 查看原因 |
| preflight_required | 需要配置 | 完成配置 |
| installing | 安装中 · 3/5 | 查看进度 |
| installed | 已安装 · 1.4.2 | 管理 |
| update_available | 可更新 · 1.5.0 | 查看更新 |
| failed | 安装失败 | 修复并重试 |
| disabled | 已停用 | 启用 |
| missing | 命令缺失 | 修复安装 |

### 6.2 MCP

| 状态 | 列表文案 | 主动作 |
| --- | --- | --- |
| not_connected | 未连接 | 配置并连接 |
| dependency_required | 需要 Runtime 组件 | 继续设置 |
| pending_configuration | 待配置 | 继续设置 |
| verifying | 正在验证 | 查看进度 |
| ready | 已就绪 | 管理 |
| degraded | 连接异常 | 修复 |
| failed | 验证失败 | 查看原因 |
| disabled | 已停用 | 重新启用 |

状态颜色只是辅助信号，所有状态必须包含文本和图标，不能只依赖风险圆点或颜色。

## 7. 移动端行为

- 筛选使用 drawer，顶部显示已选筛选数量；
- 目录和详情不并排，点击条目进入全宽详情；
- 安装/连接主动作固定在底部 action bar，但不能遮挡错误或表单内容；
- 步骤器在窄屏显示“步骤 3/5：配置”，完整步骤放在可展开区域；
- 技术事实使用两列 definition list，在极窄屏改为单列；
- 密钥、长 entrypoint、错误代码允许换行，不水平溢出。

## 8. 组件与可访问性

需要复用或补充以下组件：

- `SourceBadge`：官方、合作方、社区、工作区私有、Skill 依赖；
- `CompatibilityBadge`：兼容、需配置、不兼容；
- `OperationStepper`：安装/连接阶段和失败点；
- `SourceHealthDrawer`：分来源同步健康；
- `PreflightChecklist`：只读事实与修复动作；
- `SecretField`：不回显、轮换说明、错误关联；
- `ToolPermissionList`：风险、数据域、默认选择和批量最小权限；
- `TechnicalDetails`：脱敏日志、operation id、release digest。

可访问性底线：

- 键盘可完成搜索、筛选、选择 Runtime、安装与连接；
- 焦点在步骤变化后移动到新步骤标题，错误后移动到错误摘要；
- 长操作使用 `aria-live="polite"`，失败使用 `role="alert"`；
- 表单错误通过 `aria-describedby` 关联字段；
- 文本与背景对比度达到 WCAG AA；
- 44px 最小移动端触控区域；
- 不用 placeholder 代替 label。

## 9. 文案规范

| 避免 | 使用 | 原因 |
| --- | --- | --- |
| 安装 MCP | 配置并连接 MCP | HTTP MCP 不安装到 Runtime |
| Public CLI | 社区目录 / 平台官方 / 工作区私有 | Public 不能表达维护责任 |
| high / medium / low | 高风险 / 中风险 / 低风险，并解释原因 | 面向中文用户可理解 |
| Runtime app 操作已排队 | 已开始安装到「Managed Codex」 | 给出对象和动作 |
| failed | 安装失败 / 验证失败 | 区分失败阶段 |
| Runtime 组件 | 依赖 CLI：chrome-devtools-mcp 1.6.0 | 说明实际依赖 |
