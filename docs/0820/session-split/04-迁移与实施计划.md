# 迁移与实施计划
> **实现状态（本次会话）**：Phase 0 未开始（行为基线观测）。Phase 1–4 已完成（schema+领域服务、直接/群聊端到端、按 Lane 领取+FIFO+跨 runtime 互斥、历史面板服务端化+运行状态投影+摘要生成+消息加载/发送 API）；Phase 5 legacy 回填已完成（确定性会话 + 按 requester+employee 拆分 + 打标 + 生产惰性入口 + human participant userId）；Phase 5.3 约束收紧未做；Phase 6 除「双连接并发 claim race 注入与压测」外已完成（灰度开关、容量门控、FIFO 公平性）。各阶段下方以 `✅`/`🟡`/`⬜` 标注。


## 1. 实施原则

- 先建立服务端 Conversation 身份，再修改队列，不以 UI 临时状态代替领域对象。
- 所有 schema 先 additive，再双写、回填、切读，最后收紧约束。
- 已运行的旧会话不迁移 Provider Session，不中断、不取消、不重排。
- V2 Conversation 和 legacy 会话可以在灰度期并存。
- 每个阶段完成聚焦测试后独立提交中文 commit。
- 不在本机启动 Jenkins，不执行未经请求的部署。

## 2. 改造范围

### 2.1 数据与 Router

- `packages/db/src/postgres-schema/`：Conversation、Participant、Execution Lane、Provider Session 表；queue 新列和索引。
- 本地数据库 schema/migration：保持与 PostgreSQL 语义一致。
- `packages/db/src/agent-router-sessions.ts`：优先按 `conversationId` 生成 conversation key。
- `packages/db/src/task-queue.ts`：enqueue 写入 Conversation/Lane；claim 按 Lane 判断 active 冲突。
- `packages/db/src/types/tasks.ts`：扩展 enqueue 与 queue record 类型。

### 2.2 服务层

- 新增 `packages/services/src/conversations/`：创建、列表、读取、发送、归档、摘要和授权。
- `packages/services/src/contacts/contacts.ts`：直接消息必须接收服务端 Conversation 引用。
- `packages/services/src/messages/messages.ts`：群聊消息、提及和回复继承 Conversation。
- `packages/services/src/shared/messaging.ts`：history snapshot 按 Conversation，不按完整 channel。
- `packages/services/src/shared/conversation-execution-workspaces.ts`：迁移到 Lane 身份，保留 legacy adapter。
- auto continuation、agent output mention、workflow handoff：继承 Conversation/Lane。

### 2.3 Daemon

- task payload 解析增加 `conversationId`、`executionLaneId`。
- prompt context 只加载当前 Conversation 的消息与历史路径。
- workDir 按 Router Session/Lane 隔离。
- complete/fail/progress 事件回传 Conversation/Lane。
- Runtime task capacity 作为显式资源策略，不改回员工级互锁。

### 2.4 Web

- `/w/[workspaceSlug]/new`：调用创建接口，再重定向稳定 Conversation URL。
- `channels-page-model.ts`：解析 `conversation`，不再只解析 `new=1`。
- `channels-page-client.tsx`：按 Conversation 加载和发送；发送后保留 Conversation URL。
- `conversation-shell.tsx`：`/new` 创建、`/resume` 打开历史，不产生聊天消息。
- 历史面板：服务端分页、员工范围、状态和一句话摘要。
- 删除 localStorage 作为历史真相的职责，仅保留非权威 UI 缓存。

## 3. 分阶段计划

## Phase 1：Additive schema 与领域服务 ✅ 已完成

### 工作

- 新增四个 Conversation 领域表；
- `message`、`agent_task_queue` 增加 nullable `conversation_id` 和 `execution_lane_id`；
- 增加索引：

```text
conversation(workspace_id, last_activity_at DESC)
conversation_participant(employee_id, conversation_id)
conversation_execution_lane(workspace_id, conversation_id, employee_id) UNIQUE
agent_task_queue(runtime_id, status, execution_lane_id, priority, created_at)
message(conversation_id, created_at, id)
```

- 新增 Conversation service 和 API，只供 feature flag 测试入口使用。

### 验收

- schema 可重复执行；
- 创建 draft 幂等；
- employee history 分页稳定；
- 未开启 flag 时现有页面无行为变化。

## Phase 2：新会话端到端身份 ✅ 直接+群聊已完成

### 工作

- `/new` 和新建按钮统一调用 create Conversation；
- URL 改为 `focus + conversation`；
- 首条消息发送到 Conversation endpoint；
- message、pending、progress、result 全链路携带 Conversation；
- Router key 改为 `conversation:<id>`；
- 新 Conversation 不读取旧 Provider Session、旧 Router memory、旧 channel history path；
- 发送失败保留 draft 和 URL。

### 验收

- `/new` 后发送不会回旧消息流；
- 刷新仍停留在新 Conversation；
- 两个 Conversation 的消息和事件不会交叉；
- Provider Session ID 不相同。

## Phase 3：每 Lane 队列切流 ✅ 直接+群聊已完成

### 工作

- enqueue 写结构化 Lane ID；
- claim 对 V2 chat task 使用 Lane active guard；
- 不再使用 requester + employee 作为 V2 chat 串行条件；
- agent mention 和 auto continuation 继承 Lane；
- 增加 Runtime capacity projection；
- 调整 UI：跨 Conversation 不显示逻辑排队，同 Lane 才显示待执行。

### 灰度策略

```text
TASK_QUEUE_BY_CONVERSATION=off
  所有任务走 legacy claim

TASK_QUEUE_BY_CONVERSATION=shadow
  legacy claim 生效，同时记录 Lane 规则会选择什么

TASK_QUEUE_BY_CONVERSATION=on
  有 Lane 的 chat task 走新规则；无 Lane task 走 legacy
```

### 验收

- 旧 Conversation running 时，新 Conversation task 可被 claim；
- 同 Lane 第二条消息保持 queued；
- 另一 employee 或另一 Conversation 可并行；
- claim race 不会使同 Lane 两条任务同时 running。

## Phase 4：历史与 `/resume` 服务端化 ✅ 已完成（历史面板服务端化 + 摘要 fallback/回复后生成）

### 工作

- 历史面板改读 Conversation list；
- 当前 employee 作为筛选条件；
- 摘要 fallback + 异步生成；
- `/resume` 打开面板并恢复真实 Conversation；
- 完成通知带 Conversation ID 和摘要；
- 归档、重命名和恢复使用服务端 API。

### 验收

- 换浏览器仍能看到历史；
- Atlas 历史不出现 Vega Conversation；
- 运行中的旧 Conversation 可打开并持续收到进度；
- `/resume` 不产生用户聊天气泡或 task。

## Phase 5：Legacy 回填与双读收敛 🟡 回填已完成（确定性会话+打标+惰性入口+human userId）；约束收紧（NOT NULL/删 fallback）未做

### 5.1 历史回填

现有消息没有 Conversation ID。每个 legacy scope 创建一个默认 Conversation：

```text
legacy scope = workspace + requester + employee + direct/group channel
```

该 scope 的既有消息进入同一个 `legacy` Conversation，避免根据内容猜测不存在的历史边界。

浏览器 localStorage snapshot 不作为服务端消息真相：

- 不上传客户端保存的消息正文；
- 若 snapshot 包含可验证的现有 message ID，可仅导入用户自定义标题或归档偏好；
- 无法验证的记录保留为短期只读缓存，随后清理。

### 5.2 活跃任务

- 部署时已 claimed/running 的 legacy task 保持原 router/provider session；
- 为其生成确定性 legacy Conversation/Lane 引用，但不切换正在执行的 session；
- 完成回调双写到 legacy Conversation；
- 新 `/new` Conversation 立即使用 V2，不等待 legacy task 结束。

### 5.3 约束收紧

当 chat task 和 message 回填率达到 100% 后：

- chat trigger 的 `conversation_id`、`execution_lane_id` 改为 NOT NULL；
- 删除 chat claim 的 requester + employee fallback；
- 删除 `newConversation` 布尔输入；
- 删除 localStorage 历史真相路径；
- 保留只读 legacy Conversation，不删除审计数据。

## Phase 6：清理、性能与全面上线 🟡 灰度开关/容量/FIFO 已完成；双连接并发 claim race 注入与压测未做

### 工作

- 为 Conversation list 和 messages 分页压测；
- 检查 Router Session、Provider Session、workDir 和 token attribution 归因；
- 运行并发故障注入；
- 完成 5 至 8 人可用性测试；
- 观察一周 shadow/灰度指标；
- 移除临时兼容 adapter。

### 验收

- P0/P1 指标满足 [05-测试验收与指标.md](./05-测试验收与指标.md)；
- 无跨 Conversation 消息、session 或结果污染；
- 回滚演练通过。

## 4. Feature flags

> 默认值反映「已完成的 rollout」状态（Phase 2/3/4 已切换为 V2/服务端历史/按 Lane 领取）；与灰度上线起始态（off）不同，见 `packages/db/src/conversation-flags.ts`。

| Flag | 默认 | 作用 | 回滚效果 |
| --- | --- | --- | --- |
| `CONVERSATION_V2_ENABLED` | on | 创建与读取服务端 Conversation | off 回到 legacy 页面读写（降级） |
| `CONVERSATION_V2_DUAL_WRITE` | off | legacy 写路径同步写 Conversation（占位：本库无独立 legacy 写路径） | 停止双写，不删数据 |
| `TASK_QUEUE_BY_CONVERSATION` | on | Lane claim 规则（off/shadow 回 legacy claim） | 回到 legacy claim |
| `CONVERSATION_HISTORY_SERVER` | on | 历史面板切服务端 | off 返回空历史列表（本地面板已移除，属降级） |
| `RUNTIME_TASK_CAPACITY_ENABLED` | off | 显式容量控制与投影 | 继续 daemon 当前并行能力 |

Flag 必须由服务端控制。浏览器不能通过 query 参数开启队列规则。

## 5. 回滚

### 5.1 可以回滚

- 前端路由与历史面板；
- Conversation endpoint 使用；
- V2 claim 规则；
- 摘要生成 worker；
- capacity projection。

### 5.2 不回滚的数据

- 已创建 Conversation；
- 已关联的 message/task/Lane；
- Router/Provider Session 审计；
- 用户标题和归档状态。

回滚只能停止读取或新建，不能删除已产生的数据。

## 7. 风险与缓解

| 风险 | 级别 | 缓解 |
| --- | --- | --- |
| 活跃 legacy Provider Session 被错误换 ID | P0 | 活跃 task 不切 session，只双写归属 |
| 同 Lane 被并发 claim | P0 | 事务、行锁/原子更新、并发测试 |
| 结果写入当前打开的另一 Conversation | P0 | 所有事件和替换按 conversationId + taskId |
| 历史回填错误拆分 | P1 | 只创建一个确定性 legacy Conversation，不猜分段 |
| Runtime 并发过高导致资源耗尽 | P1 | 显式 capacity、资源指标、灰度上限 |
| localStorage 与服务端历史重复 | P2 | 不导入正文，只导入可验证偏好 |
| 空 draft 泛滥 | P2 | 24 小时清理，无消息不进历史 |
| 摘要不准确 | P2 | fallback、用户可重命名、异步失败不阻塞 |
