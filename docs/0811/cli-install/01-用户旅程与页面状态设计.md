# 用户旅程与页面状态设计

## 1. 角色与责任

| 角色 | 目标 | 可以执行的操作 |
| --- | --- | --- |
| 普通成员 | 让 AI 员工具备所需能力 | 安装已开放 CLI、配置个人凭据、连接已部署服务、申请管理员部署、查看进度 |
| 工作区管理员 | 管理工作区能力边界 | 批准部署、配置工作区密钥、授权工具、停用连接、处理异常 |
| 平台管理员/维护者 | 治理供应链与节点 | 发布不可变 release、批准镜像、维护 Runtime image、处理节点兼容性 |
| 受管节点 | 执行确定性计划 | 拉取镜像、安装包、启动/停止服务、健康检查、回报状态 |

## 2. 信息架构

```text
应用与服务市场
+-- 可获取能力
|   +-- CLI 应用
|   +-- MCP 服务
|   +-- 筛选：类型 / 来源 / 获取状态 / 风险 / Runtime
+-- 当前能力
|   +-- 已安装 CLI
|   +-- 已连接服务
|   +-- 健康与更新
+-- 我的请求
|   +-- 等待管理员
|   +-- 部署中
|   +-- 已完成 / 已拒绝
+-- 管理员治理
    +-- 待审核 release
    +-- 待部署请求
    +-- 节点与镜像准备度
    +-- 服务实例与故障
```

“管理员治理”只对管理员展示。普通成员不会看到镜像 digest、签名、release lock 或原始安装命令。

## 3. 普通用户 happy path

### 3.1 可自动安装的 CLI

```text
搜索能力 -> 选择 Runtime -> 页面显示“可安装”
-> 点击“安装” -> 查看阶段进度 -> 验证成功
-> 页面显示“已安装，可同步 Skill”
```

安装阶段固定为：

1. 检查 Runtime 在线与基础工具；
2. 锁定 release 和完整性；
3. 下载到隔离依赖目录；
4. 执行受控 argv 安装计划；
5. 验证 entrypoint 与版本；
6. 写入能力目录并通知用户。

### 3.2 已部署的服务

```text
选择 MCP 服务 -> 选择 Runtime
-> 配置凭据和工具范围 -> 点击“连接”
-> 握手和工具发现 -> 已连接
```

用户无需知道服务容器所在节点或内部 endpoint。

### 3.3 未部署的服务

```text
选择服务 -> 页面显示“需要管理员部署”
-> 点击“申请管理员部署” -> 填写用途，可选紧急程度
-> 等待管理员 -> 系统部署并验证
-> 用户补充凭据（如需要） -> 自动连接
```

系统应把申请与后续部署/连接串成一个可恢复任务，不要求用户重新搜索并从头操作。

## 4. 管理员 happy path

### 4.1 即时部署

管理员查看同一服务时，主按钮显示“部署并启用”：

1. 查看镜像来源、digest、签名、资源和网络摘要；
2. 选择节点范围：workspace、runtime 或 node shared；
3. 确认资源上限与凭据字段；
4. 系统拉取并验证镜像；
5. 创建容器并执行健康检查；
6. 创建 MCP connection，发现工具并启用；
7. 返回可用状态和审计记录。

### 4.2 处理用户申请

管理员待办行显示：申请人、工作区、目标 Runtime、能力、风险、预估资源、是否已有缓存镜像。

可执行动作：

- `批准并部署`；
- `改用已有服务`；
- `要求补充信息`；
- `拒绝`，必须填写用户可理解的原因。

## 5. 主按钮决策

页面不能只通过颜色和禁用状态表达结论。主按钮由服务端投影的 `nextAction` 决定：

| `nextAction` | 普通用户按钮 | 管理员按钮 |
| --- | --- | --- |
| `install` | 安装 | 安装 |
| `connect` | 连接 | 连接 |
| `configure_credentials` | 配置凭据 | 配置凭据 |
| `request_deployment` | 申请管理员部署 | 部署并启用 |
| `wait_for_approval` | 查看申请 | 审核申请 |
| `wait_for_operation` | 查看进度 | 查看进度 |
| `repair` | 暂时不可用 | 修复服务 |
| `govern_release` | 暂未开放 | 审核并发布 |
| `none` | 已启用 | 管理能力 |

按钮禁用只用于瞬时状态，例如正在提交、防止重复点击；不能用来表示一个长期没有出口的业务状态。

### 5.1 运行方式选择

普通用户不选择技术性的 `local/remote`、CLI 或 MCP。系统根据 capability release 与 Runtime execution profile 自动给出推荐路径：

```text
运行方式    安装到此 Runtime（推荐）
原因        需要访问 Runtime 工作目录，且当前 Runtime 支持受控 CLI 安装
```

当同一能力同时提供 CLI 和 MCP 实现时，管理员可以展开“高级设置”切换：

```text
运行方式
(*) 安装到此 Runtime    访问本地文件，随 Runtime 生命周期管理
( ) 连接受管服务        独立运行，集中升级和资源隔离
```

无法使用 CLI 的只读远程 Runtime 只显示 MCP 路径；无 MCP Gateway 但可安装 CLI 的 Runtime 只显示 CLI 路径。页面不因 `daemonMode=remote` 单独隐藏安装按钮。

## 6. 页面内容模型

### 6.1 目录列表行

固定显示：

- 名称和一句能力说明；
- 能力类型：CLI / MCP / 服务；
- 风险文字标签，不只使用圆点；
- 针对当前 Runtime 的获取状态；
- 系统推荐的运行方式及简短原因；
- 主操作结果摘要，例如“可直接安装”“需要管理员部署”。

连接状态、风险等级和部署准备度必须是三个独立字段，不能共用同一个颜色点。

### 6.2 详情页

普通用户优先看到：

```text
MiniMax CLI                         [低风险]
在 Runtime 中提供 MiniMax 命令行能力

目标 Runtime       Managed Claude
获取方式           Runtime 按需安装
当前状态           目录版本待平台审核
影响               当前尚不能提供给 AI 员工
下一步             平台管理员发布固定版本后开放

[暂未开放]
```

管理员看到额外诊断：当前 `latest`、上游声明、建议解析版本、完整性状态和“审核并发布”动作。

## 7. 错误恢复路径

### 7.1 部署失败

普通用户：

```text
服务部署没有完成
管理员已收到失败信息；该能力尚未提供给 Runtime。
[查看请求]
```

管理员：显示稳定错误码、失败阶段、节点、时间、已脱敏日志尾部，并提供“重试”“更换节点”“回滚 release”。

### 7.2 Runtime 离线

- 保留用户的安装意图；
- 显示“等待 Runtime 上线”；
- Runtime 恢复后自动继续，或允许用户切换 Runtime；
- 不要求重复创建申请。

### 7.3 缺少凭据

- 安装或部署可以先完成；
- 状态显示“等待配置”，不标记为失败；
- 只有声明的凭据字段可输入；
- 凭据提交后从验证阶段继续。

### 7.4 release 未通过治理

- 普通用户看到“暂未开放”；
- 可选择“通知我开放结果”；
- 管理员进入治理队列，不提供手动绕过按钮。

## 8. 通知与可观察性

需要通知的节点：

- 管理员收到新部署申请；
- 申请被要求补充、批准或拒绝；
- 安装/部署完成；
- 服务健康降级影响新任务；
- release 有可用升级；
- 失败超过自动重试上限。

页面刷新后的事实来源必须是持久化状态，不依赖临时 Toast 或 SSE 内存事件。

## 9. 可用性验证假设

原型至少覆盖：

- happy path：用户安装可用 CLI；
- happy path：管理员部署 managed service；
- error path：普通用户遇到未部署服务并提交申请；
- error path：部署失败后管理员重试。

使用 5 至 8 名参与者验证：

- 90% 以上用户能在 2 分钟内判断“我能否使用，以及下一步由谁处理”；
- 85% 以上用户能完成安装或部署申请；
- 用户不需要理解 release digest、CLI-Hub 或 Docker socket；
- 禁用主按钮导致的无出口任务数为 0。

## 10. 实施状态（2026-08-11）

- **服务端投影已落地**：9 个 `nextAction` 由 `projectCliCapabilityAvailability` / `projectMcpCapabilityAvailability` 在服务端收敛，普通用户与管理员共用同一份按钮决策。
- **未落地**：页面渲染层仍消费旧的 `installability` 字段，未切换到 `nextAction`。切换属于 UI 工作（Phase 6）。
