# 数据模型与接口设计

## 1. 设计目标

安装、部署、连接和可用性需要分开持久化。一个镜像已经缓存，不代表服务已启动；一个服务已启动，不代表 MCP connection 已验证；一个 CLI 安装成功，也不代表 Skill 已同步。

## 2. 领域对象

### 2.1 Capability Package

```text
capability_package
  id
  workspace_id?              // official/partner 可为空，private 必填
  source
  slug
  display_name
  kind                       // cli | mcp | service
  deployment_mode            // runtime_builtin | runtime_package | managed_service | external_service
  category
  risk
  owner_type                 // platform | partner | workspace
  visibility                 // public | workspace | hidden
```

### 2.2 Immutable Release

```text
capability_release
  id
  package_id
  version
  manifest_digest
  artifact_ref?
  artifact_integrity?
  image_digest?
  signature_key_ref?
  install_strategy?
  entry_point?
  command_argv_json?
  required_runtime_capabilities_json
  configuration_schema_json
  secret_schema_json
  network_policy_json
  resource_profile_json
  declared_tools_json?
  verification_status       // pending | approved | rejected | yanked
  compatibility_status      // unknown | compatible | partial | unsupported
  created_at
  approved_at?
  yanked_at?
```

同一个 package 可以有多个 release，但 connection/installation 必须固定引用一个 release，不能引用 `latest`。

### 2.3 Runtime Baseline

```text
runtime_baseline
  id
  runtime_id
  image_ref
  image_digest
  baseline_version
  readiness_json
  compatibility_matrix_json
  status                    // checking | ready | degraded | outdated
  checked_at
```

### 2.4 Runtime Execution Profile

`daemon_mode` 只保留为拓扑信息，不能直接推导 CLI/MCP 支持。Runtime 通过独立 profile 声明实际执行能力：

```text
runtime_execution_profile
  id
  runtime_id
  daemon_mode                 // local | remote，仅描述 daemon/工作目录位置
  filesystem_mode             // read_only | ephemeral | persistent
  writable_home
  runtime_package_executor
  mcp_gateway
  managed_service_reachable
  supported_deployment_modes_json
  profile_revision
  checked_at
```

服务端根据该 profile、release 和策略执行能力协商。Remote 受管 Docker Runtime 可以同时支持 `runtime_package` 与 MCP；Remote 只读 Runtime 可以只支持 MCP；Local Runtime 也不能在没有 Gateway 时被视为支持 MCP。

### 2.5 Service Instance

```text
managed_service_instance
  id
  workspace_id
  runtime_id?
  release_id
  node_id
  scope                     // node_shared | workspace | runtime
  desired_state             // cached | running | suspended | retired
  actual_state              // provisioning | ready | degraded | failed | retiring | retired
  container_ref?
  endpoint_ref?
  resource_profile_json
  network_identity_ref
  last_health_at?
  last_error_code?
  revision
  created_at
  updated_at
```

### 2.6 Capability Request

```text
capability_request
  id
  workspace_id
  requested_by
  runtime_id
  package_id
  release_id?
  requested_action       // install | deploy | connect | upgrade
  reason_code?
  message?
  priority               // normal | urgent
  status                 // pending | approved | rejected | running | completed | failed | cancelled
  decided_by?
  decision_reason?
  operation_id?
  created_at
  updated_at
```

### 2.7 Installation / Connection

现有 runtime app installation 和 MCP connection 继续保留，但增加 release 和 deployment 引用：

```text
runtime_app_installation
  runtime_id
  release_id
  status                 // queued | installing | verifying | installed | failed | disabled
  installed_version
  install_root
  last_error_code?
  last_verified_at?

mcp_connection
  workspace_id
  runtime_id
  package_id
  release_id
  service_instance_id?
  transport
  status                 // pending_configuration | queued_verification | verifying | ready | degraded | failed | disabled
  approved_tools_json
  secret_binding_ref?
  last_verified_at?
  last_error_code?
```

## 3. 服务端状态投影

页面不应自己根据多个对象拼接业务结论。服务端为当前用户和 Runtime 返回：

```ts
type CapabilityNextAction =
  | "install"
  | "connect"
  | "configure_credentials"
  | "request_deployment"
  | "wait_for_approval"
  | "wait_for_operation"
  | "repair"
  | "govern_release"
  | "none";

interface CapabilityAvailabilityProjection {
  packageId: string;
  releaseId?: string;
  runtimeId: string;
  kind: "cli" | "mcp" | "service";
  deploymentMode: "runtime_builtin" | "runtime_package" | "managed_service" | "external_service";
  selectedImplementation?: "runtime_package" | "managed_service" | "external_service";
  alternativeImplementations: Array<"runtime_package" | "managed_service" | "external_service">;
  selectionReason?: string;
  runtimeProfileRevision: string;
  catalogState: "approved" | "pending" | "rejected" | "yanked";
  infrastructureState: "ready" | "not_ready" | "deploying" | "degraded" | "unknown";
  userState: "available" | "installed" | "connected" | "requested" | "blocked";
  nextAction: CapabilityNextAction;
  reasonCode?: string;
  reasonText: string;
  canManage: boolean;
  operationId?: string;
}
```

`reasonCode` 可用于管理员诊断，`reasonText` 必须是面向角色的可理解文案。

`selectedImplementation` 是服务端推荐结果。普通用户不直接提交该字段；管理员切换实现时只能从 `alternativeImplementations` 中选择，服务端仍需重新校验 profile 和策略。

## 4. API 草案

### 4.1 能力可用性

```http
GET /api/workspaces/:workspaceId/capabilities/availability
  ?runtimeId=<runtime>
  &kind=cli|mcp|service
```

返回目录条目、release、Runtime readiness、部署状态、下一步动作和操作 ID。

### 4.2 请求管理员部署

```http
POST /api/workspaces/:workspaceId/capability-requests
Content-Type: application/json

{
  "runtimeId": "runtime-1",
  "packageId": "pkg-openmontage",
  "requestedAction": "deploy",
  "message": "用于视频素材处理",
  "priority": "normal"
}
```

服务端必须重新计算 workspace、Runtime、release 和权限，不信任浏览器提交的风险、endpoint、image digest 或命令。

### 4.3 管理员批准并部署

```http
POST /api/admin/capability-requests/:requestId/approve
{
  "nodeId": "node-1",
  "scope": "workspace",
  "warmInstance": false
}
```

返回 `operationId`。受管节点通过 claim/lease 执行，浏览器轮询或订阅持久化操作状态。

### 4.4 取消、重试和回滚

```http
POST /api/admin/capability-operations/:operationId/retry
POST /api/admin/capability-operations/:operationId/cancel
POST /api/admin/capability-operations/:operationId/rollback
```

所有动作使用幂等键，重复提交不得创建多个容器或多个安装记录。

### 4.5 Runtime 基线

```http
GET  /api/runtimes/:runtimeId/readiness
POST /api/runtimes/:runtimeId/readiness/check
GET  /api/admin/runtime-baselines
POST /api/admin/runtime-baselines/:baselineId/rollout
```

readiness 由 daemon 产生；管理员只能选择已批准的 baseline rollout，不能从浏览器任意写入能力布尔值。

## 5. 状态映射规则

### 5.1 CLI

```text
deployment_mode=runtime_builtin  -> nextAction=none 或 install
immutable release + writable/persistent HOME + executor + readiness ok -> install
remote + managed Docker profile   -> 仍可 install
remote + read-only/no executor     -> 不允许 CLI，评估 MCP alternative
缺少 npm/python/pip/cli-hub       -> request_deployment
latest/unsafe/missing integrity    -> govern_release
安装 operation active             -> wait_for_operation
安装成功                          -> none
```

### 5.2 MCP

```text
external_service + schema ready    -> configure_credentials/connect
managed_service + instance ready   -> configure_credentials/connect
managed_service + cached           -> request_deployment（普通用户）或管理员直接部署并连接
managed_service + not deployed     -> request_deployment（普通用户）
managed_stdio dependency missing   -> install dependency 或 request_deployment
local/remote + mcpGateway=false     -> 不允许 MCP，评估 runtime_package alternative
connection verifying               -> wait_for_operation
connection degraded/failed         -> repair
```

## 6. 权限与审计

以下事件必须记录：

- release approved/yanked；
- runtime baseline rollout；
- capability request created/approved/rejected；
- image pulled and signature verified；
- instance provisioned/health changed/retired；
- CLI installation started/completed/failed；
- MCP connection configured/verified/disabled；
- credential schema changed或secret rotated。

审计事件只保存 ID、版本、digest、状态、错误码、操作者和时间，不保存密钥、完整 endpoint query、原始命令或工具 payload。

## 7. 实施状态（2026-08-11）

- **能力请求 envelope 已落地**：`capability_request` 表与 `CapabilityRequestRecord` 类型已实现，覆盖 `requested_action ∈ {install, deploy, connect, upgrade}` + `deployment_mode ∈ {runtime_builtin, runtime_package, managed_service, external_service}` 状态机。
- **服务端投影已落地**：`CapabilityAvailabilityProjection` 返回 9 个 `nextAction` 之一，与 `capabilityRequestId` / `operationId` 关联，刷新页面可恢复状态。
- **Runtime 能力协商待实施**：当前投影仍主要使用基础 CLI readiness；`runtime_execution_profile`、`selectedImplementation`、`alternativeImplementations` 以及 local/remote 解耦属于本方案下一阶段交付，不能宣称已经完成。
- **API 已落地**：`GET /api/workspaces/:workspaceId/capabilities/availability`、`POST /api/workspaces/:workspaceId/capability-requests`、`POST /api/workspaces/:workspaceId/capability-requests/:requestId/decision`。
- **审计与幂等**：`tryRecordWorkspaceAuditEventSync` 在提交与拒绝时记录事件，`UNIQUE(workspace, runtime, package_kind, package_source, package_slug, requested_action)` 保证重复点击不会创建多条记录。
